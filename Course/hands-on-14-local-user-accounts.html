Hands-on — Local user accounts

14 - Local user accounts

Originele pagina openen →

Goal

Automate the lifecycle of one disposable local Windows account without exposing passwords or affecting unrelated accounts.

Learning objectives

By the end of this lab, you can:

  • perform a safety and privilege check before changing accounts;
  • inspect local users, groups, and membership as objects;
  • preview and create a disabled local lab account;
  • manage membership, password, and enabled state; and
  • build an idempotent, previewable account-management script.

Prerequisites

  • Complete 13 — Modules.
  • Complete Automating local user accounts before starting this lab.
  • Use an instructor-provided disposable Windows VM or Windows Sandbox.
  • Use 64-bit PowerShell and an administrator terminal.
  • Reserve the exact account name PSLabStudent14 for this lab.

How to work in this lab

Predict, run, and reflect. Run every -WhatIf preview before its real command. Stop if PSLabStudent14 already exists before you begin; do not remove or reuse an account you did not create.

Part 5 — Challenge: create an account lifecycle script

Filename: Manage-CourseLocalUser.ps1

Create Manage-CourseLocalUser.ps1 in a dedicated lab folder. The script must:

  • use [CmdletBinding(SupportsShouldProcess)];
  • accept Action with Status, Create, Enable, Disable, or Remove;
  • accept an account name that must start with PSLab;
  • default to PSLabStudent14;
  • prompt securely for a password only when an actual creation runs;
  • resolve the built-in Users group by SID;
  • avoid duplicate creation and handle a missing account clearly;
  • return a structured result object; and
  • support -WhatIf for every modifying action.

Test at least:

.\Manage-CourseLocalUser.ps1 -Action Status
.\Manage-CourseLocalUser.ps1 -Action Enable -WhatIf
.\Manage-CourseLocalUser.ps1 -Action Remove -WhatIf

Do not perform the final removal until Part 6.

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Step-by-step solution: Use Manage-CourseLocalUser.ps1. It separates requested and performed actions, prompts only inside an approved creation, skips already-correct states, and re-queries before returning the final object. Only manage accounts you created for this lab.

.\Manage-CourseLocalUser.ps1 -Action Status
.\Manage-CourseLocalUser.ps1 -Action Enable -WhatIf
.\Manage-CourseLocalUser.ps1 -Action Remove -WhatIf
Show solution Optimized

This alternative shares the state checks for Enable and Disable. It keeps creation and deletion separate and prompts for a password only after approval. Run actual changes only on the disposable account you created.

[CmdletBinding(SupportsShouldProcess)]
param(
    [Parameter(Mandatory)]
    [ValidateSet('Status', 'Create', 'Enable', 'Disable', 'Remove')]
    [string]$Action,
    [ValidatePattern('^PSLab[A-Za-z0-9_-]*$')]
    [string]$Name = 'PSLabStudent14',
    [ValidateNotNullOrEmpty()]
    [string]$FullName = 'PowerShell Lab Student 14'
)

if (-not $IsWindows) { throw 'This script requires Windows.' }
Import-Module Microsoft.PowerShell.LocalAccounts -ErrorAction Stop
$account = Get-LocalUser -ErrorAction Stop | Where-Object Name -eq $Name
$performed = 'None'
$message = if ($account) { 'Account found.' } else { 'Account does not exist.' }

if ($Action -eq 'Create') {
    if ($account) {
        $message = 'Account already exists; no duplicate was created.'
    } elseif ($PSCmdlet.ShouldProcess($Name, 'Create disabled account and add to Users')) {
        $group = Get-LocalGroup -SID 'S-1-5-32-545' -ErrorAction Stop
        $password = Read-Host -Prompt "Enter the temporary password for $Name" -AsSecureString
        $account = New-LocalUser -Name $Name -Password $password -FullName $FullName `
            -Description 'Disposable PowerShell course account' -Disabled -ErrorAction Stop
        $member = Get-LocalGroupMember -Group $group -ErrorAction Stop |
            Where-Object SID -eq $account.SID
        if (-not $member) {
            Add-LocalGroupMember -Group $group -Member $account -ErrorAction Stop
        }
        $performed = 'Created'
        $message = 'Disabled account created and added to the built-in Users group.'
    } else {
        $performed = 'Preview'
        $message = 'Creation was previewed or declined.'
    }
} elseif ($Action -in 'Enable', 'Disable' -and $account) {
    $desiredEnabled = $Action -eq 'Enable'
    if ($account.Enabled -eq $desiredEnabled) {
        $message = "Account is already $($Action.ToLower())d."
    } elseif ($PSCmdlet.ShouldProcess($Name, "$Action local account")) {
        if ($desiredEnabled) {
            $account | Enable-LocalUser -ErrorAction Stop
            $performed = 'Enabled'
        } else {
            $account | Disable-LocalUser -ErrorAction Stop
            $performed = 'Disabled'
        }
        $message = "Account $($performed.ToLower())."
    } else {
        $performed = 'Preview'
        $message = "$Action was previewed or declined."
    }
} elseif ($Action -eq 'Remove' -and $account) {
    if ($PSCmdlet.ShouldProcess($Name, 'Permanently remove local account')) {
        $account | Remove-LocalUser -ErrorAction Stop
        $performed = 'Removed'
        $message = 'Account removed.'
    } else {
        $performed = 'Preview'
        $message = 'Removal was previewed or declined.'
    }
} elseif ($Action -eq 'Remove') {
    $message = 'Account is already absent.'
}

$current = Get-LocalUser -ErrorAction Stop | Where-Object Name -eq $Name
[pscustomobject]@{
    Name = $Name
    RequestedAction = $Action
    PerformedAction = $performed
    Exists = [bool]$current
    Enabled = if ($current) { $current.Enabled } else { $null }
    Message = $message
}
