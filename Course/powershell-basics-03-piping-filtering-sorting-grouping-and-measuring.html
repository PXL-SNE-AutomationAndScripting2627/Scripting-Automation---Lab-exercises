Tab completion

The tab completion feature in PowerShell allows you to quickly and easily complete commands, cmdlets, parameters, and other elements by pressing the Tab key. This feature can save you time and reduce typing errors when working in the PowerShell environment. Here's how tab completion works in PowerShell:

  • Cmdlet Completion: When you type the first few letters of a cmdlet or command and press Tab, PowerShell will attempt to complete the command for you. If there are multiple possible completions, you can press Tab again to cycle through the options.

  • Parameter Completion: When you type a cmdlet or command followed by a hyphen (-) and press Tab, PowerShell will display a list of available parameters for that cmdlet. You can then continue typing the parameter name and press Tab to complete it.

  • Path Completion: When you type a path (e.g., a file or directory path) and press Tab, PowerShell will attempt to complete the path for you. If there are multiple possible completions, you can press Tab again to cycle through the options.

Pressing <ctrl> + <space> will show you the available options.

Pipeline and Piping

PowerShell piping is a powerful feature that allows you to pass the output of one command (or cmdlet) as input to another command. This feature makes it easier to chain together multiple commands to perform complex tasks, manipulate data, and streamline your workflow in the PowerShell environment.

In PowerShell, the pipe symbol | is used to connect commands in a pipeline. Here's how it works:

  • Command Execution: You start by running a PowerShell command or cmdlet. PowerShell cmdlets typically emit objects; external commands often emit text.
  • Pipe (|) Operator: To pass the output of the first command to a second command, you use the pipe operator (|). For example:
  • Data Flow: The output of the first command is "piped" into the second command. The second command processes this data, and you can continue chaining additional commands together, creating a sequence of operations.
  • Output: The final output of the last command in the pipeline is displayed or can be stored in a variable for further use
Get-Service | Where-Object Status -eq "Stopped" | Select-Object DisplayName, StartType, Status

Follow the objects through this pipeline

flowchart LR
    A["Get-Service: service objects"] --> B["Where-Object: keep stopped services"]
    B --> C["Select-Object: choose three properties"]
    C --> D["Display or use the resulting objects"]

Filtering decides which objects continue; selecting decides which properties appear in the resulting objects.

A Pipe can break commands up among several lines

# (note pipe must be last char on line)
Get-Service |
   Where-Object Status -eq "Stopped" |
   Select-Object DisplayName, StartType, Status

A backtick can be used for line continuation

Get-ChildItem -Path C:\ `
    -File -Filter "*.ini"

Select-Object

Is a versatile cmdlet in PowerShell used for selecting and shaping the properties of objects in the output of other cmdlets or commands. It allows you to choose which properties of an object you want to display, rename properties, calculate new properties, and more. This cmdlet is particularly useful when you want to focus on specific data within the output of a command and select properties for display.

What are common parameters?

Show solution

Common parameters are parameters that you can use with any cmdlet or advanced function in PowerShell. These parameters provide additional functionality and control over the behavior of the cmdlet or function. Some common parameters include -Verbose, -Debug, -ErrorAction, -WarningAction, -InformationAction, -ErrorVariable, -WarningVariable, -InformationVariable, -OutVariable, -OutBuffer, and -PipelineVariable.

Selecting specific properties of an object:

  • Property parameter
Get-Process | Select-Object -Property ProcessName, Id, WS
Get-Process | Select-Object ProcessName, Id, WS

Explain the following command:

Get-Process | Select-Object -p name
Show solution

Get-Process supplies process objects. Select-Object -p name selects their Name property and returns objects containing that property.

-p is a parameter-name abbreviation for -Property here, rather than a declared alias. Prefer -Property in saved scripts so the meaning is clear. The names and number of returned processes depend on the running system.

Expanding properties:

  • ExpandProperty parameter

ExpandProperty is used with the Select-Object cmdlet in PowerShell to extract and display properties of objects directly. This is particularly useful when you want to access nested properties or need to flatten the output to show just the values of a specific property rather than the property name and value pairs

Get-Process svchost | Select-Object -ExpandProperty ProcessName -Unique

svchost

The expanded property is the value of the property, not the property name and value pair. The output is a string object, not a process object.

Why is the following command not working?

Get-Process -ProcessName svchost | Select-Object -Property Name -Index 0
Show solution

-Index and -Property belong to different Select-Object parameter sets, so this combination cannot bind. Separate the operations:

Get-Process -Name svchost |
    Select-Object -Index 0 |
    Select-Object -Property Name
Get-Command Select-Object -Syntax

The first selection keeps the first process object; the next selects its Name property. The syntax lists -Index in a set without -Property. The selected process depends on the current process listing.

  • Parameter -unique
Get-Process -ProcessName svchost | Select-Object name -unique

How do you display the unique process names without the column name?

Show solution 
(Get-Process -ProcessName svchost | Select-Object name -unique).Name

or

Get-Process -ProcessName svchost | Select-Object -ExpandProperty name -unique

svchost

Dot notation retrieves the selected Name values. -ExpandProperty returns those values directly as strings. Both approaches display svchost when that process name exists, without a selected-object column heading.

How do you count the number of unique process names?

Show solution 
Get-Process |
    Select-Object -Property Name -Unique |
    Measure-Object |
    Select-Object -Property Count

Select unique names before counting. The result is one object whose Count is the number of distinct names at query time, not the number of all process instances. A Unix-style wc -l is not supplied by PowerShell and, when installed separately, counts text lines rather than process objects.

Calculating and renaming Properties:

In PowerShell, you can calculate the value of a data unit like MB, GB, TB, etc., to display the size of a file or process in a more readable format. You can do this by dividing the value by the appropriate unit (e.g., 1MB, 1GB, 1TB) and renaming the property to reflect the new unit. Here's an example of how to calculate and rename properties.

1MB # 1,048,576 bytes  
1GB # 1,073,741,824 bytes
1TB # 1,099,511,627,776 bytes

The automatic variable $PSItem (or its alias $_) contains the current object in the pipeline.

Get-Help about_PSItem

Get-Process | Select-Object -first 5 ProcessName,@{Label='WS(MB)';Expression={$_.WS/1MB}}
Get-Process | Select-Object -first 5 ProcessName,@{Label='WS(MB)';Expression={$PSItem.WS/1MB}}
Get-Process | Select-Object -first 5 ProcessName,@{Name='WS(MB)';Expression={$_.WS/1MB}}
Get-Process | Select-Object -first 5 ProcessName,@{N='WS(MB)';E={$_.WS/1MB}}

Get-Help Get-Process -Online

Interpreting the WS (workspace) Value

  • Unit: The WS value is shown in bytes.
  • Meaning: It represents the number of bytes of physical memory currently allocated to the process.

Custom Formatting:

Customize the display format of properties.

Get-ChildItem C:\Windows -File | Select-Object Name, @{Name="Size (MB)"; Expression={"{0:N1}" -f ($_.Length / 1MB)}}

This calculated property is a culture-dependent string because -f returns a string; sort by the original numeric Length before formatting if numeric order matters.

Equality Operators

In PowerShell, there are different comparison operators used to check for equality.

  • -eq, -ieq, -ceq - equals
  • -ne, -ine, -cne - not equals
  • -gt, -igt, -cgt - greater than
  • -ge, -ige, -cge - greater than or equal
  • -lt, -ilt, -clt - less than
  • -le, -ile, -cle - less than or equal

Equals (-eq, -ieq, -ceq)

The basic operator is -eq (equals), but there are variations like -ieq and -ceq. Here's an explanation of each:

  1. -eq (equals)

    • Checks if two values are equal.
    • It is case-insensitive, meaning it does not distinguish between uppercase and lowercase letters.
    "hello" -eq "HELLO"   # This returns True

  2. -ieq (case-insensitive equals)

    • Similar to -eq, but it is case-insensitive.
    • It does not distinguish between uppercase and lowercase letters.
    "hello" -ieq "HELLO"   # This returns True

  3. -ceq (case-sensitive equals)

    • Similar to -eq, but it is case-sensitive.

    • It distinguishes between uppercase and lowercase letters.

      "hello" -ceq "HELLO"   # This returns False

Some other examples:

[DateTime]'2001-11-18' -lt [DateTime]'2020-08-01' # True

Numeric comparison:

1 -eq 1 # True
1 -eq 2 # False
1 -ne 2 # True
1 -gt 0 # True
5 -gt 7 # False 
1 -ge 1 # True
1 -lt 2 # True
5 -lt 3 # False
1 -le 1 # True

Summary:

-eq and -ieq are both case-insensitive and behave the same way. -ceq is case-sensitive and will only return True if the values are exactly the same, including uppercase and lowercase letters.

Matching Operators

In PowerShell, you can use matching operators to compare strings using wildcard patterns or regular expressions. Here are some common matching operators:

  • -like, -ilike, -clike - string matches wildcard pattern
  • -notlike, -inotlike, -cnotlike - string doesn't match wildcard pattern
  • -match, -imatch, -cmatch - string matches regex pattern
  • -notmatch, -inotmatch, -cnotmatch - string doesn't match regex pattern

For wildcards, use -like:

  • * (asterisk) - Represents zero or more characters.
  • ? (Question mark) - Represents exactly one single character.
  • [ ] (square brackets) - Define a character set; a hyphen inside them specifies a range.

Get-Help about_Wildcards

"PowerShell" -like "power*"   # True (matches "Power" followed by any number of characters)
"PowerShell" -like "*shell"   # True (matches any characters followed by "shell")
"PowerShell" -like "*wer*"    # True (matches any characters with "wer" in the middle)

"PowerShell" -like "p?werShell"   # True (matches "PowerShell" because the second character is any single character)
"PowerShell" -like "p??werShell"  # False (does not match "PowerShell" because the second character is not exactly two characters)
"PowerShell" -like "power?????"   # True (matches exactly 10 characters)

"PowerShell" -like "p[oa]wershell"  # True (matches "P" followed by either "o" or "a"; does match "PowerShell")
"PowerShell" -like "power[ab]shell" # False (matches "PowerAShell" or "PowerBShell")
"PowerShell" -like "power[a-s]hell" # True (matches "PowerShell" because the second character is in the range "a" to "s")
"PowerShell" -like "power[a-r]hell" # False (does not match "PowerShell" because the second character is not in the range "a" to "r")

For regex, use -match:

  • . (Dot) - Matches any single character except a newline.
  • \d - Matches any digit character.
  • \w - Matches any word character (alphanumeric and underscore).
  • \s - Matches any whitespace character.
  • ^ (Caret) - Matches the start of a string.
  • $ (Dollar) - Matches the end of a string.
  • | (Pipe) - Matches either the expression before or after the pipe.
  • [ ] (Square brackets) - Matches any one of the characters inside the brackets.
  • [-] (Hyphen inside square brackets) - Represents a range of characters.
  • [^ ] (Caret inside square brackets) - Matches any character not inside the brackets.
  • {} (Curly braces) - Matches a specific number of occurrences of the preceding character or group.
    • * - Zero or more occurrences.
    • ? - Zero or one occurrence.
    • + - One or more occurrences.
    • {n} - Exactly n occurrences.
    • {n,} - n or more occurrences.
    • {n,m} - Between n and m occurrences.
  • \\ (Backslash) - Escapes a metacharacter, allowing you to match the character itself.
  • \b (Word boundary) - Matches a word boundary position.

Metacharacters: matches a character

  • .(dot): ANY ONE character except newline. Same as [^\n]
  • \d \D: ANY ONE digit/non-digit character. Digits are [0-9]
  • \w, \W: ANY ONE word/non-word character. For ASCII, word characters are [a-zA-Z0-9_]
  • \s, \S: ANY ONE space/non-space character. For ASCII, whitespace characters are [ \n\r\t\f]

$Matches is an automatic hashtable populated by a successful -match operation when the left operand is a single string. It contains the full match and any captured groups; a failed match does not update it.

about_Regular_Expressions

"PowerShell" -match "Power"         # True (matches "Power" anywhere in the string)
"PowerShell" -match "^Power"        # True (matches "Power" at the start of the string)
"Super PowerShell" -match "^Power"  # False (does not match "Power" at the start of the string)
"PowerShell" -match "Shell$"        # True (matches "Shell" at the end of the string)
"PowerShell" -match "PowerShell"    # True (matches the entire string)

"PowerShell" -match "P.wer"     # True (matches "P" followed by any single character followed by "wer")
"PowerShell" -match "P.*wer"    # True (matches "P" followed by any number of characters followed by "wer")
"PowerShell" -match "P\w+wer"   # True (matches "P" followed by one or more word characters followed by "wer")
"PowerShell" -match "P\w{3}wer" # True (matches "P" followed by exactly three word characters followed by "wer")

"PowerShell" -match "P[oa]werShell"  # True (matches "P" followed by either "o" or "a"; does match "PowerShell")
"PowerShell" -match "Power[ab]Shell" # False (matches "PowerAShell" or "PowerBShell")
"PowerShell" -match "Power[a-s]hell" # True (matches "PowerShell" because the second character is in the range "a" to "s")
"PowerShell" -match "Power[a-r]hell" # False (does not match "PowerShell" because the second character is not in the range "a" to "r")

# This expression returns true if it matches a server name.
# (Server-01 - Server-99).
'Server-01' -match 'Server-\d\d'  # True (matches "Server-" followed by two digits)
'Server-01' -match 'Server-\d{2}' # True (matches "Server-" followed by exactly two digits)
$matches

'ACCOUNT NAME:    Administrator' -match 'ACCOUNT NAME:\s*\w*' # True (matches "ACCOUNT NAME:" followed by zero or more whitespace characters followed by zero or more word characters)
'DC-01' -match '[A-Z]+-\d\d'  # True (matches one or more uppercase letters followed by a hyphen and two digits)
'-01' -match '[A-Z]+-\d\d'    # False (does not match because there are no uppercase letters)
'SERVER-01' -match '[A-Z]+-?\d\d' # True (matches one or more uppercase letters followed by an optional hyphen and two digits)
'SERVER01' -match '[A-Z]+-?\d\d' # True (matches one or more uppercase letters followed by an optional hyphen and two digits)

'111-222-3333' -match '\d{3}-\d{3}-\d{4}' # True (matches exactly three digits followed by a hyphen, repeated three times)
'3.141' -match '3\.\d{2,}'                # True (matches "3." followed by two or more digits)
'3,141' -match '3\.\d{2,}'                # False (does not match because the decimal point is a comma)

# not case sensitive
Get-Process | Where-Object ProcessName -like "svch*"

# case sensitive
Get-Process | Where-Object ProcessName -cmatch "^S[v]"

Replacement Operators

In PowerShell, the -replace operator is used to replace strings that match a specified pattern with a new string. This operator is particularly useful for modifying text or data based on a regular expression pattern. Here's an explanation of the -replace operator and how to use it:


# Replace all occurrences of "a" with "b" in a string (case-insensitive)
"apple" -replace "a", "b"  # Output: bpple

# Replace all occurrences of "a" with "b" in a string (case-sensitive)
"Apple" -creplace "a", "b"  # Output: Apple

Containment Operators

In PowerShell, you can use containment operators to check if a collection contains a specific value. Here are some common containment operators:

  • -contains, -icontains, -ccontains - collection contains a value
  • -notcontains, -inotcontains, -cnotcontains - collection doesn't contain a value
  • -in - value is in a collection
  • -notin - value isn't in a collection

The containment operators do not support wildcards or regular expressions. It is a strict equality comparison operator that checks if a collection (like an array or list) contains a specific element.

# Check if a collection contains a specific value (case-insensitive)
$numbers = 1, 2, 3, 4, 5
$numbers -contains 3  # Output: True

# Check if a collection contains a specific value (case-insensitive)
$fruits = "Apple", "Banana", "Cherry"
$fruits -contains "banana"  # Output: True
$fruits -notcontains "banana" # Output: False

$fruits -contains "ban*" # Output: False

# Check if a collection contains a specific value (case-sensitive)
$fruits = "Apple", "Banana", "Cherry"
$fruits -ccontains "banana"  # Output: False

# Check if a value is in a collection (case-insensitive)
"banana" -in $fruits  # Output: True

# Check if a value isn't in a collection (case-insensitive)
"banana" -notin $fruits  # Output: False

Get-Process | Where-Object ProcessName -contains "svchost"
# `-contains` does not support wildcards.
Get-Process | Where-Object ProcessName -contains "svch*"

Logical_Operators

# Logical AND
# When using the -and operator, both conditions must be true for the overall condition to be true.

# Simple examples:
$true -and $true  # Output: True
$true -and $false  # Output: False
$false -and $true  # Output: False
$false -and $false  # Output: False

# Logical OR
# When using the -or operator, at least one of the conditions must be true for the overall condition to be true.

# Simple examples:
$true -or $true  # Output: True
$true -or $false  # Output: True
$false -or $true  # Output: True
$false -or $false  # Output: False

# Logical XOR
# When using the -xor operator, only one of the conditions must be true, but not both.

# Simple examples:
$true -xor $true  # Output: False
$true -xor $false  # Output: True
$false -xor $true  # Output: True
$false -xor $false  # Output: False

# Logical NOT
# When using the -not operator, the condition is negated.

# Simple examples:
-not $true  # Output: False
-not $false  # Output: True

Examples

Get-Process | Where-Object { $_.CPU -gt 60 }
Get-Process | Where-Object { -not $_.CPU -gt 60 }

Get-Process | Where-Object { $_.CPU -gt 60 -and $_.WS -gt 100MB }

Where-Object

In PowerShell, the Where-Object cmdlet is used to filter objects based on a specified condition or criteria. It allows you to select objects from a collection that meet specific requirements, such as matching a particular property value, satisfying a logical condition, or meeting a pattern or wildcard match.

Get-Help Where-Object -online

Get-Help Where-Object -online

Get-Help about_Logical_Operators

Get-Help about_Logical_Operators

Show the processes whose cumulative CPU time is greater than 60 seconds:

Show solution 
Get-Process | Where-Object CPU -gt 60
Get-Process | Where-Object {$_.CPU -gt 60}

The filter keeps process objects whose CPU property exceeds 60 seconds of cumulative processor time. It does not test a current CPU percentage. Processes without an accessible CPU value do not satisfy that comparison.

Show the services that are stopped:

Show solution 
Get-Service | Where-Object Status -eq "Stopped"
# <$_.Property>
Get-Service | Where-Object {$_.Status -eq "Stopped"}

Only service objects whose Status is Stopped pass the filter. The actual service names and count depend on the machine.

Show services where the Displayname is "Windows Time" and the name is "w32time":

Show solution 
Get-Service -DisplayName "Windows Time" | Where-Object {$_.Name -eq 'w32time'}

The query first selects the display name, then verifies the service's Name. A matching Windows Time service is returned regardless of its current running status.

Show services where the status is "Running" and the name contains "lm":

Show solution 
Get-Service -ErrorAction 'SilentlyContinue' | Where-Object {$_.Status -eq "running" -and $_.Name -like "*lm*" }

Both conditions must be true: the service is running and its name contains lm. The default string matching is case-insensitive. No matches is valid. -ErrorAction SilentlyContinue suppresses non-terminating retrieval errors; it does not repair access failures or guarantee a complete service listing.

# Boolean: true or false values
Get-Service | Where-Object CanStop -eq $true

Get-ChildItem | Where-Object { $_.Length -gt 1kb -and $_.Name -like "w*"}

Where-Object - Example 1

List all processes that start with the letter "l". Make use of the like and the match operator.

Why does using -match "^l*" fail to restrict the result to those names?

Show solution 
Get-Process | Where-Object Name -Like 'l*'
Get-Process | Where-Object { $_.ProcessName -match '^l' }

Both commands select names beginning with l, case-insensitively. The wildcard l* requires the initial letter and allows any suffix. The regex ^l requires l at the start.

^l* is valid regex, but l* permits zero l characters. It therefore matches the beginning of every process name, including names not starting with l. The names and count returned by the corrected filters vary.

Where-Object - Example 2

List all services that are automatic started during the boot process and are currently running.

How remove the red error messages in the output?

Show solution 
Get-Service -ErrorAction SilentlyContinue |
    Where-Object { $_.StartType -eq 'Automatic' -and $_.Status -eq 'Running' } |
    Select-Object Name, Status, StartType

Both conditions are needed. Filtering only StartType also includes automatic services that are currently stopped. Filter service objects before selecting the display properties.

-ErrorAction SilentlyContinue hides non-terminating errors from Get-Service. It does not fix the underlying problem, stop terminating errors, or prove that every service was read. Investigate unexpected errors before relying on the inventory.

Where-Object - Example 3

List all the executables in the Windows directory and subdirectories with a filesize greater or equal to 128 bytes

Hint : Get-Childitem

Show solution 
Get-ChildItem -Path C:\Windows -Filter *.exe -File -Recurse | Where-Object {$_.Length -ge 128}

-Filter '*.exe' limits filenames during retrieval, -File excludes directories, and -Recurse searches subdirectories. The property filter keeps lengths of at least 128 bytes, including exactly 128. Results and access errors depend on the system; this command only reads files.

Where-Object - Example 4

List all the files in a directory (Windows) that were modified in the last 24 hours.

Show the amount of files that were modified in the last 24 hours.

Show solution 
$modifiedSince = (Get-Date).AddHours(-24)
$recentFiles = @(Get-ChildItem -LiteralPath 'C:\Windows' -File -Recurse |
    Where-Object { $_.LastWriteTime -ge $modifiedSince })
$recentFiles
$recentFiles.Count

The cutoff is a DateTime value. -ge includes a timestamp exactly at the cutoff. Save one selection and count it rather than querying twice while files and the clock may change. @(...) gives a stable count even for zero or one result. The count and any access errors vary by machine.

Where (scriptblock expression) - extra possibilities to filter a collection of objects in a more efficient way

Sort-Object

In PowerShell, the Sort-Object cmdlet sorts the elements of an array or collection based on one or more properties. This cmdlet allows you to arrange data in ascending or descending order and can be used to order data by numerical, alphabetical, or date-based criteria. Here's an explanation of Sort-Object and how to use it:

Get-Help Sort-Object -Online

Get-Help Sort-Object -Online

Sorting a list of numbers in ascending order:

$numbers = 5, 2, 8, 1, 7
$sortedNumbers = $numbers | Sort-Object

Get-ChildItem -Path $PSHOME -File | Sort-Object Name

Sorting a list of strings in descending order, considering case sensitivity:

$fruits = "Apple", "apple", "banana", "Cherry", "Strawberry"
$sortedFruits = $fruits | Sort-Object -Descending -CaseSensitive

Get-ChildItem -Path $PSHOME -File | Sort-Object Name -Descending

You can also sort objects based on a property (e.g., sorting a list of processes by their "WS" property):

Get-Process | Sort-Object -Descending WS | Select-Object -first 5 ProcessName,@{Label='WS(MB)';Expression={$_.WS/1MB}}
Get-Process | Sort-Object -Descending WS | Select-Object -first 5 ProcessName,@{Name='WS(MB)';Expression={$_.WS/1MB}}
Get-Process | Sort-Object -Descending WS | Select-Object -first 5 ProcessName,@{N='WS(MB)';E={$_.WS/1MB}}

To sort by ProcessName in descending order and then by WS in ascending order, use:

Get-Process | Sort-Object @{Expression='ProcessName';Descending=$true}, @{Expression='WS';Ascending=$true} | Select-Object -First 5 ProcessName,@{Name='WS(MB)';Expression={$_.WS/1MB}}

List the 10 biggest files in the Windows System32 directory. Sort the files by their size in descending order. Show the Fullname and the size of the files in MB, round the size to 2 decimal places.

Show solution

    Sort-Object Length -Descending -Top 10 |

Group-Object

Group-Object is a PowerShell cmdlet used to group objects based on the value of a specified property. It is useful when you want to categorize data or find how many objects share the same property value.

Example 2 : Grouping processes by the ProcessName:

# Get all processes and group them by their names
# Group-Object -Property ProcessName: Groups the processes by the ProcessName property.
Get-Process | Group-Object -Property ProcessName

Show the five process names with the highest process counts:

Show solution 
Get-Process | Group-Object -Property ProcessName | Sort-Object -Descending Count -Top 5 | Select-Object Count, Name

Output varies with the processes currently running; groups are sorted by count descending.

Group process instances by ProcessName, sort the resulting groups by their numeric Count descending, and keep at most five groups. Name is the group's process name. Counts and tie ordering depend on the current processes.
