Hands-on — Arithmetic calculations

07 - Arithmetic calculations

Originele pagina openen →

Goal

Use numeric variables, arithmetic operators, precedence, casting, and rounding to produce reliable calculations.

Learning objectives

By the end of this lab, you can:

  • use addition, subtraction, multiplication, division, and remainder operators;
  • predict how parentheses change calculation order;
  • distinguish numeric addition from string concatenation;
  • increment and update numeric variables; and
  • round calculated values deliberately.

Prerequisites

  • Complete Arithmetic calculations before starting this lab.
  • Understand variables, numeric types, and casting.

Environment and safety requirements

Use PowerShell 7 on your Windows lab computer. Administrator rights are not required. The calculations affect session variables only and do not change system settings. Save the challenge script in your lab folder.

How to work in this lab

For every activity, predict the result, run the commands, and explain what happened. Keep the same session open and work through each part in order. Keep calculated values numeric so later commands can reuse them.

After attempting each activity, open Show solution to check your commands, expected results, and explanations. The final exercise and self-check also have solutions. Keep the session and setup required by the activity. If you already changed a file or variable, compare its result rather than replaying the change from the solution.

Part 1 — Use arithmetic operators

Activity 1.1 — Calculate with two values

$firstNumber = 17
$secondNumber = 5

$firstNumber + $secondNumber
$firstNumber - $secondNumber
$firstNumber * $secondNumber
$firstNumber / $secondNumber
$firstNumber % $secondNumber

Reflect:

  1. What does each operator calculate?
  2. Which operator returns the remainder?
  3. Why is the division result not a whole number?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Solution and explanation:

For 17 and 5, the results are 22, 12, 85, 3.4, and 2. The operators are addition, subtraction, multiplication, division, and remainder. % returns the remainder.

17 is not evenly divisible by 5, so ordinary division preserves the fractional part as 3.4 instead of returning a whole-number quotient.

Activity 1.2 — Apply operator precedence

2 + 3 * 4
(2 + 3) * 4
20 / 5 + 3
20 / (5 + 3)

Reflect:

  1. Which operations happen first without parentheses?
  2. How do parentheses change the result?
  3. Why should complex formulas use parentheses even when precedence is known?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Solution and explanation:

The results are 14, 20, 7, and 2.5. Multiplication and division happen before addition. Parentheses explicitly change or document the intended order.

Activity 1.3 — Update a counter

$completedTasks = 3
$completedTasks++
$completedTasks += 2
$completedTasks

Reflect:

  1. What does ++ do?
  2. What does += 2 do?
  3. What is the final value?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Solution and explanation:

++ adds one and += 2 adds two while assigning the result back. The final value is 6.

Part 2 — Control numeric types

Activity 2.1 — Compare text with numbers

$inputValue = '12'

$inputValue + 3
[int]$inputValue + 3
$inputValue * 3

Reflect:

  1. Why does the first expression return 123?
  2. Why does multiplication repeat a string here?
  3. Which expression performs numeric addition?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Solution and explanation:

The results are string 123, integer 15, and string 121212. With a string on the left, + concatenates and * repeats. Casting with [int] enables numeric addition.

Activity 2.2 — Convert division results

[int](7 / 2)
[int](5 / 2)
[double](7 / 2)
[decimal]7 / [decimal]2

Reflect:

  1. What happens when each fractional result is cast to [int]?
  2. Does this conversion always discard the fractional part?
  3. Which results preserve a fractional part?
  4. Why should calculations with decimal amounts use a deliberate numeric type?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Solution and explanation:

  1. Casting the two fractional results to [int] yields 4 and 2.
  2. This conversion rounds to the nearest integer; midpoint values round to the nearest even integer. It does not always discard the fraction. Here, 3.5 becomes 4, while 2.5 becomes 2.
  3. The double and decimal results both preserve 3.5.
  4. Decimal represents base-10 fractions such as decimal amounts more directly than binary floating-point types. Choose the type and rounding rule deliberately rather than assuming every numeric operation truncates.

The complete result sequence is 4, 2, 3.5, 3.5. The last two values have Double and Decimal types, respectively.

Activity 2.3 — Inspect result types

$wholeResult = 6 * 7
$fractionResult = 7 / 2
$decimalResult = [decimal]7 / [decimal]2

$wholeResult.GetType().Name
$fractionResult.GetType().Name
$decimalResult.GetType().Name

Reflect:

Record the type of each result and explain why types matter to later calculations.

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Solution and explanation:

The types are normally Int32, Double, and Decimal. Type affects precision, conversion, comparison, and formatting behaviour.

Part 3 — Round and format results

Activity 3.1 — Round a value

$measurement = 111.2226

[math]::Round($measurement)
[math]::Round($measurement, 2)
[math]::Round($measurement, 3)

Reflect:

  1. What does the second argument control?
  2. Does rounding change $measurement?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Solution and explanation:

The results are 111, 111.22, and 111.223. The second argument is the number of decimal places. The original variable remains 111.2226 because Round() returns a value.

The default midpoint rule for [math]::Round() is rounding to even. These three inputs are not midpoint cases. Assign the returned value explicitly if you want to replace the original variable.

Activity 3.2 — Separate calculation from display

[decimal]$price = 19.95
$quantity = 3
$total = $price * $quantity

$total
'Total: {0:N2}' -f $total
$total.GetType().Name

The N2 format displays two decimal places. Decimal and thousands separators follow the current culture; the formatted text can differ between computers.

Reflect:

  1. Which command produces a numeric value?
  2. Which command produces formatted text?
  3. Why should a script keep $total numeric until display time?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Solution and explanation:

  1. $total returns the numeric Decimal value 59.85.
  2. 'Total: {0:N2}' -f $total returns a String with two displayed decimal places. The final type inspection reports Decimal.
  3. Keeping the variable numeric permits later arithmetic without parsing text.

The formatted message depends on culture: examples include Total: 59.85 and Total: 59,85. Formatting does not alter the value or type of $total.

Part 4 — Challenge: calculate an invoice

Filename: Get-InvoiceCalculation.ps1

Save the supplied values and your calculation in this file. Run . .\Get-InvoiceCalculation.ps1 in your lab session.

Use these values:

[decimal]$hoursWorked = 7.5
[decimal]$hourlyRate = 42.75
[decimal]$taxRate = 0.21

For this exercise, keep the subtotal and tax unrounded. Round only the final total, and store that rounded numeric value in the object's Total property.

Calculate:

  1. the subtotal (hours × rate);
  2. the tax amount (subtotal × tax rate);
  3. the final total (subtotal + tax);
  4. the final total rounded to two decimals; and
  5. a PSCustomObject containing Hours, Rate, Subtotal, Tax, and Total.

Explain where parentheses, decimal types, and rounding help make the calculation clear.

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Invoice solution:

[decimal]$hoursWorked = 7.5
[decimal]$hourlyRate = 42.75
[decimal]$taxRate = 0.21

$subtotal = $hoursWorked * $hourlyRate
$tax = $subtotal * $taxRate
$finalTotal = $subtotal + $tax
$roundedTotal = [math]::Round($finalTotal, 2)

$invoice = [pscustomobject]@{
    Hours    = $hoursWorked
    Rate     = $hourlyRate
    Subtotal = $subtotal
    Tax      = $tax
    Total    = $roundedTotal
}

$invoice

Expected values are subtotal 320.625, tax 67.33125, unrounded final total 387.95625, and rounded total 387.96. Decimal types make the intended numeric type explicit; intermediate variables make each formula clear. Parentheses can clarify a combined formula: ($hoursWorked * $hourlyRate) * (1 + $taxRate). Only the final total is rounded to two decimal places.

Show solution Optimized

This version calculates the properties directly, while keeping the intermediate values unrounded and the final total numeric.

[decimal]$hoursWorked = 7.5
[decimal]$hourlyRate = 42.75
[decimal]$taxRate = 0.21

$subtotal = $hoursWorked * $hourlyRate
$tax = $subtotal * $taxRate

[pscustomobject]@{
    Hours    = $hoursWorked
    Rate     = $hourlyRate
    Subtotal = $subtotal
    Tax      = $tax
    Total    = [math]::Round(($subtotal + $tax), 2)
}

Practice and self-check

  1. Which operator returns a remainder?
  2. What does += do?
  3. Why does '10' + 5 differ from [int]'10' + 5?
  4. How do parentheses affect precedence?
  5. Which method rounds a number?
  6. Why should formatting be separate from calculation?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Self-check answers:

  1. % returns the remainder.
  2. += adds to the current value and assigns the result back to the variable.
  3. '10' + 5 concatenates into string 105; [int]'10' + 5 adds into integer 15.
  4. Parentheses group the expressions that must be evaluated first.
  5. [math]::Round() returns a rounded numeric value.
  6. Formatted output is text. Keeping the calculation numeric avoids reparsing that text and culture-dependent separators before further arithmetic.

Submission checklist

  • Complete each prediction and reflection.
  • Inspect at least three numeric result types.
  • Complete the invoice object with a total rounded to two decimals.
  • Keep calculated properties numeric until presentation.

Summary

Arithmetic reliability depends on operators, precedence, and data types. Convert text before calculations, use parentheses to communicate intent, and round only when the required precision is known.
