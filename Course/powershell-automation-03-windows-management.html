Automating Windows management

03 - Windows management

Originele pagina openen →

Windows management combines purpose-built cmdlets, security descriptors, event logs, background jobs, and firewall information. The safest workflow is to discover current state, make a narrowly scoped change, and verify the result.

Learning objectives

By the end of this lesson, you can:

  • discover commands in the Windows management and security modules;
  • inspect computer information and recent Windows events;
  • read and safely modify an access control list in a practice folder;
  • start, monitor, receive, and remove a background job; and
  • inspect Windows Firewall rules without changing them.

Prerequisites

  • Complete the PowerShell Basics course and the Windows information lesson.
  • Use Windows PowerShell or PowerShell 7 on Windows.
  • Use a disposable practice folder for permission changes.
  • Run read-only examples first; use administrator rights only when an assigned task requires them.

Discover management commands

Get-Command -Module Microsoft.PowerShell.Management |
    Sort-Object Noun, Verb |
    Select-Object -First 25 Name

Get-Command -Module Microsoft.PowerShell.Security |
    Select-Object Name

Prefer a purpose-built cmdlet when one exists. It usually provides clearer parameters, help, validation, and object output than directly calling a low-level method.

Collect computer and event information

Get-ComputerInfo |
    Select-Object CsName, WindowsProductName, WindowsVersion, OsLastBootUpTime

Get-WinEvent -LogName Application -MaxEvents 20 |
    Select-Object TimeCreated, Id, LevelDisplayName, ProviderName, Message

Get-WinEvent returns event objects. Filter before formatting, and avoid collecting an unlimited event log when a focused query is enough.

$startTime = (Get-Date).AddDays(-1)

Get-WinEvent -FilterHashtable @{
    LogName   = 'System'
    StartTime = $startTime
    Level     = 2, 3
} -ErrorAction SilentlyContinue |
    Select-Object TimeCreated, Id, LevelDisplayName, ProviderName

Understand access control lists

An access control list (ACL) contains access control entries. Each entry connects an identity to rights, an allow or deny type, and inheritance settings.

$practiceFolder = Join-Path 'C:\powershell' 'Windows-Management-Lab'
New-Item -Path $practiceFolder -ItemType Directory -Force

$acl = Get-Acl -Path $practiceFolder
$acl | Select-Object Owner, AreAccessRulesProtected
$acl.Access |
    Select-Object IdentityReference, FileSystemRights,
        AccessControlType, IsInherited

Do not copy an ACL from an unrelated folder without understanding inherited and explicit entries.

Add a rule only in a practice folder

The following example grants the current Windows identity read access to the dedicated folder. It first checks whether the equivalent rule already exists.

$identity = [System.Security.Principal.WindowsIdentity]::GetCurrent().Name
$acl = Get-Acl -Path $practiceFolder

$ruleExists = $acl.Access | Where-Object {
    $_.IdentityReference -eq $identity -and
    $_.FileSystemRights -band [System.Security.AccessControl.FileSystemRights]::ReadAndExecute -and
    $_.AccessControlType -eq 'Allow'
}

if (-not $ruleExists) {
    $rule = [System.Security.AccessControl.FileSystemAccessRule]::new(
        $identity,
        'ReadAndExecute',
        'ContainerInherit,ObjectInherit',
        'None',
        'Allow'
    )

    $acl.AddAccessRule($rule)
    Set-Acl -Path $practiceFolder -AclObject $acl -WhatIf
}

Set-Acl -WhatIf previews applying the complete modified security descriptor. In a real change, export or record the original ACL and verify the effective result afterward.

Run background jobs

A background job returns the prompt while work continues in another process. The job object represents the work; its output is retrieved separately.

Background job lifecycle

flowchart LR
    A["Start-Job"] --> B["Wait-Job: wait for completion"]
    B --> C["Receive-Job: retrieve output"]
    C --> D["Remove-Job: release the job"]

Inspect the job state and errors as well as its output; completion does not necessarily mean the work succeeded.

$job = Start-Job -Name 'ComputerSnapshot' -ScriptBlock {
    Get-CimInstance -ClassName Win32_OperatingSystem |
        Select-Object CSName, Caption, Version, LastBootUpTime
}

Get-Job -Name 'ComputerSnapshot'
Wait-Job -Job $job
$result = Receive-Job -Job $job -Keep
$result
Remove-Job -Job $job

Receive-Job normally removes received output from the job's result cache. Use -Keep only when you intentionally need to receive the same stored data again. Remove completed jobs when they are no longer needed.

Objects returned from process-based or remote jobs are serialized copies. Methods may be unavailable even though properties remain useful.

Inspect Windows Firewall

Get-NetFirewallProfile |
    Select-Object Name, Enabled, DefaultInboundAction, DefaultOutboundAction

Get-NetFirewallRule -PolicyStore ActiveStore |
    Where-Object Enabled -eq 'True' |
    Group-Object Direction, Action |
    Sort-Object Name |
    Select-Object Name, Count

Firewall rule names, display names, and groups can be localized or managed by policy. Inspect PolicyStoreSourceType before assuming that a local change is appropriate. Make changes only through an approved change process.

Practice and self-check

  1. Why should you prefer a purpose-built cmdlet to a low-level CIM method?
Show solution

A purpose-built cmdlet generally provides clearer parameters, help, validation, and object output. Check its documentation and safety features before use.

  1. Why is a filtered event query better than retrieving an entire log?
Show solution

It limits the result to relevant events, such as a time range or severity, reducing the amount of data to retrieve and review.

  1. What information is stored in an access control entry?
Show solution

An entry identifies a user or group, its rights, whether access is allowed or denied, and inheritance settings.

  1. Why must Set-Acl receive the complete ACL object?
Show solution

Set-Acl applies the supplied security descriptor to the target, rather than adding only one isolated entry. Read and modify the existing ACL carefully so you do not unintentionally replace other permissions.

  1. Which commands manage the lifecycle of a background job?
Show solution

Use Start-Job to start it, Get-Job to inspect it, Wait-Job to wait, Receive-Job to retrieve output, and Remove-Job to remove it. Inspect the job state and errors as well as the output.

  1. Why might a firewall rule resist a local change?
Show solution

The active rule may be supplied or enforced by Group Policy or another policy store rather than locally managed. Inspect its policy source and use the approved change process.

Apply the lesson in Hands-on 16 — Windows management.

Summary

Windows management automation starts with discovery and narrow queries. Treat ACLs as complete security descriptors, manage the full job lifecycle, keep firewall work read-only unless specifically authorized, and verify every change.
