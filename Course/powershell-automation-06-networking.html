Automating Windows networking

06 - Networking

Originele pagina openen →

Windows networking cmdlets expose IP addresses, interfaces, routes, DNS client settings, connectivity tests, and firewall rules as objects. These commands are useful for both diagnostics and controlled configuration.

Learning objectives

By the end of this lesson, you can:

  • discover commands in the NetTCPIP, DnsClient, and NetSecurity modules;
  • inspect interfaces, addresses, gateways, routes, DNS clients, and firewall profiles;
  • test ICMP and TCP connectivity with structured results;
  • explain the parameters required for a static IP configuration; and
  • build a read-only network-readiness report.

Prerequisites

  • Complete the PowerShell Basics course and the Windows information lesson.
  • Use Windows with the networking modules available.
  • Do not change IP, DNS, route, or firewall settings unless the instructor provides an isolated VM and exact values.

Discover networking commands

Get-Command -Module NetTCPIP |
    Sort-Object Noun, Verb |
    Select-Object Name

Get-Command -Module DnsClient -Noun '*DnsClient*' |
    Select-Object Name

Get-Command -Module NetSecurity -Noun '*NetFirewall*' |
    Select-Object Name

The noun often reveals the resource: NetIPAddress, NetIPInterface, NetRoute, DnsClient, or NetFirewallRule.

Inspect IP configuration

Get-NetIPConfiguration |
    Select-Object InterfaceAlias, InterfaceIndex, IPv4Address,
        IPv4DefaultGateway, DNSServer

Get-NetIPAddress -AddressFamily IPv4 |
    Where-Object AddressState -eq 'Preferred' |
    Select-Object InterfaceAlias, InterfaceIndex, IPAddress,
        PrefixLength, PrefixOrigin, AddressState

Get-NetIPInterface -AddressFamily IPv4 |
    Select-Object InterfaceAlias, InterfaceIndex, ConnectionState, Dhcp, InterfaceMetric

Interface aliases can change and may be localized. An interface index is useful for selecting the exact adapter during one configuration workflow, but it can also change after hardware or operating-system changes. Discover immediately before modifying.

Understand static IP parameters

A static IPv4 configuration normally needs:

  • the exact interface alias or index;
  • a unique IPv4 address;
  • a prefix length, such as 24 for 255.255.255.0;
  • a default gateway in a reachable subnet; and
  • one or more DNS server addresses.

Preview only with instructor-provided values:

New-NetIPAddress `
    -InterfaceAlias 'Ethernet' `
    -IPAddress '192.0.2.20' `
    -PrefixLength 24 `
    -DefaultGateway '192.0.2.1' `
    -WhatIf

Set-DnsClientServerAddress `
    -InterfaceAlias 'Ethernet' `
    -ServerAddresses '192.0.2.53', '192.0.2.54' `
    -WhatIf

The 192.0.2.0/24 network is documentation space and is not a usable lab configuration unless the instructor has deliberately built that isolated network. A wrong network change can disconnect the machine.

Inspect the routing table

Get-NetRoute -AddressFamily IPv4 |
    Sort-Object DestinationPrefix, RouteMetric |
    Select-Object DestinationPrefix, NextHop, InterfaceAlias, RouteMetric

Find-NetRoute -RemoteIPAddress '1.1.1.1' |
    Select-Object IPAddress, InterfaceAlias, NextHop, RouteMetric

A route describes which interface and next hop Windows selects for a destination. Lower effective metrics are generally preferred among otherwise applicable routes.

Inspect DNS client configuration

Get-DnsClient |
    Select-Object InterfaceAlias, ConnectionSpecificSuffix,
        RegisterThisConnectionsAddress

Get-DnsClientServerAddress -AddressFamily IPv4 |
    Select-Object InterfaceAlias, ServerAddresses

Resolve-DnsName -Name 'learn.microsoft.com' -Type A

DNS name resolution can fail even when basic IP connectivity succeeds, so test them separately.

Test connectivity

Separate diagnostic questions

flowchart LR
    A["Target name or address"] --> B["DNS: can the name be resolved?"]
    A --> C["ICMP: does the host answer a ping?"]
    A --> D["TCP: is the selected port reachable?"]

These tests answer different questions. A blocked ping does not prove that a TCP service is unavailable, and a DNS failure does not prove an IP address is unreachable.

Test-NetConnection -ComputerName 'learn.microsoft.com'

Test-NetConnection -ComputerName 'learn.microsoft.com' -Port 443 |
    Select-Object ComputerName, RemoteAddress, RemotePort, TcpTestSucceeded

An ICMP failure does not prove the host is unavailable because firewalls may block echo requests. A TCP test checks one service port and is often more relevant.

Inspect firewall configuration

Get-NetFirewallProfile |
    Select-Object Name, Enabled, DefaultInboundAction, DefaultOutboundAction

Get-NetFirewallRule -PolicyStore ActiveStore |
    Where-Object Enabled -eq 'True' |
    Select-Object -First 20 DisplayName, Direction, Action, Profile,
        PolicyStoreSourceType

Firewall ports and addresses are stored in associated filter objects.

Get-NetFirewallRule -DisplayName 'Windows Remote Management*' |
    Get-NetFirewallPortFilter |
    Select-Object Protocol, LocalPort, RemotePort

Practice and self-check

  1. Which modules manage TCP/IP, DNS clients, and firewall rules?
Show solution

NetTCPIP provides TCP/IP commands, DnsClient provides DNS client commands, and NetSecurity provides firewall commands.

  1. Why should an interface be rediscovered immediately before a change?
Show solution

Aliases and interface indexes can change. Rediscovering and checking the adapter helps ensure that the change targets the intended interface.

  1. What does prefix length 24 represent?
Show solution

For IPv4, /24 means the first 24 bits identify the network prefix. Its subnet mask is 255.255.255.0.

  1. What information does a default route provide?
Show solution

A default route describes where to send traffic when no more specific route matches, including the selected interface and usually a next-hop gateway.

  1. Why should DNS and TCP connectivity be tested separately?
Show solution

DNS tests whether a name resolves; TCP tests whether a particular port is reachable. One can succeed while the other fails, so separate results help identify the problem.

  1. Why might the active firewall policy differ from locally stored rules?
Show solution

The active policy can include rules from other sources, such as Group Policy, in addition to local rules. Inspect the policy source rather than assuming that every active rule is locally managed.

Summary

Windows networking modules provide structured discovery and diagnostics for interfaces, addresses, routes, DNS, connectivity, and firewall state. Query first, select exact targets, preview supported changes, and never alter connectivity without an approved rollback path.
