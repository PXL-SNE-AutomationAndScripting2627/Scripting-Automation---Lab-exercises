Automating Active Directory

04 - Active Directory

Originele pagina openen →

Active Directory Domain Services (AD DS) provides centralized identity, authentication, authorization, policy, and resource organization for Windows domain networks. The ActiveDirectory PowerShell module makes individual and bulk administration discoverable and repeatable.

Learning objectives

By the end of this lesson, you can:

  • explain domains, domain controllers, organizational units, and directory objects;
  • distinguish organizational units from security and distribution groups;
  • discover and use ActiveDirectory module commands;
  • query and manage users, groups, group membership, and organizational units; and
  • design a safe, previewable bulk-provisioning workflow.

Prerequisites

  • Complete the PowerShell Basics course and the Windows management lessons.
  • Use an instructor-provided training domain and account with delegated lab permissions.
  • Have the ActiveDirectory module available through Windows Server management tools or RSAT.
  • Never run the modifying examples against a production directory.

Understand the directory structure

An AD DS directory is hierarchical:

  • a forest is the top-level security and schema boundary;
  • a domain contains directory objects and a DNS name;
  • a domain controller hosts AD DS and responds to directory requests;
  • an organizational unit (OU) organizes objects, supports delegation, and can receive Group Policy; and
  • an object represents a user, group, computer, contact, or another directory resource.

Example directory hierarchy

flowchart TD
    A["Forest"] --> B["Domain: training.example"]
    B --> C["OU: PowerShell Labs"]
    C --> D["OU: Lab Users"]
    D --> E["User: Alex Morgan"]

This shows one possible hierarchy; domain controllers host the directory service and are not represented as a parent of the OUs.

Distinguished names identify an object's location from the object to the domain root. For example:

CN=Alex Morgan,OU=Lab Users,OU=PowerShell Labs,DC=training,DC=example

Organizational units versus groups

Organizational units Groups
Organize directory objects hierarchically Collect users, computers, or groups
Support delegated administration Assign access or distribute messages
Can be linked to Group Policy Do not directly receive Group Policy
An object normally has one parent OU/container An object can belong to many groups

Use OUs for organization and delegated management. Use security groups to assign permissions. Avoid assigning permissions directly to individual user accounts when a suitable group can represent the role.

Prepare and discover the module

Get-Module -ListAvailable ActiveDirectory
Import-Module ActiveDirectory

Get-Command -Module ActiveDirectory -Noun ADUser, ADGroup, ADOrganizationalUnit |
    Sort-Object Noun, Verb |
    Select-Object Name

On a Windows client, administrators normally install the AD DS and AD LDS RSAT tools. On Windows Server, install the appropriate management tools rather than adding the AD DS server role merely to obtain cmdlets.

Query users deliberately

Get-ADUser requires -Identity for one known user or -Filter for a query. It returns a default property set unless -Properties requests more.

Get-ADUser -Identity 'amorgan' -Properties Department, Title, Enabled |
    Select-Object SamAccountName, Name, Department, Title, Enabled

Get-ADUser -Filter "Department -eq 'IT'" -Properties Department |
    Select-Object Name, SamAccountName, Department

Avoid -Filter * without a search base in a large directory. Scope queries to the correct OU when possible.

$searchBase = 'OU=Lab Users,OU=PowerShell Labs,DC=training,DC=example'
Get-ADUser -Filter * -SearchBase $searchBase |
    Select-Object Name, SamAccountName, Enabled

Create and update a user

Ask for a temporary password without embedding it in the script. Preview the creation first.

$temporaryPassword = Read-Host -Prompt 'Enter the temporary password' -AsSecureString

$userParameters = @{
    Name                  = 'Alex Morgan'
    GivenName             = 'Alex'
    Surname               = 'Morgan'
    SamAccountName        = 'amorgan'
    UserPrincipalName     = 'amorgan@training.example'
    Path                  = 'OU=Lab Users,OU=PowerShell Labs,DC=training,DC=example'
    Department            = 'IT'
    AccountPassword       = $temporaryPassword
    Enabled               = $true
    ChangePasswordAtLogon = $true
}

New-ADUser @userParameters -WhatIf
Set-ADUser -Identity 'amorgan' -Title 'Support trainee' -WhatIf

A robust script first checks whether the SamAccountName and user principal name are available. It should report a conflict instead of silently updating the wrong account.

Manage organizational units and groups

$labRoot = 'OU=PowerShell Labs,DC=training,DC=example'

New-ADOrganizationalUnit -Name 'Lab Users' -Path $labRoot -WhatIf

New-ADGroup `
    -Name 'PS Lab Operators' `
    -SamAccountName 'PSLabOperators' `
    -GroupCategory Security `
    -GroupScope Global `
    -Path "OU=Groups,$labRoot" `
    -WhatIf

Add-ADGroupMember -Identity 'PSLabOperators' -Members 'amorgan' -WhatIf

Use Get-ADGroupMember to verify membership. Removing an object or group membership also supports -WhatIf; always resolve the exact target first.

Design safe bulk provisioning

A CSV-driven workflow should:

  1. validate required columns and values;
  2. scope all paths to a dedicated training OU;
  3. check for duplicate identities;
  4. use one securely entered temporary password rather than storing it in CSV;
  5. create accounts disabled or require password change at first sign-in;
  6. support -WhatIf through SupportsShouldProcess; and
  7. return one result object per input row.
Import-Csv '.\new-users.csv' | ForEach-Object {
    [pscustomobject]@{
        SamAccountName = $_.SamAccountName
        TargetOU       = $_.Path
        PlannedAction  = 'Create'
    }
}

Do not use a CSV as proof that a change succeeded. Query AD after the operation and record the verified state.

Treat domain join as a separate infrastructure change

Joining a computer changes its security context, requires suitable local and domain credentials, and commonly requires a restart. It is not part of the student provisioning lab. On an instructor-assigned disposable client, an administrator can first preview the exact request:

Add-Computer `
    -ComputerName 'Client01' `
    -DomainName 'training.example' `
    -OUPath 'OU=Lab Computers,OU=PowerShell Labs,DC=training,DC=example' `
    -Credential (Get-Credential) `
    -WhatIf

Do not use -Restart until the change is approved, connectivity is verified, BitLocker and local recovery access are understood, and the instructor has provided a rollback procedure.

Practice and self-check

  1. How do OUs and groups serve different purposes?
Show solution

Organizational units organize objects and support delegation and Group Policy. Groups collect members for purposes such as assigning permissions or distributing messages.

  1. Why should a large user query include -SearchBase?
Show solution

It limits the search to the intended directory location, reducing unnecessary results and helping avoid inspecting unrelated accounts.

  1. Why does Get-ADUser require -Properties for non-default properties?
Show solution

The cmdlet returns a default set of properties. Use -Properties to request additional attributes, such as Department, needed by the report.

  1. Which parameters identify the destination OU and logon names for New-ADUser?
Show solution

-Path identifies the destination OU. -SamAccountName specifies the SAM account name, and -UserPrincipalName specifies the user principal name used for sign-in.

  1. Why should temporary passwords stay out of CSV files?
Show solution

CSV files store plain text and can be copied, shared, or committed accidentally. Request the password securely instead and do not expose it in logs or source files.

  1. What should a bulk-provisioning script return for every input row?
Show solution

Return a structured result identifying the input account and its outcome, including validation errors, conflicts, failures, or a planned action when using -WhatIf. Verify actual changes in Active Directory.

Summary

Active Directory automation manages centralized objects through scoped, object-based commands. Understand the directory hierarchy, separate OU and group responsibilities, query narrowly, protect passwords, preview changes, and verify results in a dedicated training OU.
