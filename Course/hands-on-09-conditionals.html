Hands-on — Conditionals

09 - Conditionals

Originele pagina openen →

Goal

Make PowerShell choose an appropriate action by testing values, types, paths, and combinations of conditions.

Learning objectives

By the end of this lab, you can:

  • use if, elseif, and else branches;
  • combine comparisons with -and, -or, and -not;
  • distinguish $null, empty text, and valid values;
  • use Test-Path in a decision; and
  • use switch for clear multi-value classification.

Prerequisites

  • Complete the variables and parameters hands-on labs.
  • Complete the conditionals lesson before starting this lab.
  • Understand Boolean values, object properties, and simple pipeline commands.

Environment and safety requirements

Use PowerShell 7 on your Windows lab computer. Your instructor must first prepare C:\powershell with writable access. This lab only inspects paths and changes session variables and does not change system settings. Save the challenge script in your lab folder. Administrator rights are not required. Keep the same terminal open. If it is restarted, recreate an activity's values before using them in a later step.

How to work in this lab

Predict which branch runs, execute the code, and explain why.

After attempting each activity, open Show solution to check your commands, expected results, and explanations. The final exercise and self-check also have solutions. Keep the session and setup required by the activity. If you already changed a file or variable, compare its result rather than replaying the change from the solution.

    'Service is available.'
} else {
    'Service is unavailable.'
}

Reflect

  2. What type must the condition produce?
  3. What changes when the value becomes $false?

Expected results and reflection answers:

The first branch runs for $true; the else branch runs for $false. Conditions are interpreted as Boolean values.

} elseif ($score -ge 50) {
    $result = 'Pass'
} else {
    $result = 'Fail'
}

$result

  1. Which branch runs?
  2. Why is the 50 test placed after the 85 test?
  3. What result should scores 92, 50, and 49 receive?

Checkpoint: Verify the supplied score and the three requested boundary examples.

Expected results and reflection answers:

Score 78 is Pass. The higher threshold comes first so scores 85 and above are not captured by the broader pass range. Scores 92, 50, and 49 produce Distinction, Pass, and Fail.

The supplied score displays Pass.

Score-change solution:

Keep the if statement from Activity 1.2, but replace its first assignment with $score = 90 before rerunning it. Do not reset it to 78.

$score = 90

if ($score -ge 85) {
    $result = 'Distinction'

Part 3 — Test missing values and paths

Activity 3.1 — Compare null and empty text

Predict

Which values count as missing, empty, or lacking useful text?

Part 5 — Challenge: classify device readiness

Filename: Get-DeviceReadiness.ps1

Save the supplied data and your challenge commands in this file. Run . .\Get-DeviceReadiness.ps1 in your lab session.

Use:

$devices = @(
    [pscustomobject]@{ Name = 'LT-204'; FreeGB = 24; Updated = $true;  State = 'Online'  }
    [pscustomobject]@{ Name = 'LT-205'; FreeGB = 8;  Updated = $true;  State = 'Online'  }
    [pscustomobject]@{ Name = 'DT-301'; FreeGB = 40; Updated = $false; State = 'Online'  }
    [pscustomobject]@{ Name = 'DT-302'; FreeGB = 30; Updated = $true;  State = 'Offline' }
)

For each device, create a result object with Name and Readiness:

  • Ready when online, updated, and at least 15 GB is free;
  • Attention when online but any other readiness check fails;
  • Unavailable when offline; and
  • Unknown for any other state.

A foreach loop runs its body once for each input device. The loop variable $device holds the current object; output one custom object per iteration. Use the collection iteration reference in the variables lesson if needed. Start with this structure and write the decisions yourself:

$readinessResults = foreach ($device in $devices) {
    # Decide the readiness for this device.
    # Output an object with Name and Readiness.
}

Use foreach, if/else, and a nested or separate switch. Explain the order of your checks.

Success criteria: Return one object per input in the original order. Check offline state before the two online checks. The unknown-state rule must also work, even though the supplied dataset contains only online and offline devices.

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Use the challenge's supplied input objects in the same session.

Readiness classification solution:

foreach ($device in $devices) {

    if ($device.State -eq 'Offline') {
        $readiness = 'Unavailable'
    }
    elseif ($device.State -eq 'Online' -and $device.Updated -and $device.FreeGB -ge 15) {
        $readiness = 'Ready'
    }
    elseif ($device.State -eq 'Online') {
        $readiness = 'Attention'
    }
    else {
        $readiness = 'Unknown'
    }

    [PSCustomObject]@{
        Name      = $device.Name
        Readiness = $readiness
    }
}
Show solution Optimized

Use the challenge's supplied input objects in the same session.

Readiness classification solution:

$readinessResults = foreach ($device in $devices) {
    $readiness = switch ($device.State) {
        'Offline' { 'Unavailable' }
        'Online' {
            if ($device.Updated -and $device.FreeGB -ge 15) {
                'Ready'
            } else {
                'Attention'
            }
        }
        default { 'Unknown' }
    }

    [pscustomobject]@{
        Name      = $device.Name
        Readiness = $readiness
    }
}

$readinessResults

Expected results are Ready, Attention, Attention, and Unavailable. State is checked first because offline devices cannot be ready; online devices then receive the two readiness checks.

Wat is the difference between the two solutions? The first uses if/elseif/else statements to classify readiness, while the second uses a switch statement for the state check and an if statement for the online readiness checks. Both produce the same output but demonstrate different approaches to decision-making in PowerShell.

Self-check answers:

Question Answer
If condition A Boolean/truth value.
elseif Runs when earlier conditions were false and its own is true.
-and / -or Both true versus at least one true.
-not Reverses truth.
Null versus empty Absence differs from a present zero-length string.
default Fallback for unmatched cases.

Summary

Conditionals turn Boolean tests into controlled branches. Order specific checks carefully, combine conditions explicitly, and include fallback handling for missing or unexpected values.
