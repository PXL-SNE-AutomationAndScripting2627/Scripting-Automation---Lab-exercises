Hands-on — Interactive PowerShell introduction

01 - Intro, Cmdlets, help, and commands

Originele pagina openen →

Goal

Explore what PowerShell is, why organisations automate work, and how to use a few safe PowerShell commands. This is an interactive lab: for each activity, predict first, run the command, then explain what you observed.

Learning objectives

By the end of this lab, you can:

  • explain why automation and scripting are useful in an IT context;
  • describe PowerShell as both a command-line shell and a scripting language;
  • identify the PowerShell version and edition installed on your computer;
  • use Get-Command and Get-Help to discover cmdlets;
  • create and use a personal practice folder safely;
  • create, run, and improve a small PowerShell script; and
  • describe the purpose of an execution policy without changing it.

Prerequisites

  • Complete Introduction before starting this lab.
  • Complete Cmdlets, help, and commands before starting this lab.
  • PowerShell is available on your computer. PowerShell 7 (pwsh) is recommended.
  • Visual Studio Code and the Microsoft PowerShell extension are installed.
  • Your instructor has prepared C:\powershell with writable access.
  • Work only in the practice folder created in this lab. Do not run commands on production systems or folders that contain important files.

How to work in this lab

For every activity, complete the three steps.

  1. Predict: write or discuss what you think will happen.
  2. Run: enter the command exactly as shown.
  3. Reflect: answer the questions in your own words.

When a question asks you to discuss, compare your answer with a partner before the class discussion.

After attempting each activity, open Show solution to check your commands, expected results, and explanations. The final exercise and self-check also have solutions. Keep the session and setup required by the activity. If you already changed a file or variable, compare its result rather than replaying the change from the solution.

Discussion solution:

Prediction and reflection answers:

The number of available commands depends on installed modules and the session. Get-Date, Get-Location, and Get-ChildItem are valid discoveries. Verb-noun names make commands easier to predict and search: Get suggests reading data. These commands discover metadata; they do not change files or configuration.

Naming solution:

Item Name
Get-Command Cmdlet or command name
Get within Get-Command Verb
Command within Get-Command Noun
-Verb Named parameter

A cmdlet performs an action; its parameters control its behaviour. A hyphen marks a named parameter, and a space separates that parameter from its value. Within the command name, the verb describes the action and the noun its target. A switch parameter can be supplied without a following value.

Parameters can be required or optional. Inspect their Required? information with help, or inspect the command syntax:

Get-Help Get-Command -Parameter Verb
Get-Command Get-Command -Syntax

Verb is optional: Get-Command also works without it.

Help solution:

Help describes the command, its syntax, parameters, and examples. SYNOPSIS summarises its purpose. -Format chooses the date display format. One small example is:

Get-Date -Format 'yyyy-MM-dd'

This displays the current calendar date in year-month-day order. The date changes each day. If local help lacks examples, the supplied Microsoft links provide the full documentation.

Part 4 — Create a safe practice folder

Activity 4.1 — Inspect before you create

In this lab, use a folder named Introduction-Lab on your local machine.

Predict

What should happen if you check whether a folder exists before creating it?

Run

You can check whether a folder exists before creating it. This is a safe practice to avoid overwriting or deleting important data.

For example, check whether you already have a folder under the root-folder C:\powershell\Introduction-Lab with:

$practiceFolder = 'C:\powershell\Introduction-Lab'
Test-Path -Path $practiceFolder

Reflect

  1. Did the folder already exist?
  2. Why is Test-Path useful before creating, copying, or removing something?
  3. Why do we store the folder path in $practiceFolder instead of repeatedly typing it?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Path inspection answers:

Test-Path returns False for a folder that does not exist and True for an existing path. Record the result from your computer. The workspace in this lab is C:\powershell\Introduction-Lab.

Check before file operations to confirm the intended target and avoid mixing work with existing data. Keeping the path in $practiceFolder reduces typing errors and lets later commands reuse the same location.

Activity 4.2 — Create and enter the folder

Run

Test-Path -Path $practiceFolder
Set-Location -Path $practiceFolder
Get-Location

Reflect

  1. What does -Force do in this example?
  2. What output proves that you are in the intended folder?
  3. Why should you confirm your location before working with files?

Safety rule: never copy a destructive command from the internet without understanding its path, target, and possible effect. In later lessons you will use preview options such as -WhatIf before changing files.

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Folder verification answers:

-Force permits creating the directory when it already exists; it does not empty it. Test-Path should return True, and Get-Location should report C:\powershell\Introduction-Lab.

Confirming the location helps prevent later file commands from targeting a different folder. Keep any existing work rather than deleting it.

Part 6 — Execution policies and responsible scripting

Activity 6.1 — Inspect, do not change

Execution policies are a Windows safety feature that helps control when scripts can run. They are not a complete security boundary, but they can prevent accidental script execution.

  3. Why should you ask before changing an execution policy on a managed device?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Policy inspection answers:

Get-ExecutionPolicy shows the effective policy; -List shows all scopes. Record the actual values: they depend on the machine and organisational rules. Undefined means no policy is set at that scope.

  1. Process applies only to the current PowerShell session.
  2. MachinePolicy and UserPolicy let an organisation apply policy centrally.
  3. Ask before changing a managed policy: it may enforce school or employer requirements. Policy settings do not establish whether a script is trusted.

Part 7 — Challenge: explain your first automation

Filename: Start-Lab.ps1

Work alone for five minutes, then compare with a partner.

Scenario

A lecturer wants a small script that creates a dated message at the start of each lab session. The lecturer wants to run it in the personal practice folder and review its output before using it in class.

Your task

Create a script named Start-Lab.ps1 that:

  1. writes a welcome message for the Automation and Scripting course;
  2. displays the current date and time;
  3. displays the current PowerShell version; and
  4. does not create, remove, or change any files.

Use Get-Help if you need to rediscover a command.

Suggested starting point

# Write your script here.

Explain your work

Answer in complete sentences.

  1. Which commands did you use, and what does each one do?
  2. Why is this script safe to test in a classroom?
  3. What would you add if the script needed to save a report later?
  4. What should you check before you automate a task that changes data?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Save this script as Start-Lab.ps1 in $practiceFolder, then run it with .\Start-Lab.ps1 after reviewing the saved text.

First automation solution:

Write-Output 'Welcome to the Automation and Scripting course!'
Write-Output "The current date and time is $(Get-Date)."
Write-Output "PowerShell version: $($PSVersionTable.PSVersion)"

Write-Output displays text, Get-Date returns the current date and time, and $PSVersionTable.PSVersion supplies the version. The script only outputs information, so it does not modify files. Before automating a data-changing task, check the target path, permissions, input data, expected result, preview options, and recovery plan.

The three output lines contain a welcome, the current date and time, and the installed PowerShell version. The last two values vary between runs or machines. To save a report later, choose a safe destination, check existing files, then add the appropriate export command.

Show solution Optimized

This version groups the output lines before sending them to the pipeline. It still only displays information and does not change any files.

@(
    'Welcome to the Automation and Scripting course!'
    "The current date and time is $(Get-Date)."
    "PowerShell version: $($PSVersionTable.PSVersion)"
) | Write-Output

Summary

PowerShell is both a shell for entering commands and a scripting language for automating repeatable work. Cmdlets commonly use a verb-noun name, and Get-Command plus Get-Help let you discover and understand them. Good automation begins with a clear task, a safe practice environment, small tests, and careful review of commands and scripts before they run.
