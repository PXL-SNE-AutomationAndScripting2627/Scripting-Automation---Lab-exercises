Automating the Windows registry

07 - Registry

Originele pagina openen →

PowerShell exposes the Windows registry through a provider. Registry keys behave like containers on a PowerShell drive, while registry values are properties of those keys.

Learning objectives

By the end of this lesson, you can:

  • navigate the HKCU: and HKLM: registry drives;
  • distinguish registry keys from registry values;
  • read, create, update, rename, and remove values in a dedicated practice key;
  • preview and verify registry changes; and
  • restore or remove lab settings safely.

Prerequisites

  • Complete the PowerShell Basics course, especially files, providers, and exception handling.
  • Use PowerShell on Windows.
  • Perform modifying examples only under HKCU:\Software\PowerShellCourse\RegistryLab.
  • Do not copy examples to policy, security, startup, Windows Update, or system-wide locations.

Understand the Registry provider

Get-PSProvider -PSProvider Registry
Get-PSDrive -PSProvider Registry

PowerShell normally exposes:

  • HKCU: for HKEY_CURRENT_USER; and
  • HKLM: for HKEY_LOCAL_MACHINE.

The provider makes familiar item cmdlets available. Registry keys are items; entries and their data are item properties.

Key and value overview

The diagram distinguishes the lab key from its values. Modify only the specified practice key, and preview changes first.

Registry task Cmdlet
Get or enumerate keys Get-Item, Get-ChildItem
Create, rename, or remove a key New-Item, Rename-Item, Remove-Item
Read values Get-ItemProperty, Get-ItemPropertyValue
Create a value New-ItemProperty
Change a value Set-ItemProperty
Rename or remove a value Rename-ItemProperty, Remove-ItemProperty

Navigate without losing your location

You can use a full provider path from any current location.

Get-Item -Path 'HKCU:\Software'
Get-ChildItem -Path 'HKCU:\Software' |
    Select-Object -First 10 PSChildName, Name

Get-Item -Path 'Registry::HKEY_CURRENT_USER\Software'

If you temporarily use Set-Location, save and restore the previous location.

Push-Location 'HKCU:\Software'
Get-Location
Pop-Location

Create a dedicated practice key

$labKey = 'HKCU:\Software\PowerShellCourse\RegistryLab'

New-Item -Path $labKey -Force -WhatIf
Test-Path -Path $labKey

Preview the operation, then run it without -WhatIf only for this exact path. -Force creates missing parent keys and returns the existing key when it already exists.

Create and read registry values

Registry values have a name, a type, and data.

New-ItemProperty `
    -Path $labKey `
    -Name 'CourseMode' `
    -PropertyType String `
    -Value 'Practice' `
    -WhatIf

New-ItemProperty `
    -Path $labKey `
    -Name 'AttemptCount' `
    -PropertyType DWord `
    -Value 1 `
    -WhatIf

After performing the approved operations, read the values:

Get-ItemProperty -Path $labKey |
    Select-Object CourseMode, AttemptCount

Get-ItemPropertyValue -Path $labKey -Name 'CourseMode'

Common value types include String, ExpandString, MultiString, Binary, DWord, and QWord. Choose the type expected by the consuming application.

Update and rename values

Set-ItemProperty -Path $labKey -Name 'CourseMode' -Value 'Assessment' -WhatIf
Rename-ItemProperty -Path $labKey -Name 'AttemptCount' -NewName 'RunCount' -WhatIf

Query the value before and after a real change. Registry commands can succeed syntactically while the application still rejects an unsupported value.

Find keys and values carefully

Recursive registry searches can be slow and may encounter access errors. Start from the narrowest known path.

Get-ChildItem -Path 'HKCU:\Software\PowerShellCourse' -Recurse |
    Where-Object PSChildName -Like '*Registry*' |
    Select-Object Name

$properties = Get-ItemProperty -Path $labKey
$properties.PSObject.Properties |
    Where-Object Name -NotLike 'PS*' |
    Select-Object Name, Value

Remove only the lab artifacts

Remove-ItemProperty -Path $labKey -Name 'CourseMode' -WhatIf
Remove-Item -Path $labKey -Recurse -WhatIf

Before removal, compare the resolved path to the exact lab key. Do not use a wildcard or a variable that has not been validated. After cleanup, Test-Path $labKey should return False.

Build reversible registry automation

A responsible registry script:

  1. validates that it is running on Windows;
  2. restricts its path to an approved root;
  3. captures the previous value and type;
  4. supports -WhatIf and confirmation;
  5. verifies the new state; and
  6. provides a restore or cleanup action.

Practice and self-check

  1. Which registry hives do HKCU: and HKLM: represent?
Show solution

HKCU: represents HKEY_CURRENT_USER; HKLM: represents HKEY_LOCAL_MACHINE.

  1. Why are registry values managed with ItemProperty cmdlets?
Show solution

The Registry provider represents keys as items and the named values inside them as item properties. Use commands such as Get-ItemProperty and Set-ItemProperty to work with those values.

  1. What is the difference between String and DWord value types?
Show solution

String stores text; DWord stores a 32-bit integer. Use the type expected by the application that reads the value.

  1. Why should a recursive search start from a narrow path?
Show solution

A narrow starting path reduces the number of keys searched and the chance of encountering unrelated data or access errors. It also makes results easier to review.

  1. What should be recorded before changing an existing value?
Show solution

Record the exact key and value name, the previous data, and its registry type so the original setting can be restored.

  1. Which checks make registry automation reversible?
Show solution

Confirm Windows and the approved path, record whether the value existed and its previous data and type, preview the change, and verify the result. Provide a restore action for an existing value or a scoped cleanup action for a new lab value, then verify the restored state.

Apply the lesson in Hands-on 20 — Registry.

Summary

The Registry provider maps keys to items and values to item properties. Work only in an approved path, choose the correct value type, preview supported changes, verify results, and keep a clear rollback or cleanup action.
