Regular Expressions

04 - Regular expressions

Originele pagina openen →

Learning objectives

  • Read and write basic regular-expression patterns.
  • Choose between exact comparison, wildcards, and regex for practical tasks.
  • Use -match, -replace, -split, and Select-String safely.
  • Test patterns against representative input.

Prerequisites

  • Familiarity with strings and pipeline filtering.

PowerShell supports regular expressions with Select-String, the -match, -replace, and -split operators, and the [System.Text.RegularExpressions.Regex] class.

Why regex matters in administration

A wildcard is a simple pattern for selecting names, such as *.log for log files. A regular expression (regex) describes the structure of text: which characters are allowed, how often they occur, and which parts to extract.

An administrator might first select log files with a wildcard, then use regex to find error codes inside those files. Regex is useful when a script must validate identifiers, extract a domain and user, or hide part of an identifier before sharing a report. These tasks appear throughout this lesson and lab.

Choose a pattern for the task

Real-world task Suitable approach Why it fits
Check one exact service name $name -eq 'Spooler' No pattern is needed.
Select log files Get-ChildItem -File -Filter '*.log' A wildcard selects names by extension.
Select names starting with PC- $name -like 'PC-*' The rest of the name can be anything.
Require PC- and exactly three digits $name -match '^PC-[0-9]{3}$' Regex expresses character type and count.
Extract domain and user from a log line Named capture groups with -match Regex returns meaningful parts for later commands.
Mask part of a structured identifier -replace with capture groups Regex can replace one part while keeping another.

Reading the pattern ^PC-[0-9]{3}$

flowchart LR
    A["Start of string: ^"] --> B["Literal prefix: PC-"]
    B --> C["ASCII digit: [0-9]"]
    C --> D["Repeat digit exactly 3 times: {3}"]
    D --> E["End of string: $"]

For example, PC-123 matches; PC-12 and PC-1234 do not.

Wildcards can also use character ranges: PC-[0-9][0-9][0-9] works with -like. Regex becomes convenient when patterns need repetition counts, alternatives, or capture groups. Choose the clearest pattern for the task.

Wildcards and regex use different syntax

The operator or command parameter determines which pattern language is used. -like uses wildcards; -match and Select-String -Pattern use regex. Get-ChildItem -Filter uses a provider-specific filter, not regex; for the FileSystem provider, simple patterns such as *.log are useful.

Meaning Wildcard with -like Regex with -match
Any sequence of characters in a single-line string * .*
Any one character in a single-line string ? .
A literal dot . \.
Exactly three ASCII digits [0-9][0-9][0-9] [0-9]{3}
Require the whole string to match Built into -like Add ^ and $ for these examples.

In regex, * repeats the preceding element zero or more times. For example, log* means lo followed by zero or more g characters. It does not mean "starts with log". An unanchored regex can match part of a longer string.

'report.log' -like '*.log'
'report.log' -match '\.log$'
'lo' -like 'log*'
'lo' -match 'log*'

Expected output:

True
True
False
True

Example: select reports, then check their filename format

A support team keeps dated reports and informal notes in the same folder. Use these sample names to compare the two requirements without creating files.

$reportNames = @(
    'report-2026-10-16.log'
    'report-notes.log'
    'report-2026-1.log'
    'old-report-2026-10-16.log'
    'report-2026-10-16.log.bak'
)

$reportNames | Where-Object { $_ -like 'report-*.log' }

The wildcard selects three names:

report-2026-10-16.log
report-notes.log
report-2026-1.log

Now require four digits, a hyphen, two digits, a hyphen, and two digits in the date position. Run this in the same session after creating $reportNames.

$reportNames | Where-Object {
    $_ -match '^report-[0-9]{4}-[0-9]{2}-[0-9]{2}\.log$'
}

Only report-2026-10-16.log matches. The anchors reject extra text at either end, and \. requires a literal dot before log. This checks the date's shape; it does not prove that the date exists. For calendar validation, use date parsing as well.

Both approaches can be combined: select files by name with Get-ChildItem -Filter '*.log', then search their contents with Select-String -Pattern. The hands-on uses this workflow in Activity 4.3. Prefer existing object properties when available; use regex to interpret text that needs parsing.

Regex Summary

  • Character: All characters, except those having special meaning in regex, matches themselves.

    • E.g., the regex x matches substring "x"; regex 9 matches "9"; regex = matches "="; and regex @ matches "@".

  • Special Regex Characters: These characters have special meaning in regex (to be discussed below): ., +, *, ?, ^, $, (, ), [, ], {, }, |, \.

  • Escape Sequences (\char): To match a character with special meaning in a regex, prefix it with a backslash (\).

    • E.g., \. matches "."; regex \+ matches "+"; and regex \( matches "(".
    • Use \\ to match a literal backslash.
    • Common regex escapes include \n (newline), \t (tab), and \r (carriage return). In PowerShell, the backslash is not the string escape character; PowerShell uses the backtick, so single-quoted regex patterns are often easiest.

  • A Sequence of Characters (or String): Strings can be matched via combining a sequence of characters (called sub-expressions).

    • E.g., the regex Saturday matches "Saturday".
    • Regex itself is case-sensitive by default. PowerShell's -match, -replace, -split, and Select-String are case-insensitive by default; use -cmatch, -creplace, -csplit, or Select-String -CaseSensitive for case-sensitive matching.

  • OR Operator (|): E.g., the regex four|4 matches either "four" or "4" (as a substring unless anchored).

  • Character class (or Bracket List):

    • [...]: matches any one character in the set, e.g., [aeiou] matches one of "a", "e", "i", "o", or "u".
    • A hyphen between endpoints defines a range, e.g., [0-9] matches an ASCII digit and [A-Za-z] matches an ASCII English letter.
    • ^, -, ], and \ may need escaping inside a character class, depending on their position.

  • Occurrence Indicators (or Repetition Operators):

    • +: one or more (1+), e.g., [0-9]+ matches one or more digits such as '123', '000'.
    • *: zero or more (0+), e.g., [0-9]* matches zero or more digits. It accepts all those in [0-9]+ plus the empty string.
    • ?: zero or one (optional), e.g., [+-]? matches an optional "+", "-", or an empty string.
    • {m,n}: m to n (both inclusive)
    • {m}: exactly m times
    • {m,}: m or more (m+)

  • Metacharacters: matches a character

    • .(dot): ANY ONE character except newline. Same as [^\n]
    • \d, \D: ANY ONE decimal digit/non-digit character. In .NET regex, \d includes Unicode decimal digits; use [0-9] for ASCII digits.
    • \w, \W: ANY ONE word/non-word character. In .NET regex, \w includes Unicode letters, combining marks, decimal digits, and connector punctuation (including underscore); for ASCII word characters use [a-zA-Z0-9_].
    • \s, \S: ANY ONE whitespace/non-whitespace character. \s includes Unicode whitespace; common ASCII whitespace characters are space, \n, \r, \t, and \f.

  • Position Anchors: match positions rather than characters, such as the start or end of a string or a word.

    • ^ matches the start of the input string. $ matches its end or the position before a final \n; in multiline mode, both match line boundaries.
      • E.g., ^[0-9] matches a digit at the start of the input.
      • E.g., [0-9]$ matches a digit at the end of the input.
    • \b: boundary of word, i.e., start-of-word or end-of-word.
      • E.g., \bcat\b matches the word "cat" in the input string.
    • \B: matches a position that is not a word boundary.

  • Parenthesized Capture Groups:

    • Use parentheses ( ) to capture groups in your regular expressions. These allow you to extract specific parts of a matched string.

Select-String

The Select-String cmdlet searches text and files for regular-expression matches. It is case-insensitive by default; use -CaseSensitive to make matching case-sensitive.

Get-Content text.txt | Select-String "pattern"

"The 1ste place, the 2nd place" | Select-String -Pattern '\d{1,3}' -AllMatches

Match operator

-match Operator:

You can use the -match operator to check if a string matches a regular expression:

$string = 'The quick brown fox jumped over the lazy dog'

$string -cmatch 'fix'
$string -cmatch 'fox'

# In regex, . matches one character (except a newline).
$string -cmatch 'f.x'

# Use ( ) for group and | for or
'John Savill' -cmatch 'Jo(n|hn)'
'Jon Savill' -cmatch 'Jo(n|hn)'
'Joh Savill' -cmatch 'Jo(n|hn)'
'Joh Savill' -cmatch 'Jo[n|hn]' # The class includes h, so this matches 'Joh'.

# ^ matches NOT in the group
$string -cmatch 'f[^xyz]x'

# ^ (caret) means the start of the string. A type of anchor
$string -cmatch '^fox'
$string -cmatch '^The'

# $ means the end of the string
$string -cmatch 'fox$'
$string -cmatch 'dog$'

# I want what is tested to ONLY be John or Jon. Combine with the ^ and $ (start and end)
'John' -cmatch '^Jo(n|hn)$'
'Jon' -cmatch '^Jo(n|hn)$'
'John Savill' -cmatch '^Jo(n|hn)$'

# can use a range in this case any lower case character
$string -cmatch 'f[a-z]x'

# or multiple
$string -cmatch 'f[a-z][a-z]'

# can or with | multiple character groups
'fOx' -cmatch 'f[a-z]x'
'fOx' -cmatch '^f([a-z]|[A-Z])x$'
'f0x' -cmatch '^f([a-z]|[A-Z]|[0-9])x$'

# this also works as its multiple ranges within a single character group
'fix' -cmatch '^f[a-zA-Z0-9]x$'

# \w for any word character, i.e. [a-zA-Z0-9_] includes underscore
'f0x' -cmatch 'f\wx'
$string -cmatch 'f\wx'

# I may only want to match the whole word
'the aforementioned word' -cmatch 'for' #grr
# \b to the rescue for whole word only
'the aforementioned word' -cmatch '\bfor\b'
'the for word' -cmatch '\bfor\b'

#Can still use other things with this
'the for word' -cmatch '\bf.r\b'

# + is one or more therefore .+ is one or more any characters between start with The and end with dog
$string -cmatch '^The.+dog$'
'test ending in dog' -cmatch '^The.+dog$'
'abcdefg' -cmatch '^a.+g$'

# * (asterisk) means zero or more
'abcdefg' -cmatch '^a.*g$'
'ag' -cmatch '^a.*g$'
'ag' -cmatch '^a.+g$' # + is one or more remember
'acg' -cmatch '^a.+g$'

# ? means 0 or 1
'ag' -cmatch '^a.?g$'
'acg' -cmatch '^a.?g$'
'abcdefg' -cmatch '^a.?g$'

# Can quantify with {number} or {min,} or {min,max}
'abcdefg' -cmatch '^a.{5}g$'
'abcdefhig' -cmatch '^a.{5}g$'

'abcdefg' -cmatch '^a.{3,}g$'
'abcg' -cmatch '^a.{3,}g$'

'abcdefg' -cmatch '^a.{0,5}g$'
'abcdefhig' -cmatch '^a.{0,5}g$'

'abcdefg' -cmatch '^a.{3,5}g$'
'abcdefhig' -cmatch '^a.{3,5}g$'
'abcg' -cmatch '^a.{3,5}g$'

# \d for a digit
'123-45-6789' -cmatch '^\d\d\d-\d\d-\d\d\d\d$'
'123-455-6789' -cmatch '^\d\d\d-\d\d-\d\d\d\d$'
'123-45-67f9' -cmatch '^\d\d\d-\d\d-\d\d\d\d$'

# Use our quantifier
'123-45-6789' -cmatch '^\d{3}-\d{2}-\d{4}$'
'1235-45-6789' -cmatch '^\d{3}-\d{2}-\d{4}$'

$text = "Hello, 123"
if ($text -match "^\w+, \d+$") {
    Write-Host "Matched"
}

replace operator

-replace Operator:

The -replace operator allows you to perform substitutions based on regular expressions:

$text = "The quick brown fox jumps over the lazy dog"
$modifiedText = $text -replace "fox", "cat"

'putting a SSN 123-45-67892 in here and 000-54-6234 as well' -replace '\b\d{3}-\d{2}-\d{4}\b','666-66-6666'

split operator

-split Operator:

You can split a string into an array using the -split operator and specify a regular expression as the delimiter:

$text = "one,two,three,four"
$array = $text -split ","

RegularExpressions.Regex Class

[System.Text.RegularExpressions.Regex] Class:

You can use the [System.Text.RegularExpressions.Regex] class to create regular expression objects and perform advanced regex operations in PowerShell:

$pattern = [System.Text.RegularExpressions.Regex]::new('\d{3}-\d{2}-\d{4}')
$matches = $pattern.Matches("123-45-6789 Hello 123-45-9999")

Matches

After a successful scalar -match, PowerShell stores the full match at $Matches[0] and captured groups at numeric and (for named groups) named keys.

'123-45-6789' -cmatch '(\d{3})-(\d{2})-(\d{4})'
$Matches[0]

$hits = '123-45-6789 555-45-6789' | Select-String -Pattern '(\d{3})-(\d{2})-(\d{4})' -AllMatches

$hits.Matches

First, match the domain and user without capture groups. The match succeeds, but $Matches contains only key 0, the full matched text.

$string = 'The last logged on user was CONTOSO.COM\jsmith'
$string -match 'was [\w.-]+\\[\w.-]+'
$Matches

Expected output:

True

Name                           Value
----                           -----
0                              was CONTOSO.COM\jsmith

To extract the domain and user separately, add named capture groups with (?<name>pattern). Each name becomes a key in $Matches.

$string = 'The last logged on user was CONTOSO.COM\jsmith'
$string -match 'was (?<domain>[\w.-]+)\\(?<user>[\w.-]+)'

$Matches

Write-Output "`nDomain name:"
$Matches.domain

Write-Output "`nUser name:"
$Matches.user

Expected output (the order of the $Matches entries can vary):

True

Name                           Value
----                           -----
user                           jsmith
domain                         CONTOSO.COM
0                              was CONTOSO.COM\jsmith

Domain name:
CONTOSO.COM

User name:
jsmith

Practice and self-check

  1. When would -like 'report-*.log' be sufficient for a support script?
Show solution

When the requirement is simple name selection: select names beginning with report- and ending in .log, with any intervening text. No date validation or field extraction is required.

  1. Why does that wildcard also select report-notes.log?
Show solution

The * wildcard permits any sequence of characters, including notes. It does not require digits or a date-shaped segment.

  1. How does regex help when you need a date-shaped filename or separate values from a log line?
Show solution

Regex can specify positions, character classes, and repetition counts to check a shape. Capture groups extract matched fields, such as a domain and username, into separate values for later processing.

  1. Why does 'lo' -match 'log*' return True?
Show solution

In regex, * repeats only the preceding token. g* permits zero g characters, so lo matches. The pattern is also unanchored; it need not cover the complete input.

  1. Does a filename matching [0-9]{4}-[0-9]{2}-[0-9]{2} prove its date exists?
Show solution

No. The pattern checks a digit-and-hyphen shape and, without anchors, can match part of a filename. Even an anchored shape permits impossible dates such as 2026-02-31. Validate a captured value as a calendar date separately.

Summary

Use exact comparison for a known value and wildcards for simple name selection. Use regex when text needs structural checks, extraction, or selective replacement. Select the pattern language supported by the operator or parameter, and test both matching and rejected inputs.
