Hands-on — Loops

10 - Loops

Originele pagina openen →

Goal

Repeat work predictably with bounded loops and choose the loop type that best fits the data or condition.

Learning objectives

By the end of this lab, you can:

  • use for, while, do while, and do until loops;
  • iterate collections with foreach and ForEach-Object;
  • prevent off-by-one and non-terminating loops; and
  • control iteration with break and continue.

Prerequisites

  • Complete Loops before starting this lab.
  • Complete 09 — Conditionals.
  • Understand arrays and Boolean conditions.

How to work in this lab

Predict the number and order of outputs before running each bounded example.

After attempting each activity, open Show solution to check your commands, expected results, and explanations. The final exercise and self-check also have solutions. Keep the session and setup required by the activity. If you already changed a file or variable, compare its result rather than replaying the change from the solution.

Part 1 — Repeat a known number of times

Activity 1.1 — Use a for loop

for ($index = 1; $index -le 5; $index++) {
    "Iteration $index"
}

Reflect

  1. Identify initializer, condition, and iterator.
  2. How many times does the body run?
  3. What value makes the condition false?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Expected results and reflection answers:

Initializer is $index = 1, condition $index -le 5, iterator $index++. It runs five times; after incrementing to 6, the condition is false.

Activity 1.2 — Index an array safely

$servers = @('SRV-01', 'SRV-02', 'SRV-03')

for ($index = 0; $index -lt $servers.Count; $index++) {
    [pscustomobject]@{
        Index  = $index
        Server = $servers[$index]
    }
}

Reflect

  1. Why does the loop begin at zero?
  2. Why use -lt $servers.Count instead of -le?
  3. What is an off-by-one error?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Expected results and reflection answers:

Arrays begin at index 0. Valid indexes are 0 through Count - 1, so the test must be -lt Count. Using -le Count attempts one index beyond the end.

The objects pair indexes 0, 1, and 2 with SRV-01, SRV-02, and SRV-03. An off-by-one error includes one too many or too few iterations.

Part 2 — Repeat while a condition changes

Activity 2.1 — Use while

$remainingAttempts = 3

while ($remainingAttempts -gt 0) {
    "Attempts remaining: $remainingAttempts"
    $remainingAttempts--
}

Reflect

  1. When is the condition checked?
  2. Which statement guarantees progress toward stopping?
  3. What would happen without the decrement?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Expected results and reflection answers:

while checks before every iteration. $remainingAttempts-- guarantees progress. Without it, the condition remains true and the loop does not terminate.

The messages show attempts remaining 3, 2, and 1; the final value is 0.

Activity 2.2 — Compare while and do while

$counter = 5

while ($counter -lt 3) {
    'while body ran'
}

do {
    'do-while body ran'
} while ($counter -lt 3)

Reflect

  1. Which body runs at least once?
  2. Why does the ordinary while body not run?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Expected results and reflection answers:

The ordinary while runs zero times because 5 is not less than 3. do while runs once before checking.

Part 5 — Challenge: process a ticket queue

Filename: Get-TicketQueue.ps1

Save the supplied data and your challenge commands in this file. Run . .\Get-TicketQueue.ps1 in your lab session.

Use:

$tickets = @(
    [pscustomobject]@{ Id = 201; Status = 'Open';   Minutes = 15 }
    [pscustomobject]@{ Id = 202; Status = 'Closed'; Minutes = 20 }
    [pscustomobject]@{ Id = 203; Status = 'Open';   Minutes = 45 }
    [pscustomobject]@{ Id = 204; Status = 'Blocked'; Minutes = 30 }
    [pscustomobject]@{ Id = 205; Status = 'Open';   Minutes = 25 }
)

Create $processedTickets with a foreach loop:

  • skip closed tickets with continue;
  • stop processing when a blocked ticket is reached;
  • for every processed ticket, output an object with Id, Minutes, and Sequence;
  • increment Sequence only for processed tickets; and
  • calculate the total minutes after the loop.

Explain why tickets after the blocked item are not processed.

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Use the challenge's supplied input objects in the same session.

Queue-processing solution (Beginner):

$sequence = 0

$processedTickets = foreach ($ticket in $tickets) {
    if ($ticket.Status -eq 'Closed') {
        continue
    }

    if ($ticket.Status -eq 'Blocked') {
        break
    }

    $sequence++

    [pscustomobject]@{
        Id       = $ticket.Id
        Minutes  = $ticket.Minutes
        Sequence = $sequence
    }
}

$totalMinutes = ($processedTickets | Measure-Object Minutes -Sum).Sum
$processedTickets
$totalMinutes

Tickets 201 and 203 are processed with sequences 1 and 2. Ticket 202 is skipped. Ticket 204 ends the loop, so 205 is never reached. Total minutes are 60.

Show solution Optimized

Use the challenge's supplied input objects in the same session.

Queue-processing solution (Optimized):

$processedTickets = foreach ($ticket in $tickets) {
    if ($ticket.Status -eq 'Blocked') {
        break
    }
    if ($ticket.Status -ne 'Closed') {
        $ticket
    }
} | ForEach-Object -Begin { $sequence = 0 } -Process {
    $sequence++
    [pscustomobject]@{
        Id       = $_.Id
        Minutes  = $_.Minutes
        Sequence = $sequence
    }
}

$totalMinutes = ($processedTickets | Measure-Object -Property Minutes -Sum).Sum
$processedTickets
$totalMinutes

The optimized version combines the ticket filtering in the first loop and uses ForEach-Object with -Begin and -Process blocks for cleaner sequence tracking. Both produce the same result: tickets 201 and 203 with sequences 1 and 2, total minutes of 60.

Self-check answers:

Question Answer
for Known count or index-controlled repetition.
Condition progress Prevents a non-terminating loop.
Always once A do loop.
foreach / ForEach-Object Language loop over a collection versus pipeline cmdlet.
break / continue Exit loop versus skip current iteration.
Array bound Use index < Count.

Summary

Choose loops based on whether repetition follows a count, condition, collection, or pipeline. Every condition-controlled loop needs a clear path to termination.
