PowerShell setup

01 - PowerShell setup

Originele pagina openen →

Learning objectives

After completing this guide, you can:

  • check which PowerShell version you are running;
  • install PowerShell 7 on a Windows computer; and
  • use a safe, temporary execution-policy setting for a lab session.

Prerequisites

  • A Windows computer.
  • Permission to install software, or access to your institution's software portal.

Why use PowerShell?

PowerShell is the automation language used throughout this course. It lets you run commands, work with structured data, and combine repeatable steps into scripts. PowerShell 7 is the current cross-platform version and is the version used in the examples and hands-on exercises.

Check the installed version

Open PowerShell and run:

$PSVersionTable.PSVersion

For this course, use PowerShell 7 or later. Start it with pwsh. Windows PowerShell 5.1 can remain installed alongside PowerShell 7; it is a separate application.

Option 1: Install PowerShell 7 with WinGet

Open a terminal with administrator privileges.

Use the method approved by your institution. On a personal Windows computer, WinGet is Microsoft's recommended method:

winget search Powershell

winget search --id Microsoft.PowerShell

Find the latest stable version in the output, then install it with:

winget install --id Microsoft.PowerShell --source winget --installer-type wix

(To force the MSI version rather than the store package, append --installer-type wix). This installation type is recommended for enterprise features, custom administrative configurations, and full system integration.

PowerShell 7: MSI (WIX) vs. Microsoft Store (MSIX)

Feature / Aspect MSI Package (WIX) Microsoft Store (MSIX)
Installation Scope Machine-wide (C:\Program Files\PowerShell\7) or per-user Current user only (%LOCALAPPDATA%\Microsoft\WindowsApps)
Updates Via Microsoft Update (opt-in), winget, or manual MSI Automatic via Microsoft Store background updates
Inbound PSRemoting (WinRM) Supported; can register endpoints Not supported (blocked by sandbox isolation)
System-Level Changes ($PSHOME) Fully supported (with administrator elevation) Read-only; cannot modify system configurations
AllUsers Cmdlets Fully supported (Update-Help -Scope AllUsers, etc.) Blocked (Update-Help, machine-scoped policies)
Shell Integration Adds File Explorer context menus & event log manifests Limited; launches through App Execution Alias
Secondary User Invocation Can be executed via runas or by service accounts Difficult to run under alternative credentials due to AppX/MSIX identity

Close and reopen your terminal, then confirm the installation:

pwsh

$PSVersionTable.PSVersion

If WinGet is unavailable, use the official PowerShell installation guide. Do not install preview versions for this course unless your instructor asks you to.

Option 2 - Installing PowerShell 7 on Windows: MSI Installer Method

The standard .msi package is the best choice for enterprise features, custom administrative configurations, and full system integration.

Key Technical Limitations of the Store Version

  1. No Inbound Remoting (WinRM)
    Because the Store package cannot write to $PSHOME or alter WSMAN system configurations, other machines cannot use PowerShell Remoting to connect to your system. Outbound connections (remoting to other servers via SSH or WinRM) still work.

  2. Blocked System-Level Commands
    Any cmdlet attempting to write to the installation root or machine-wide settings will fail with access errors:

    • Set-ExecutionPolicy -Scope LocalMachine
    • Update-Help -Scope AllUsers
    • Register-PSSessionConfiguration
    • Enable-ExperimentalFeature -Scope AllUsers

  3. Isolated File & Execution Context
    The Store app runs via an App Execution Alias (pwsh.exe). Automated scheduled tasks, service accounts, or legacy scripts that expect a standard C:\Program Files\... path can experience permission or path resolution issues.

Recommendation

  • Choose the MSI version for systems administration, IT automation, infrastructure-as-code, module development for wider deployment, or multi-user availability.
  • Choose the Store version only for casual scripting, personal CLI usage, or on restricted corporate machines where you lack local admin privileges to install MSI packages.

Why Choose the MSI Installer?

Unlike the Microsoft Store package, the MSI package provides:

  • Machine-wide installation support (C:\Program Files\PowerShell\7).
  • Full support for inbound PowerShell Remoting (WinRM).
  • Integration with Windows Update (Microsoft Update).
  • Custom Explorer context menu integration and event logging manifests.

Step-by-Step Installation Instructions

1. Download the Installer

  1. Navigate to the official PowerShell GitHub Releases page.
  2. Scroll to the Assets section of the latest stable release.
  3. Download the appropriate 64-bit installer file:
    • PowerShell-<version>-win-x64.msi

2. Run the Installer

  1. Double-click the downloaded .msi file to launch the setup wizard.
  2. Accept the licensing agreement and select the destination directory (defaults to C:\Program Files\PowerShell\7\).

3. Configure Optional Actions

During the installation wizard, you will reach the Optional Actions screen. It is recommended to check the following:

  • Add PowerShell to PATH Environment Variable (Recommended)
    Allows launching PowerShell 7 via pwsh from any command prompt or terminal.
  • Register Windows Event Logging Manifest
    Enables structured event logging for audit and diagnostic purposes.
  • Enable PowerShell Remoting (PSRemoting)
    Allows remote management sessions via WinRM.
  • Add 'Open here' Context Menus to File Explorer
    Adds quick-launch options for PowerShell 7 directly in folder context menus.
  • Enable PowerShell Run in Windows Explorer Context Menu
    Allows running .ps1 files directly via PowerShell 7 with a right-click.

4. Configure Update Preferences

On the Microsoft Update Settings screen:

  • Check Use Microsoft Update when I check for updates to ensure PowerShell 7 receives automated updates alongside standard Windows security patches.

5. Complete Setup

  1. Click Install and approve the User Account Control (UAC) prompt.
  2. Click Finish once setup completes.

Verification

Open your terminal or Windows Run dialog (Win + R) and run:

pwsh

To confirm the installed version inside the prompt:

$PSVersionTable.PSVersion

Use a temporary execution policy for lab work

Organisational policy always takes precedence. If scripts are blocked during a personal lab session, set the policy only for the current PowerShell process:

Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned

This setting is removed when you close that PowerShell window. Run only scripts that you trust and understand.

To update it in the future

winget upgrade --id Microsoft.PowerShell

Practice

  1. Start PowerShell 7 with pwsh.
  2. Run $PSVersionTable.PSVersion and record the major version.
  3. Close the window and reopen PowerShell 7.

To uninstall PowerShell 7

  1. Open Settings > Apps > Apps & features.
  2. Search for "PowerShell" and select the installed version.
  3. Click Uninstall and follow the prompts.

or with WinGet:

winget uninstall --id Microsoft.PowerShell

Summary

PowerShell 7 is the course runtime and runs beside Windows PowerShell 5.1. Use pwsh to open it, and prefer a process-scoped execution-policy change when a lab requires one.
