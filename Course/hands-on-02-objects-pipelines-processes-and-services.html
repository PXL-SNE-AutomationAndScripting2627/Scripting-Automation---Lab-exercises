Hands-on — Objects, pipelines, processes, and services

02 - Objects, pipelines, processes, and services

Originele pagina openen →

Goal

Explore how PowerShell returns objects, how a pipeline passes those objects between commands, and how to inspect processes and services without changing the computer.

Learning objectives

By the end of this lab, you can:

  • distinguish an object, a property, and a method;
  • use Get-Member to inspect an object's members;
  • select and filter objects in a pipeline; and
  • query your own process and Windows services safely.

Prerequisites

  • Complete Objects, pipelines, processes, and services before starting this lab.
  • Complete Windows processes before starting this lab.
  • Complete 01 — Intro, Cmdlets, help, and commands
  • Use PowerShell 7 where available.
  • Work only with the read-only commands shown in this lab. Do not start, stop, or restart a process or service.

How to work in this lab

For every activity, complete the three steps.

  1. Predict: write or discuss what you think will happen.
  2. Run: enter the command exactly as shown.
  3. Reflect: answer the questions in your own words.

After attempting each activity, open Show solution to check your commands, expected results, and explanations. The final exercise and self-check also have solutions. Keep the session and setup required by the activity. If you already changed a file or variable, compare its result rather than replaying the change from the solution.

Part 1 — Objects, properties, and methods

Activity 1.1 — Inspect an object

Predict

Does Get-Date return only text, or does it return an object with data and actions?

Run

Get-Date | Get-Member

Reflect

  1. What type is shown near the top of the output?
  2. Find one property and one method.
  3. In your own words, what is the difference between a property and a method?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Expected results and explanation:

Get-Date returns a System.DateTime object. Properties include DayOfWeek, Year, and Date. Methods include ToShortDateString() and AddDays(). A property is data held by an object; a method is an action that the object can perform.

Activity 1.2 — Read a property with dot notation

Run

$today = Get-Date
$today.DayOfWeek
$today.ToShortDateString()

Reflect

  1. Which line reads a property?
  2. Which line calls a method? How can you recognise it?
  3. Why might storing the date in $today be useful?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Expected results and explanation:

$today.DayOfWeek reads a property. $today.ToShortDateString() calls a method; parentheses identify a method call. Storing the value in $today lets a script reuse the same date object instead of collecting a new value repeatedly.

Activity 1.3 — Select only the data you need

Run

Get-Date | Select-Object DateTime, DayOfWeek, Year

Reflect

  1. Which properties are shown?
  2. Does Select-Object change the original date object? Explain your answer.

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Expected results and explanation:

The selected output has DateTime, DayOfWeek, and Year. Select-Object creates new objects containing the requested properties; it does not modify the original DateTime object. The selected objects omit other date members, so keep the original object when later commands need them.

Part 2 — Follow objects through a pipeline

Activity 2.1 — Start with simple values

Predict

What do you expect each command to send to the next command in the pipeline?

Run

1..5 | Measure-Object
1..5 | Where-Object { $_ -gt 3 }

Reflect

  1. What does Measure-Object report?
  2. Which values pass through the Where-Object filter?
  3. What does $_ represent inside the braces?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Expected results and explanation:

Measure-Object reports a count of five values. The filter passes 4 and 5. Inside the braces, $_ is the current pipeline object, so each number is compared with 3 in turn.

Activity 2.2 — Use a pipeline with process objects

Run

Get-Process -Id $PID | Select-Object ProcessName, Id, CPU, WorkingSet

$PID is the identifier of the current PowerShell process, so this command does not require you to choose another process.

Reflect

  1. Which process is displayed?
  2. Which property could identify this exact process?
  3. Why is ProcessName alone not always enough to identify a process?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Expected results and explanation:

This displays the current PowerShell host process, normally named pwsh or powershell. Id identifies that particular running process. Several process instances can share the same ProcessName, so use Id when an exact instance matters.

The process ID is $PID. Its CPU time and memory use vary as the process runs.

Activity 2.3 — Filter before selecting

Run

Get-Process |
    Where-Object ProcessName -like 'p*' |
    Select-Object -First 5 ProcessName, Id

Reflect

  1. In what order do the three pipeline commands run?
  2. What does the wildcard * mean in 'p*'?
  3. Why is it useful to filter before selecting or exporting data?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Expected results and explanation:

Get-Process produces process objects, Where-Object keeps those whose names begin with p, and Select-Object keeps the first five and shows two properties. * matches zero or more characters. Filtering early reduces the number of objects that later stages must process or export.

Part 3 — Processes and services

Activity 3.1 — Compare a process and a service

Predict and discuss

Which statement best describes a service?

  • A. A document saved on disk.
  • B. A background component that can run without a signed-in user.
  • C. A replacement name for every process.

Run

Get-Process -Id $PID | Get-Member
Get-Service | Select-Object -First 1 | Get-Member

Reflect

  1. What object type is returned by Get-Process?
  2. What object type is returned by Get-Service?
  3. Give one reason or example that a service might be running when no user is signed in.

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Expected results and explanation:

The process is normally a System.Diagnostics.Process object. Get-Service returns System.ServiceProcess.ServiceController objects. The correct statement is B: a service is a background component that can run without a signed-in user, for example to provide networking, logging, or time synchronisation.

Activity 3.2 — Query services safely

Run

Get-Service |
    Where-Object Status -eq 'Running' |
    Select-Object -First 10 Name, DisplayName, Status

Reflect

  1. What does Status -eq 'Running' test?
  2. Why are both Name and DisplayName useful?
  3. Does this command make any change to a service? How do you know?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Expected results and explanation:

Status -eq 'Running' keeps only service objects whose Status property equals Running. Name is a stable service identifier used by commands; DisplayName is a human-friendly name. All commands begin with Get, Where, or Select, so this pipeline reads and presents data without changing a service.

Activity 3.3 — Find out what a command accepts

Run

(Get-Command Get-Service).Parameters["Name"].Attributes
(Get-Command Get-Process).Parameters["Name"].Attributes

Reflect

  1. Does the Name parameter of each command accept pipeline input? Record what the help shows.
  2. Why should you check help before assuming that a pipeline will work?

Normally you can use Get-Help Get-Service -Parameter Name and Get-Help Get-Process -Parameter Name to check the help for each command. But the help information is not always up to date, so the Get-Command approach is more reliable.

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Pipeline-binding answers:

Inspect the installed commands' ParameterAttribute records. For Name, Get-Service accepts pipeline input by value and by property name. Get-Process accepts it by property name, not by value. The metadata shows ValueFromPipeline and ValueFromPipelineByPropertyName separately.

Commands with similarly named parameters can have different binding rules. Use help to understand their meaning and installed command metadata to check their capabilities; do not assume that a string pipeline works for both.

Part 4 — Challenge: build a safe status view

Filename: Get-ProcessStatus.ps1

Save the pipeline in your lab folder and run .\Get-ProcessStatus.ps1.

Scenario

An instructor wants a quick, read-only view of the PowerShell process that runs the lab. The view should show the process name, its identifier, and its current CPU time.

Your task

Write a one-line pipeline that:

  1. starts with the current PowerShell process using $PID;
  2. selects ProcessName, Id, and CPU; and
  3. does not start, stop, or modify any process.

Then explain what every pipeline stage does and why the command is safe.

Suggested starting point

# Write your pipeline here.

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Status-view solution (Beginner):

One valid solution:

Get-Process -Id $PID | Select-Object ProcessName, Id, CPU

Get-Process -Id $PID retrieves only the current PowerShell process. The pipe passes that process object to Select-Object, which displays the requested properties. Neither command changes the process, so the pipeline is safe to run in this lab.

The process is the current PowerShell host. Its ID, CPU time, and process name depend on the running session.

Show solution Optimized

Status-view solution (Optimized):

Get-Process -Id $PID -OutVariable psProcess | Select-Object ProcessName, Id, CPU
$psProcess

Or, using a more compact approach:

Get-Process -Id $PID | Select-Object -Property ProcessName, Id, CPU

The optimized version stores the process object in -OutVariable for reuse, or uses the explicit -Property parameter name for clarity. Both maintain the same pipeline flow and safety: no modifications occur. The one-liner remains the most direct solution.

  2. What is the difference between $today.DayOfWeek and $today.ToShortDateString()?
  3. What does $_ mean inside Where-Object?
  4. Which property uniquely identifies a running process during its lifetime?
  5. What is the difference between a process and a service?
  6. Why is a read-only query safer than Stop-Process or Stop-Service in a beginner lab?

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Self-check answers:

Question Detailed solution
Which cmdlet shows an object's properties and methods? Get-Member
Difference between $today.DayOfWeek and $today.ToShortDateString()? The first reads a property; the second calls a method.
What does $_ mean in Where-Object? The current object entering that pipeline stage.
Which property uniquely identifies a process during its lifetime? Id
Difference between a process and a service? A process is a running program instance; a service is a managed background component that can run without a signed-in user.
Why are read-only queries safer here? They inspect data without stopping, starting, or otherwise disrupting a process or service.

Summary

PowerShell sends objects through the pipeline, not just formatted text. Use Get-Member to inspect objects, select the properties you need, and filter data before presenting it. Processes and services can be queried safely; changing them requires a separate, deliberate decision.
