Conditionals

10 - Conditionals

Originele pagina openen →

Learning objectives

By the end of this chapter, you can:

  • use comparisons to produce Boolean decisions;
  • choose between if, elseif, else, and switch;
  • combine conditions with -and, -or, and -not;
  • distinguish null, empty text, and a supplied parameter;
  • inspect a path before choosing a file operation; and
  • explain first-match behaviour and multiple matching switch cases.

Prerequisites

  • Complete the variables lesson and parameters lesson.
  • Understand Boolean values, named properties, and basic pipelines.
  • Use PowerShell 7 on your Windows lab computer.

Why conditions matter

A backup report should not announce success just because a folder exists. It may also need a recent verification and enough free space. Conditions turn these rules into explicit decisions whose inputs and results you can inspect.

The examples below read values or change session variables. The path example only inspects C:\powershell. Your instructor must prepare that base folder before class; no administrator rights are needed for these checks. Use the matching lab to apply the ideas to a separate device-readiness task.

Start with a comparison and one decision

A condition is an expression that PowerShell interprets as true or false. A comparison produces a Boolean value for scalar inputs:

$availableGB = 12
$availableGB -ge 20

The result is False because 12 is not at least 20.

An if statement runs its body only when the condition is true. An else body handles the false case:

flowchart TD
    A{"availableGB at least 20?"} -- Yes --> B["Space check passed"]
    A -- No --> C["Review available space"]

if ($availableGB -ge 20) {
    'Space check passed.'
} else {
    'Review available space.'
}

The output is Review available space.. Parentheses contain the condition; braces contain the statements to run. Change the assignment above the statement when testing another input, then rerun the statement.

Comparison reference

Operator Meaning Example result
-eq Equal 12 -eq 12 is true
-ne Not equal 12 -ne 20 is true
-lt Less than 12 -lt 20 is true
-le Less than or equal 12 -le 12 is true
-gt Greater than 12 -gt 20 is false
-ge Greater than or equal 12 -ge 12 is true

Use = to assign and -eq to compare. An assignment inside a condition can change the value instead of checking it.

Store numeric values as numbers. If the left operand is text, comparisons can use text ordering or type conversion rather than the intended numeric rule. The conversion examples explain why the input type matters.

Order several outcomes with elseif

Use elseif when a later outcome should be tested only if earlier conditions were false:

$backupAgeHours = 30

if ($backupAgeHours -le 24) {
    $backupReview = 'Current'
} elseif ($backupAgeHours -le 48) {
    $backupReview = 'Review soon'
} else {
    $backupReview = 'Overdue'
}

$backupReview

The result is Review soon. The tests are evaluated in order. After a true condition, PowerShell runs that body and skips later branches. If no condition matches, else runs.

Put narrower ranges before broader ranges. If the 48 test came first, a value of 12 would be called Review soon even though it is current. Check boundary values: 24, 48, and 49.

Show solution

24 selects Current because it satisfies -le 24. 48 selects Review soon because the first test is false and -le 48 is true. 49 reaches Overdue because both earlier comparisons are false.

Nest decisions when a second test depends on the first

A nested if is useful when a second question only makes sense after the first one has been answered:

$backupAvailable = $true
$backupVerified = $false

if ($backupAvailable) {
    if ($backupVerified) {
        'Backup is available and verified.'
    } else {
        'Backup exists but still needs verification.'
    }
} else {
    'No backup is available.'
}

The middle message appears. Flatten related ranges with elseif when that is clearer; keep a nested decision when it represents a dependent check.

Combine conditions

Logical operators combine Boolean tests.

Operator Rule
-and Both conditions must be true.
-or At least one condition must be true.
-not or ! Reverse the Boolean value. 
$destinationAvailable = $true
$freeSpaceGB = 26

if ($destinationAvailable -and ($freeSpaceGB -ge 20)) {
    'Backup destination passes both checks.'
}

The message appears because both checks pass. Changing the space to 10 prevents it.

$backupOverdue = $false
$verificationFailed = $true

if ($backupOverdue -or $verificationFailed) {
    'A backup review is needed.'
}

$maintenanceActive = $false
if (-not $maintenanceActive) {
    'Normal scheduling can continue.'
}

Both messages appear. Parentheses make the intended grouping clearer when combining several tests. PowerShell short-circuits -and and -or: it skips the right side when the left side already determines the outcome.

Apply: Activities 2.1–2.3: combined conditions.

Distinguish missing values from valid false values

Null, empty text, and whitespace can require different handling:

$missingLabel = $null
$emptyLabel = ''
$blankLabel = '   '

$null -eq $missingLabel
$null -eq $emptyLabel
[string]::IsNullOrWhiteSpace($blankLabel)

The results are True, False, and True. IsNullOrWhiteSpace() accepts null, empty, and whitespace-only text as having no useful characters.

A truth test is broader than a null test

$retryCount = 0

if ($retryCount) {
    'The count is nonzero.'
} else {
    'The count is zero.'
}

The second message appears. 0 is a legitimate numeric value even though it evaluates as false. $false, '', and $null are also false in a condition. The nonempty strings 'False' and '0' are true; they are text, not Boolean or numeric values. Converting arbitrary text with [bool] does not interpret words such as 'False' as Boolean false.

Use a Boolean property directly when it already contains a Boolean. Use $null -eq $value to test absence, and an explicit comparison or text validation method for other rules. Scalar and collection comparisons differ: a collection on the left of -eq filters matching elements rather than necessarily returning one Boolean. Keep $null on the left for null tests.

Parameter presence is a separate question

A null value does not prove that the caller omitted an argument. The caller may explicitly supply null. A default can also produce a non-null value even when its argument was omitted.

Use $PSBoundParameters.ContainsKey('Name') inside a script or function when the question is whether the parameter was supplied. Use its variable's value when the question is what to do. In particular, test a switch's value for the feature decision; an explicitly false switch was supplied but is still disabled. See the parameter presence example for a complete script.

Check paths and object types

Test-Path checks existence and returns a Boolean for a single ordinary path. -PathType Container requires a directory; Leaf requires a file in the FileSystem provider.

$inspectionRoot = 'C:\powershell'

if (Test-Path -LiteralPath $inspectionRoot -PathType Container) {
    'The course base is a directory.'
} else {
    'Ask the instructor to prepare the course base.'
}

The first message appears after preparation. -LiteralPath treats the path as written instead of interpreting wildcard characters. Existence does not prove that a file contains correct data or that the account can write there.

The -is operator checks whether a value is compatible with a type; -isnot negates that test. These do not compare two objects for equality.

$observedValue = 20

$observedValue -is [int]
$observedValue -isnot [string]

Both results are True. For a file-system object, [System.IO.DirectoryInfo] identifies a directory and [System.IO.FileInfo] identifies a file.

Apply: Activity 3.2: read-only path decisions.

Match named cases with switch

Use switch when comparing one value with several named cases is clearer than a chain of comparisons.

$backupStage = 'Verified'

switch ($backupStage) {
    'Queued'   { 'Wait for processing.' }
    'Copied'   { 'Run verification.' }
    'Verified' { 'Prepare the handover.' }
    default    { 'Review the unknown stage.' }
}

The output is Prepare the handover.. default runs only when no case matches. Basic text matching is case-insensitive; use -CaseSensitive when case is significant.

Wildcards for simple name selection

$reportName = 'backup-summary.csv'

switch -Wildcard ($reportName) {
    '*.csv' { 'Use the tabular report reader.' }
    '*.json' { 'Use the JSON reader.' }
    default { 'Review the report format.' }
}

The first case matches. -Wildcard interprets each case as a wildcard pattern. Here * means zero or more characters. A normal switch treats '*.csv' as literal text instead.

Apply: Activities 4.1–4.2: exact and wildcard cases.

Advanced: more than one switch case can match

Unlike if/elseif, switch can execute several matching bodies for the same input:

$jobSize = 5

switch ($jobSize) {
    { $_ -gt 0 }  { 'Positive job size.' }
    { $_ -lt 10 } { 'Small job.' }
}

Both messages appear. A condition in braces is a script block that tests the current switch input, represented by $_.

To choose only the first matching case, use break:

switch ($jobSize) {
    { $_ -gt 0 }  { 'Positive job size.'; break }
    { $_ -lt 10 } { 'Small job.'; break }
}

Only Positive job size. appears. Case order now decides which result wins. When switch receives several input values, break exits the whole switch, not just processing of one value. Use continue to advance to the next switch input. The loops lesson develops these flow-control statements.

Regex cases

-Regex interprets case labels as regular expressions. Use it when checking structure or capturing a field rather than selecting a simple filename suffix.

$queueMessage = 'Queue: PRN-42'

switch -Regex -CaseSensitive ($queueMessage) {
    '^Queue: PRN-(?<Number>[0-9]{2})$' {
        "Queue number: $($Matches.Number)"
        break
    }
    default { 'The queue message has an unexpected format.' }
}

The result is Queue number: 42. Anchors require the complete shape, [0-9]{2} requires two digits, and the named capture supplies the number. Inspect $Matches inside the successful body before another match replaces it. The regex lesson explains the pattern syntax.

Quick operator reference

Need Operator
Scalar equality or ordering -eq, -ne, -lt, -le, -gt, -ge
Simple wildcard matching -like, -notlike
Regex matching -match, -notmatch
Collection membership -contains, -notcontains, -in, -notin
Type compatibility -is, -isnot
Combined Boolean conditions -and, -or, -not

For case-sensitive string comparisons, use forms such as -ceq, -clike, and -cmatch. Default string comparison forms are case-insensitive. -replace performs a regex replacement and returns text; it is not a Boolean comparison operator.

Show solution

For $jobSize = 5, removing the first matching break allows both Positive job size. and Small job. to appear because both conditions match. With break, only the first message appears. For several switch input values, break exits the entire switch.

Removing break from the queue-regex example adds no output with its current single matching case: default does not run after a successful match. It could matter if another matching case or further inputs were added.

Explain why matching a queue message with regex is a different task from selecting a file by its suffix.
Show solution

The queue regex checks the complete Queue: PRN-42 structure, requires two digits, and captures 42 as $Matches.Number. A wildcard such as *.csv selects a name ending in that suffix without extracting a field or checking the rest of its structure. Choose the pattern language for the requirement.

Summary

Comparisons turn scalar values into Boolean decisions. if/elseif/else chooses the first matching branch. Logical operators combine rules, while explicit null, text, path, and type checks make the intended test clear.

A switch can match multiple cases unless control flow stops it. Choose literal cases, wildcards, or regex according to the required check, and include a fallback for unexpected input. A supplied parameter and a true value are different facts.
