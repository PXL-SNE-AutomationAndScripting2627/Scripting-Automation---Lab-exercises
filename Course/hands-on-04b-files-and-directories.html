Hands-on 04b — Files and directories

04b - Files and directories

Originele pagina openen →

Goal

Prepare a classroom workstation handover while preserving source files. Build paths, inspect files, work on a copy, and verify the delivered folder.

Learning objectives

After completing this lab, you can:

  • resolve absolute, relative, wildcard, and literal paths;
  • create directories and inspect or search text files;
  • preview, copy, edit, move, rename, and remove exact practice files;
  • verify preservation and changes with file hashes;
  • search recursively and filter timestamps, sizes, and hidden attributes;
  • predict folder-copy layouts and batch rename targets; and
  • deliver a verified folder with a reusable CSV inventory.

Prerequisites

  • Complete the Files and directories lesson, including its advanced sections, before starting this lab.
  • Complete the output, formatting, and export lesson and hands-on 04.
  • Understand object properties, basic pipelines, filtering, and sorting.

Use the lessons for command explanations. This lab applies those concepts to a separate scenario and dataset.

Environment and safety requirements

Use PowerShell 7 on Windows with Visual Studio Code or Windows Terminal. Your instructor must first prepare C:\powershell with writable access. The commands then run with a normal user account.

Work only in a new C:\powershell\File-Directory-Lab folder. Preserve any existing attempt and choose a different child name. Inspect every preview's source and destination. The only deletion is the exact temporary file created in Activity 1.2. Keep the completed handover and sources for assessment.

How to work in this lab

Complete Parts 1 to 5 in order, including Advanced Part 4. All activities are required. Allow approximately 140–180 minutes, with a break after Part 3.

Follow predict → run → inspect → explain. Commands under Run supply setup or a starting example; write the missing task commands yourself. Use the same PowerShell session throughout: later parts reuse earlier path and hash variables. If the session closes, start a new attempt with a new root and complete the activities in order.

After attempting each task, open Show solution to compare commands, results, and explanations. Run supplied setup once. If you already made a file change, inspect the result instead of replaying it from the solution.

Part 1 — Prepare the handover workspace

Activity 1.1 — Choose and create a fresh workspace

A separate workspace makes every source and destination easy to check. Join-Path combines a parent path and a child name. A variable beginning with $ keeps that path for reuse.

Predict: should an unused workspace return True or False?

Run:

$labRoot = Join-Path -Path 'C:\powershell' -ChildPath 'File-Directory-Lab'
$labRoot
Test-Path -LiteralPath $labRoot

If the result is True, preserve that folder and choose a new child name before continuing. Do not reuse an earlier attempt.

Tasks:

  1. Create the root and three folders named source, draft, and handover.
  2. Store their paths in $sourceFolder, $draftFolder, and $handoverFolder.
  3. List the root's directories, sorted by name.

Reflect: why keep source files separate from edited copies?

Checkpoint: the root contains exactly the three empty folders.

Workspace solution:

$sourceFolder = Join-Path -Path $labRoot -ChildPath 'source'
$draftFolder = Join-Path -Path $labRoot -ChildPath 'draft'

Activity 1.2 — Create the supplied input files

The handover contains a client configuration, instructions, and a room note. Square brackets in the source filename are deliberate.

Predict: will Set-Content create a missing file inside an existing folder?

Run once:

$branchFolder = Join-Path -Path $sourceFolder -ChildPath 'branch-02'

Set-Content -LiteralPath $readmePath -Value 'Check the classroom client before handover.'
Set-Content -LiteralPath $branchNotePath -Value 'Use the teaching VLAN.'
New-Item -Path $scratchPath -ItemType File | Out-Null
Set-Content -LiteralPath $scratchPath -Value 'TEMPORARY HANDOVER BUILD NOTE'

Set-Content writes the supplied lines, replacing existing content. The comma supplies two strings for the configuration. New-Item with -ItemType File creates an empty file before the final command fills it.

Part 2 — Inspect paths, items, and content

Activity 2.1 — Resolve paths and preserve literal names

An absolute path identifies a location independently of the current folder. A relative path such as .\branch-02 starts from your current location. -LiteralPath treats characters such as [ and ] as part of the name.

Predict: will -Path and -LiteralPath find the same configuration here?

Run:

Set-Location -LiteralPath $sourceFolder
Get-Location
Test-Path -LiteralPath '.\branch-02' -PathType Container
Test-Path -LiteralPath $settingsPath -PathType Leaf
Test-Path -Path $settingsPath -PathType Leaf

Tasks:

  1. Inspect the configuration's Name, DirectoryName, and Length with Get-Item -LiteralPath and Select-Object.
  2. Return to $labRoot and test .\branch-02 again.

Reflect: what changed when you moved to the root? Why does a literal path matter even though the filename is stored in a variable?

Checkpoint: the absolute configuration path still works; the relative branch path no longer finds a folder at the root.

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Path solution:

Get-Item -LiteralPath $settingsPath |
    Select-Object Name, DirectoryName, Length
Set-Location -LiteralPath $labRoot
Test-Path -LiteralPath '.\branch-02' -PathType Container
Test-Path -LiteralPath $settingsPath -PathType Leaf

The supplied checks return True, True, and False in that order. With -Path, [lab] is a wildcard character set matching one character; it does not mean the literal text [lab]. A variable stores text but does not change how a cmdlet interprets it.

The task checks return False and True. The current directory changed, so the relative path now searches below the root. The absolute path still identifies source\client[lab].ini. Its length is positive; the exact byte count and absolute directory depend on the chosen workspace.

Activity 2.2 — Inspect items and search text

Get-Item inspects the named item. Get-ChildItem enumerates its children. A directory is an object too, but it is not a text file.

  2. List only its direct files, displaying Name and Length.
  3. List only its direct directories.
  4. Use Select-String -LiteralPath with -SimpleMatch to find Server= in the configuration.

-File and -Directory restrict the kind of child returned. -SimpleMatch searches for literal text rather than a regex pattern.

Reflect: which file is missing from the direct file listing, and why?

Checkpoint: two direct files, one direct directory, and one matching configuration line.

Get-ChildItem -LiteralPath $sourceFolder -Directory |

Its room-b.txt is one level deeper and requires recursion to appear in a file search. The matching configuration line is line 2: Server=training.example.invalid.

Part 3 — Change a working copy safely

Activity 3.1 — Preview a copy and edit only the copy

A file hash is a content fingerprint. Matching SHA256 hashes provide a useful check that copying preserved the bytes. Appending text changes them.

Predict: will -WhatIf create the destination file?

Run:

$draftConfigPath = Join-Path -Path $draftFolder -ChildPath 'client.ini'
$sourceSettingsHash = (Get-FileHash -LiteralPath $settingsPath -Algorithm SHA256).Hash
Copy-Item -LiteralPath $settingsPath -Destination $draftConfigPath -WhatIf
Test-Path -LiteralPath $draftConfigPath

Tasks:

  1. Check the preview paths, perform the copy, and verify its hash equals $sourceSettingsHash.
  2. Append ReadyForClass=true to the draft with Add-Content.
  3. Read both versions. Save the edited draft's hash in $editedSettingsHash.
  4. Verify that the original's hash still matches $sourceSettingsHash.

.Hash retrieves the hash string from the returned object. -eq compares values for equality.

Reflect: should the edited hash still equal the source hash?

Checkpoint: two original lines, three draft lines, and an unchanged source.

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Copy and edit solution:

Copy-Item -LiteralPath $settingsPath -Destination $draftConfigPath
(Get-FileHash -LiteralPath $draftConfigPath -Algorithm SHA256).Hash -eq $sourceSettingsHash
Add-Content -LiteralPath $draftConfigPath -Value 'ReadyForClass=true'
Get-Content -LiteralPath $settingsPath
Get-Content -LiteralPath $draftConfigPath
$editedSettingsHash = (Get-FileHash -LiteralPath $draftConfigPath -Algorithm SHA256).Hash
$editedSettingsHash -eq $sourceSettingsHash
(Get-FileHash -LiteralPath $settingsPath -Algorithm SHA256).Hash -eq $sourceSettingsHash

The supplied Test-Path returns False because a preview changes nothing. The first hash comparison is True. After appending, the draft contains the two original lines followed by ReadyForClass=true. Its comparison with the original hash is False; checking the unchanged source is True. Keep both hash variables for the final verification.

Part 4 — Advanced file selection and previews

Activity 4.1 — Search recursively and filter typed metadata

Advanced file selection combines a starting directory, a filename filter, and properties such as LastWriteTime and Length. Complete all advanced activities; they are required parts of the topic.

-Recurse includes subdirectories. @(...) collects results into an array so .Count works consistently for zero, one, or several results.

Predict: how many *.txt files will each search find at this point?

Run:

$directTextFiles = @(Get-ChildItem -LiteralPath $sourceFolder -File -Filter '*.txt')
$allTextFiles = @(Get-ChildItem -LiteralPath $sourceFolder -File -Filter '*.txt' -Recurse)
$directTextFiles.Count
$allTextFiles.Count
$cutoff = (Get-Item -LiteralPath $readmePath).LastWriteTime

Tasks:

  1. Display the recursive text files' FullName and Length.
  2. List all source files recursively with LastWriteTime -ge $cutoff, sorted by LastWriteTime. Display Name and LastWriteTime.
  3. Measure the recursive text files' Length with -Minimum, -Maximum, -Average, and -Sum.

-ge means greater than or equal to. The cutoff is a DateTime object, so the comparison uses timestamps rather than formatted date strings.

Reflect: why use FullName when searching several folders? Why can the timestamp-filtered result vary between machines?

Checkpoint: one direct text file and two recursive text files. The timestamp result includes handover-notes.txt.

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Recursive inspection solution:

$allTextFiles | Sort-Object FullName | Select-Object FullName, Length
Get-ChildItem -LiteralPath $sourceFolder -File -Recurse |
    Where-Object { $_.LastWriteTime -ge $cutoff } |
    Sort-Object LastWriteTime |
    Select-Object Name, LastWriteTime
$allTextFiles |
    Measure-Object -Property Length -Minimum -Maximum -Average -Sum

The counts are 1 and 2: handover-notes.txt is direct; branch-02\room-b.txt is nested. Full paths distinguish files with the same name in different directories. $_ is the current pipeline object.

The timestamp query includes the notes file because its timestamp equals the cutoff. Other matches depend on actual write times and filesystem timestamp precision. Measurement has Count equal to 2 and positive byte statistics. Exact timestamps and byte counts are machine-dependent; keep the numeric properties for comparisons and calculations.

Activity 4.2 — Inspect a controlled hidden file

On Windows, hidden is a file attribute. Default directory listings omit hidden files; -Force includes them without removing the attribute.

Predict: will a hidden file stop existing when it disappears from a normal listing?

Run once:

$markerPath = Join-Path -Path $sourceFolder -ChildPath 'review-marker.txt'
Set-Content -LiteralPath $markerPath -Value 'Reviewed for the classroom.'
Set-ItemProperty -LiteralPath $markerPath -Name Attributes -Value Hidden

This setup sets the attribute only on the new marker, inside your workspace.

Tasks:

  1. Compare direct file listings with and without -Force.
  2. Use Get-ChildItem -Hidden -File to show hidden files only.
  3. Inspect the marker's Attributes with Get-Item -Force -LiteralPath.

Reflect: does -Force mean the same thing as administrator access?

Checkpoint: two files in the normal direct listing, three with -Force, and one hidden marker.

Try the challenge yourself first. Then use the solution to check your work.

Show solution

Attribute inspection solution:

Get-ChildItem -LiteralPath $sourceFolder -File | Select-Object Name
Get-ChildItem -LiteralPath $sourceFolder -File -Force | Select-Object Name
Get-ChildItem -LiteralPath $sourceFolder -File -Hidden | Select-Object Name
Get-Item -LiteralPath $markerPath -Force | Select-Object Name, Attributes

The normal listing shows the configuration and handover notes. -Force adds review-marker.txt. -Hidden shows only that marker, whose attributes include Hidden. The file still exists. -Force requests provider-specific behaviour; it does not grant administrator rights or bypass filesystem permissions.

Activity 4.3 — Preview folder copies and a batch rename

Copying a directory into an existing destination includes its directory name. Copying its children into an existing destination places those children directly there. Inspect both layouts before choosing a copy operation.

Predict: which preview puts branch-02 directly below the destination?

Run once:

$copyPreviewRoot = Join-Path -Path $labRoot -ChildPath 'copy-preview'
$folderPreview = Join-Path -Path $copyPreviewRoot -ChildPath 'folder-case'
$contentsPreview = Join-Path -Path $copyPreviewRoot -ChildPath 'contents-case'
New-Item -Path $copyPreviewRoot -ItemType Directory | Out-Null
New-Item -Path $folderPreview -ItemType Directory | Out-Null
New-Item -Path $contentsPreview -ItemType Directory | Out-Null
$sourceContents = Join-Path -Path $sourceFolder -ChildPath '*'

Tasks:

  1. Preview copying $sourceFolder into $folderPreview with -Recurse, -Force, and -WhatIf.
  2. Preview copying $sourceContents into $contentsPreview with the same switches. Use -Path here because * deliberately selects children.
  3. Predict the relative destination of branch-02\room-b.txt for both.
  4. Select the visible recursive *.txt files and preview adding review- to each name. Use ForEach-Object with Rename-Item -LiteralPath.
  5. Verify that the two destination folders remain empty and names are unchanged.

Inside ForEach-Object { ... }, $_ is the current file. The expression 'review-' + $_.Name builds its proposed new name.

Checkpoint: previews only; no source names or contents have changed.

Try the challenge yourself first. Then use the solution to check your work.

Folder copy previews:

Self-check answers:

  1. [lab] is interpreted as a wildcard character set by -Path. -LiteralPath treats the brackets as part of the filename.
  2. Relative paths start from the new working location; absolute paths retain their original meaning.
  3. Get-Item inspects the named item; Get-ChildItem enumerates its children.
  4. -Recurse includes the nested branch-02\room-b.txt.
  5. Matching SHA256 hashes provide evidence of identical bytes. Appending the readiness line changes the draft's content and hash.
  6. Copying preserves the source and creates another item. Moving relocates it. Renaming changes its name without moving it to another directory here.
  7. Both sides remain typed timestamps, avoiding culture-dependent text ordering.
  8. Neither. -Force includes hidden files in this listing and grants no rights.
  9. Copying source into an existing folder creates a nested source directory; copying source\* places its children directly inside the destination.
  10. Preview Remove-Item -LiteralPath $scratchPath -WhatIf, inspect the exact path, perform the deletion, and check that the scratch file is absent while the source and delivered configuration remain.
