What is a function

In programming and scripting languages, including PowerShell, a function is a reusable, self-contained block of code that performs a specific task or set of tasks. Functions are used to organize code, promote reusability, and make the code more modular.

In PowerShell, a function is defined using the function keyword followed by the function name and a set of curly braces that enclose the code block.

Function overview

flowchart LR
    A["Call the function"] --> B["Pass input through parameters"]
    B --> C["Run the function's code"]
    C --> D["Output a result"]
    D --> E["Display, store, or pipe the result"]

Parameters and output are optional: a function can also perform a task without receiving input or returning a result.

Syntax:

function [<scope:>]<name> [([type]$parameter1[,[type]$parameter2])]
{
  begin {<statement list>}
  process {<statement list>}
  end {<statement list>}
  clean {<statement list>}
}

function [<scope:>]<name>
{
  param([type]$parameter1 [,[type]$parameter2])
  dynamicparam {<statement list>}
  begin {<statement list>}
  process {<statement list>}
  end {<statement list>}
  clean {<statement list>}
}

Explanation of the syntax:

  • function: This keyword is used to define a function in PowerShell.
  • <scope:>: This is an optional scope modifier that specifies the visibility of the function. It can be global, script, or local. If not specified, the function is local to the current scope.
  • <name>: This is the name of the function. It should be a valid identifier and follow PowerShell naming conventions.
  • param: This keyword is used to define parameters for the function. Parameters allow you to pass values into the function when it is called.
  • [type]: This is an optional type declaration for the parameter. It specifies the expected data type of the parameter (e.g., [string], [int], etc.).
  • begin, process, end, and clean: These are optional script blocks that define different stages of the function's execution. The begin block is executed once before any input is processed, the process block is executed for each input object, the end block is executed once after all input has been processed, and the clean block is executed for cleanup tasks.
  • <statement list>: This represents the actual code or statements that will be executed within each block of the function.
  • dynamicparam: This is an optional block that allows you to define dynamic parameters for the function. Dynamic parameters are parameters that can be added or modified at runtime based on certain conditions.
  • The function can be called by its name, and you can pass arguments to the parameters defined in the function. Functions can return values using the return keyword, and they can also output objects to the pipeline for further processing.

Here's a simple example of a PowerShell function:

Example - Example_SayHello.ps1:

function Show-Hello {
    Write-Host "Hello, World!"
}

In this example:

  • SayHello is the name of the function.
  • The code block within the curly braces contains the instructions or commands to be executed when the function is called.
  • The Write-Host cmdlet is used to output the "Hello, World!" message to the console.

You can call the function by simply typing its name:

SayHello

When you run this script, it will execute the code within the SayHello function, resulting in the "Hello, World!" message being printed to the console.

Why use function(s)

Using functions in programming, including PowerShell, offers several advantages, contributing to cleaner, more modular, and more maintainable code. Here are some reasons why using functions is beneficial:

  • Modularity: Functions allow you to break down your code into smaller, manageable pieces. Each function can focus on a specific task or functionality, making the code easier to understand and maintain.

  • Reusability: Once you've defined a function, you can call it multiple times from different parts of your script or from other scripts. This promotes code reuse and helps avoid duplicating code.

  • Readability: Functions provide a way to encapsulate and name specific operations or tasks. This makes your code more self-documenting, as the function name often indicates its purpose.

  • Parameterization: Functions can accept parameters, allowing you to customize their behavior based on input values. This parameterization enhances flexibility and adaptability.

  • Encapsulation: Functions encapsulate logic, meaning that the internal details of a function are hidden from the rest of the script. This helps prevent unintended interference or modification of variables within the function.

  • Testing and Debugging: Functions make it easier to test and debug code. Since functions focus on specific tasks, it's simpler to isolate and address issues within a function rather than dealing with the entire script.

  • Code Organization: Functions contribute to a more organized code structure. Instead of having a long, monolithic script, you can group related functionality into separate functions, making the codebase more structured and maintainable.

  • Scoping: Functions have their own scope in PowerShell. Variables defined within a function are local to that function by default, reducing the risk of naming conflicts with variables in other parts of the script.

Naming

When naming functions in PowerShell (or any programming language), it's essential to choose clear, descriptive, and meaningful names that convey the purpose or action of the function. Here are some best practices for naming functions:

  • Use Verb-Noun Naming Convention: Follow the standard PowerShell naming convention for functions, which is Verb-Noun. Choose a verb that describes the action the function performs and a noun that describes the object or target of the action. For example: Get-Process, Start-Service, Stop-Service.

    • For example: <ApprovedVerb>-<Prefix><SingularNoun>
    • ApprovedVerbs: Get-Verb | Sort-Object -Property Verb

  • Be Descriptive: Make the function name descriptive enough to convey its purpose without needing to read the entire function body. A good function name should provide a clear idea of what the function does.

  • Avoid Ambiguity: Avoid names that are ambiguous or could be easily confused with other functions or variables. Clarity is crucial for readability and maintainability.

  • Consistency: Maintain consistency in naming conventions across your scripts and functions. Consistency makes the codebase more predictable and easier to understand.

  • Use PascalCase: In PowerShell, use CamelCase for function names. Start each word with an uppercase letter, For example: Get-Process, Start-Service, Invoke-MyFunction.

  • Avoid Abbreviations (Unless Standard): While brevity is valuable, avoid unnecessary abbreviations in function names. Use abbreviations only if they are standard or widely recognized (e.g., Invoke-WebRequest).

  • Be Concise but Informative: Keep function names concise while providing enough information. Aim for a balance between brevity and clarity.

Parameters

Functions in PowerShell can also take parameters, allowing you to pass values into the function, and they can return values using the return keyword. Here's an example of a function with parameters:

How arguments reach parameters

flowchart LR
    A["Call: Multiply-Numbers -a 5 -b 3"] --> B["Parameters: a = 5, b = 3"]
    B --> C["Multiply: 5 * 3"]
    C --> D["Result: 15"]

Example - Example_MultiplyNumbers.ps1:

function Multiply-Numbers {
    param (
        [int]$a,
        [int]$b
    )

    $result = $a * $b
    return $result
}

# Call the function and store the result in a variable
$result = Multiply-Numbers -a 5 -b 3

# Output the result
Write-Host "The result is: $result"

The result is: 15

In this example, the Multiply-Numbers function takes two parameters ($a and $b), multiplies them, and returns the result. The result is then stored in a variable and displayed in the console.

Various parameter types

  • Boolean:
    • Represents true or false values.
  • Supports other Datatypes like string, int, double, array, hashtable, ...
function Example-Function {
    param (
        [bool]$IsEnabled
    )
    # Function body
}
  • Switch: Used for parameters that represent a switch (on/off) or boolean flag.
function Example-Function {
    param (
        [switch]$Force
    )
    # Function body
}
  • ValidateSet: Restricts the parameter to a predefined set of values. powershell
function Example-Function {
    param (
        [ValidateSet("Option1", "Option2", "Option3")]
        [string]$Choice
    )
    # Function body
}

Accept pipeline input

The pipeline (|) sends output objects from one command to the next. To bind those objects directly to a function parameter, mark the parameter with ValueFromPipeline or ValueFromPipelineByPropertyName. A process block then runs once for each incoming object. Without process, the function body does not automatically run once per object.

Two ways to bind pipeline input

flowchart LR
    A["Incoming number: 4"] --> B["By value: Number = 4"]
    B --> C["process: assess 4"]
    D["Incoming object: Name = Anis, Course = Scripting"] --> E["By property name: Name = Anis"]
    E --> F["process: greet Anis"]

The examples below define each function and show the corresponding output.

Bind the whole object by value

ValueFromPipeline binds each incoming object itself to the parameter when its type is compatible or PowerShell can convert it. This example receives integers and returns an assessment object for each one:

function Get-NumberAssessment {
    [CmdletBinding()]
    param(
        [Parameter(Mandatory, ValueFromPipeline)]
        [int]$Number
    )

    process {
        [pscustomobject]@{
            Number = $Number
            Even   = $Number % 2 -eq 0
            Square = $Number * $Number
        }
    }
}

1..4 | Get-NumberAssessment

Number  Even Square
------  ---- ------
     1 False      1
     2  True      4
     3 False      9
     4  True     16

For each number, PowerShell binds the value to $Number, runs process, and outputs the resulting object. The parameter can also be supplied directly: Get-NumberAssessment -Number 4 produces one object.

Bind a property by name

ValueFromPipelineByPropertyName looks for a property whose name matches the parameter name or one of its aliases. It binds that property's value, not the whole incoming object.

function Get-StudentGreeting {
    [CmdletBinding()]
    param(
        [Parameter(Mandatory, ValueFromPipelineByPropertyName)]
        [string]$Name
    )

    process {
        "Hello, $Name!"
    }
}

$students = @(
    [pscustomobject]@{ Name = 'Anis'; Course = 'Scripting' }
    [pscustomobject]@{ Name = 'Jan'; Course = 'Networking' }
)

$students | Get-StudentGreeting

Hello, Anis!
Hello, Jan!

Each object's Name property binds to -Name; Course is not used. If a property is missing or its value cannot be converted to the parameter type, binding can fail for that object. When both forms are available, PowerShell tries binding without type conversion first: by value, then by property name. It then tries the same order with type conversion if needed.

Processing stages

  • begin runs once before pipeline objects are processed, for setup.
  • process runs once per incoming object. With a direct call, it runs once.
  • end runs once after processing completes, for final output or summary.

Normal processing flow

flowchart TD
    A["begin: setup once"] --> B{"Another input object?"}
    B -- Yes --> C["process: handle one object"]
    C --> B
    B -- No --> D["end: finish once"]

All three blocks are optional. process controls when the work runs; the parameter attributes control how pipeline objects are bound. The ForEach-Object { Process-Input -Name $_ } example in the input redirection section below explicitly passes each value and therefore does not require the function parameter to accept pipeline input.

Redirection

You can use functions in combination with redirection operators to control input and output. Redirection operators allow you to send the output of a command or function to a file, variable, or another command. Here are some examples:

Using Function with Output Redirection

Example_GetEvenNumbers.ps1:

function Get-EvenNumbers {
    param (
        [int]$Max
    )

    2..$Max | Where-Object { $_ % 2 -eq 0 }
}

# Redirect output to a file
Get-EvenNumbers -Max 10 > "EvenNumbers.txt"

# Redirect output to a variable
$evenNumbers = Get-EvenNumbers -Max 10
Write-Host "Even Numbers: $evenNumbers"

Even Numbers: 2 4 6 8 10

Using Function with Input Redirection:__

Example_Process-Input.ps1:

function Process-Input {
    param (
        [string]$Name
    )

    Write-Host "Hello, $Name!"
}

# Read input from a file and pass it to the function
Get-Content "Names.txt" | ForEach-Object { Process-Input -Name $_ }

Hello, Dominique!
Hello, Anis!
Hello, Jan!
Hello, Luisella!

# Define a function named Start-App
function Start-App {

Scope

By default, all variables created in functions are local, they only exist within the function, though they are still visible if you call a second function from within the first one.​

To persist a variable, so the function can be called repeatedly and the variable will retain it's last value, prepend $script: to the variable name, e.g. $script:myvar​

To make a variable global prepend $global: to the variable name, e.g. $global:myvar

Function global: Get-MyProcessID declares a function named Get-MyProcessID. The global: scope modifier makes the function globally accessible.

Example_MyProcessID.ps1:

Function global:Get-MyProcessID {
    Param (
       [string]$ProcessName
    ) #end Param
    $processid =Get-Process -Name $ProcessName | select-object Id
    return $processid
}

.\Example_MyProcessID.ps1

Start Notepad 5 times using the range operator.

1..5 | ForEach-Object { Start-Process "notepad.exe" }

The function has a global scope and can therefor be accessed outside the script.

An Advanced PowerShell function contains the [cmdletbinding()] attribute ​ (or the Parameter attribute).

This adds several capabilities such as additional parameter checking, and the ability to easily use Write-Verbose.​

A function with cmdletbinding will throw an error if unhandled parameter values appear on the command line.
