Managing files and directories with PowerShell

06 - Files and directories

Originele pagina openen →

Why this matters

A support technician needs to inspect a log, keep the original, and move a working copy into a report folder. PowerShell makes these steps repeatable: you can select the right files, inspect their contents, preview a change, and verify its result.

Safe file workflow

flowchart LR
    A["Identify the exact source and destination"] --> B["Inspect the source"]
    B --> C["Preview the change with WhatIf"]
    C --> D["Apply only the intended change"]
    D --> E["Verify files and contents"]

This lesson explains the commands behind that workflow. The dedicated 04b — Files and directories hands-on provides guided practice and an independent handover challenge. Complete it after the combined output, formatting, files, and directories lab.

Learning objectives

After this lesson and the matching lab activities, you can:

  • build a path and explain the current working directory;
  • distinguish a file object from a directory object;
  • create, list, and inspect practice files and folders;
  • read, replace, append, and search text content;
  • copy, move, rename, and remove a specific practice file;
  • preview supported changes with -WhatIf and verify the resulting state;
  • search subdirectories and filter by timestamps and attributes; and
  • explain folder-copy behaviour and preview batch operations.

Prerequisites

  • PowerShell 7 on Windows and a terminal.
  • Familiarity with strings, pipelines, and Select-Object.
  • An instructor-prepared, writable C:\powershell folder. Routine lesson commands do not need elevation once that access is ready.

A variable such as $sourceLog stores a value for reuse. = assigns that value, and $sourceLog retrieves it. A dot accesses a property, as in $file.Name. The examples introduce these uses before relying on them.

How to use this lesson with the hands-on

Start with the foundations, then complete the advanced material. Predict each example's result, run it, and inspect what changed. Keep the same PowerShell session open: later examples reuse its variables and files. If you restart, repeat the earlier examples in order.

The lesson uses its own PowerShell-Files-Lesson folder. The hands-on has a separate workspace and its own setup. Follow the lab's instructions when you switch to it.

Foundations

Prepare a small working example

Use a dedicated folder so that every change has a known target. The following commands create the lesson folder and three subfolders.

Join-Path builds a path from a parent and a child name. C:\powershell is the course practice base. New-Item creates an item; -ItemType Directory requests a folder. Out-Null suppresses the returned object.

$fileLessonRoot = Join-Path -Path 'C:\powershell' -ChildPath 'PowerShell-Files-Lesson'
$dataFolder = Join-Path -Path $fileLessonRoot -ChildPath 'data'
$archiveFolder = Join-Path -Path $fileLessonRoot -ChildPath 'archive'
$reportFolder = Join-Path -Path $fileLessonRoot -ChildPath 'reports'

New-Item -Path $fileLessonRoot -ItemType Directory -Force | Out-Null
New-Item -Path $dataFolder -ItemType Directory -Force | Out-Null
New-Item -Path $archiveFolder -ItemType Directory -Force | Out-Null
New-Item -Path $reportFolder -ItemType Directory -Force | Out-Null

Get-ChildItem -LiteralPath $fileLessonRoot -Directory |
    Select-Object Name

Expected folder names:

archive
data
reports

For a directory, -Force allows reuse of an existing folder. It does not empty that folder. Use these commands only with the lesson paths above. When you repeat the lesson, its writing examples replace the named sample files.

Inspect: Find the three folders in File Explorer. Which variable contains each full path?

Show solution

$dataFolder contains C:\powershell\PowerShell-Files-Lesson\data, $archiveFolder contains C:\powershell\PowerShell-Files-Lesson\archive, and $reportFolder contains C:\powershell\PowerShell-Files-Lesson\reports. All three are children of $fileLessonRoot. Enter a variable's name in the terminal to display its stored path.

Understand paths and the working directory

An absolute path identifies a location from its drive or root. A relative path is interpreted from the current working directory. For example, .\data means the data folder below the current directory.

Set-Location -LiteralPath $fileLessonRoot
Get-Location
(Get-Location).Path
Test-Path -LiteralPath '.\data' -PathType Container

Set-Location changes location and normally prints nothing. Get-Location returns a location object; .Path retrieves its path as text. The final command returns True because the setup created the directory.

-PathType Container checks for a directory. -PathType Leaf checks for a file in the FileSystem provider.

Prefer -LiteralPath when you already have an exact path: characters such as brackets are treated literally. Use -Path when you intentionally need a wildcard pattern and the command supports one. Quote paths containing spaces.

Inspect: Explain why .\data might identify a different location after another Set-Location command.

Show solution

.\data starts from the current working directory. After Set-Location, the same text refers to a child of the new location. $dataFolder holds the absolute lesson path and continues to identify the original directory.

Create and inspect a file

New-Item -ItemType File creates an empty file. This example uses -Force to reset only the lesson's named sample file if it already exists.

$sourceLog = Join-Path -Path $dataFolder -ChildPath 'support.log'
New-Item -Path $sourceLog -ItemType File -Force | Out-Null

Get-Item -LiteralPath $sourceLog |
    Select-Object Name, Length

Test-Path -LiteralPath $sourceLog -PathType Leaf

The file is named support.log, its initial Length is 0 bytes, and Test-Path returns True.

Get-Item returns the item at a path. Get-ChildItem returns the items inside a directory. Both return objects that other commands can inspect.

(Get-Item -LiteralPath $sourceLog).GetType().FullName
(Get-Item -LiteralPath $dataFolder).GetType().FullName

Get-Item -LiteralPath $sourceLog |
    Get-Member -MemberType Properties

The first two results are:

System.IO.FileInfo
System.IO.DirectoryInfo

GetType() identifies an object's type. File objects have properties such as Name, FullName, Length, CreationTime, and LastWriteTime. Directory objects share several of those properties but do not have a file's Length; they have properties such as Parent instead.

Inspect: Which command would you use to inspect the folder itself? Which would you use to list the files inside it?

Show solution 
Get-Item -LiteralPath $dataFolder
Get-ChildItem -LiteralPath $dataFolder -File

Get-Item returns the directory object. Get-ChildItem -File returns its direct file children; add -Recurse when the task includes subdirectories.

Write, read, append, and search text

Set-Content writes text to a file, replacing existing content. Add-Content appends text. Get-Content reads the text back.

Set-Content -LiteralPath $sourceLog -Value 'INFO: Support check started.'
Add-Content -LiteralPath $sourceLog -Value 'ERROR: Sample connection failure.'

$notesPath = Join-Path -Path $dataFolder -ChildPath 'notes.txt'
Set-Content -LiteralPath $notesPath -Value 'Practice notes.'

Get-Content -LiteralPath $sourceLog

Expected log content:

INFO: Support check started.
ERROR: Sample connection failure.

Get-Content normally returns one string per line. -Raw returns the whole file as one string, useful when later processing requires the complete text.

To find relevant lines, use Select-String. Its -Pattern parameter uses a regular expression; the literal word ERROR is sufficient here.

Select-String -LiteralPath $sourceLog -Pattern 'ERROR' |
    Select-Object FileName, LineNumber, Line

The match is in support.log on line 2, inside C:\powershell\PowerShell-Files-Lesson\data.

Inspect: What would happen to the two log lines if you used Set-Content again instead of Add-Content?

Show solution

Set-Content would replace the existing contents with the supplied new value. The earlier lines would be lost unless supplied again. Add-Content keeps the existing lines and appends the new line.

Apply: Complete Activities 1.2 and 2.2 of hands-on 04b for guided practice with text files.

List and select files

Use -File for files and -Directory for folders. -Filter selects names with a filesystem wildcard. A wildcard such as *.log selects log filenames; it does not search their contents.

Get-ChildItem -LiteralPath $dataFolder -File |
    Select-Object Name, Length, LastWriteTime

Get-ChildItem -LiteralPath $dataFolder -File -Filter '*.log' |
    Select-Object Name

The first command lists notes.txt and support.log. The second selects only support.log in the sample workspace. Lengths and timestamps depend on the file contents and when you ran the examples.

Filter by name during retrieval when possible. Use Where-Object later when you need to test an object property, such as its size or modification time.

Inspect: Which command would you change to select *.txt instead? Why would that not find the word ERROR inside a log?

Show solution 
Get-ChildItem -LiteralPath $dataFolder -File -Filter '*.txt' |
    Select-Object Name

Change Get-ChildItem's filename filter from *.log to *.txt. This selects notes.txt in the sample folder. A filename filter does not read file contents. Use Select-String -LiteralPath $sourceLog -Pattern 'ERROR' to search for that text inside the log.

Preview a change, then copy and verify

Copying keeps the source and creates a separate destination file. Build the destination explicitly so you can see its complete name.

$logCopyPath = Join-Path -Path $archiveFolder -ChildPath 'support-copy.log'

$sourceLog
$logCopyPath
Copy-Item -LiteralPath $sourceLog -Destination $logCopyPath -WhatIf

-WhatIf describes the proposed copy without performing it. For a fresh workspace, the destination does not exist yet. On a repeat run, an older copy might already be present, so existence alone cannot prove that a preview made a new copy.

After inspecting the paths, run the copy and check its result:

Copy-Item -LiteralPath $sourceLog -Destination $logCopyPath

Test-Path -LiteralPath $sourceLog -PathType Leaf
Test-Path -LiteralPath $logCopyPath -PathType Leaf
Get-FileHash -LiteralPath $sourceLog, $logCopyPath |
    Select-Object Path, Hash

Both existence checks return True. The hashes match because the two files have the same contents. A hash is a value calculated from a file's bytes; it helps compare the copy with the source.

Apply: Use the same preview, perform, and verify pattern in Activity 3.1 of hands-on 04b.

Move and rename a working copy

Moving changes a file's location. Renaming changes its name within a directory. The original support.log remains available because this example moves its copy.

$movedLogPath = Join-Path -Path $reportFolder -ChildPath 'support-copy.log'

Move-Item -LiteralPath $logCopyPath -Destination $movedLogPath -WhatIf
Move-Item -LiteralPath $logCopyPath -Destination $movedLogPath

Test-Path -LiteralPath $logCopyPath
Test-Path -LiteralPath $movedLogPath -PathType Leaf

The checks return False and True, respectively.

Rename-Item -LiteralPath $movedLogPath -NewName 'support-reviewed.log' -WhatIf
Rename-Item -LiteralPath $movedLogPath -NewName 'support-reviewed.log'

$reviewedLogPath = Join-Path -Path $reportFolder -ChildPath 'support-reviewed.log'
Get-Item -LiteralPath $reviewedLogPath |
    Select-Object Name, DirectoryName

-NewName receives the new name, not a destination path. Use Move-Item when you want to change the parent directory.

Inspect: Which path disappears after the move? Which file still contains the original log?

Show solution

$logCopyPath, the former archive\support-copy.log, disappears. Immediately after the move the copy is at $movedLogPath; after the rename it is at $reviewedLogPath. The original $sourceLog, data\support.log, remains unchanged throughout.

Apply: Complete Activity 3.2 of hands-on 04b before attempting its independent handover challenge.

Remove a specific practice file

Removal deletes the targeted item. Preview the exact file you intend to remove, perform the change, and check the result.

Remove-Item -LiteralPath $reviewedLogPath -WhatIf
Test-Path -LiteralPath $reviewedLogPath -PathType Leaf

The file still exists after the preview, so the check returns True.

Remove-Item -LiteralPath $reviewedLogPath
Test-Path -LiteralPath $reviewedLogPath
Test-Path -LiteralPath $sourceLog -PathType Leaf

The removed copy returns False; the original log returns True. This example targets one known practice file. A wildcard would select a wider set of items, which requires separate inspection.

Foundation checkpoint

Before moving on, explain:

  1. Why does the working directory matter for a relative path?
Show solution

A relative path is resolved from the current working directory. Changing that directory can make the same relative text identify a different item.

  1. How do Get-Item and Get-ChildItem differ?
Show solution

Get-Item returns the item at the named path. Get-ChildItem enumerates children of a directory, and -Recurse extends that enumeration below it.

  1. When would you choose Set-Content rather than Add-Content?
Show solution

Use Set-Content to create or deliberately replace the complete contents. Use Add-Content when existing content must remain and new text belongs after it.

  1. What is the difference between selecting log filenames and searching log text?
Show solution

Get-ChildItem -Filter '*.log' selects file objects by name. Select-String reads text and returns matching lines. Choose the files, then search their contents.

  1. What changes after a copy, a move, a rename, and a removal?
Show solution

A copy creates a separate destination while keeping the source. A move relocates an item. A rename changes its name. Removal deletes the selected item. Copying, moving, and renaming normally preserve file contents.

  1. Why should verification follow a state-changing command?
Show solution

A command being accepted does not prove the intended final state. Check exact paths, contents, and hashes as appropriate to detect a wrong destination, an unexpected overwrite, or an incomplete operation.

Advanced material

Complete all the sections below. They extend the foundational commands with searches through subfolders, date and attribute filters, folder copying, and batch operations. Explain each example's behaviour as well as running it.

The examples reuse the lesson setup, including $dataFolder and $sourceLog. Complete the foundations first, or recreate their setup in a new session. None of these examples uses the hands-on's workspace.

Search through subdirectories

-Recurse searches below the supplied directory. Keep the starting path limited to the folder relevant to the task.

Get-ChildItem -LiteralPath $fileLessonRoot -File -Filter '*.log' -Recurse |
    Select-Object FullName, Length

The core example leaves the original support.log in data. Any additional files you created can change the result. FullName makes nested locations visible without relying on the default display layout.

Include or exclude multiple filename patterns

-Filter accepts one filter string. -Include and -Exclude can express multiple wildcard patterns. The following -Path deliberately ends in * to enumerate the directory's contents.

$dataContents = Join-Path -Path $dataFolder -ChildPath '*'

Get-ChildItem -Path $dataContents -File -Include '*.log', '*.txt' -Exclude 'old-*' |
    Select-Object Name

With the core sample files, the result contains notes.txt and support.log. -Include and -Exclude are applied after enumeration; a single extension filter is usually clearer with -Filter.

Filter timestamps without turning dates into text

CreationTime records creation, LastWriteTime records the latest write, and LastAccessTime records access information. These properties are date objects, not formatted strings.

Get-Item -LiteralPath $sourceLog |
    Select-Object Name, CreationTime, LastWriteTime, LastAccessTime

$cutoff = [datetime]'2026-10-01'
Get-ChildItem -LiteralPath $dataFolder -File |
    Where-Object { $_.LastWriteTime -gt $cutoff } |
    Select-Object Name, LastWriteTime

[datetime] converts the quoted value to a date object. Use an unambiguous year-month-day value such as 2026-10-01; avoid ambiguous inputs such as 01/10/2026. Results depend on the sample files' timestamps.

Add a time, such as [datetime]'2026-10-01 09:30:00', when the comparison requires it. Use CreationTime instead of LastWriteTime only when creation is the fact you want to test.

Format the date after filtering when presenting it to a person:

Get-ChildItem -LiteralPath $dataFolder -File |
    Select-Object Name,
        @{Name = 'ModifiedDate'; Expression = { $_.LastWriteTime.ToString('dd/MM/yy') }}

The calculated property labels the display column. ToString('dd/MM/yy') produces text for display. Get-Date -Format also returns text; keep date objects for date comparisons.

Inspect hidden files and attribute expressions

File attributes describe characteristics such as hidden, system, or read-only. A file can have several attributes at once. -Force includes hidden and system items during listing, but does not grant access that your account lacks.

The lesson's $dataFolder may contain no hidden files. To see existing examples on Windows 11, inspect the Windows drive and Windows directory instead. These are read-only, top-level listings; they require no changes to the files or to File Explorer settings.

Show existing Windows 11 items

$env:SystemDrive identifies the Windows drive, usually C:. Appending \ produces its root path. $env:windir identifies the Windows directory, usually C:\Windows.

$systemDriveRoot = $env:SystemDrive + '\'

Get-ChildItem -LiteralPath $systemDriveRoot -Force |
    Sort-Object Name |
    Select-Object Name, Attributes

The Attributes column makes hidden and system items visible even when the console's default display does not show every attribute.

Common Windows 11 examples include:

Location Typical attributes What it is
C:\ProgramData Hidden, Directory Shared application data folder
C:\$Recycle.Bin Hidden, System, Directory Recycle Bin folder
C:\pagefile.sys Hidden, System, Archive Paging file, when configured here
C:\swapfile.sys Hidden, System, Archive Windows swap file, when present
C:\hiberfil.sys Hidden, System, Archive Hibernation file, when enabled

Use the actual paths printed on your system if Windows is on another drive. The list, file locations, and additional attributes vary by configuration. A missing hiberfil.sys does not mean the query failed.

Inspect: Use Attributes to distinguish directories from files in your output. Which of the common examples are directories?

Show solution

ProgramData and $Recycle.Bin have the Directory attribute. pagefile.sys, swapfile.sys, and hiberfil.sys are files when present. Hidden and System are independent flags; neither tells you whether the item is a directory. Use -File or -Directory to select that kind of item.

Show only hidden files or only system files

Add -File to exclude directories. Compare the attributes returned by these three queries:

Get-ChildItem -LiteralPath $systemDriveRoot -File -Hidden -Force |
    Sort-Object Name |
    Select-Object Name, Attributes

Get-ChildItem -LiteralPath $systemDriveRoot -File -System -Force |
    Sort-Object Name |
    Select-Object Name, Attributes

Get-ChildItem -LiteralPath $env:windir -File -System -Force |
    Sort-Object Name |
    Select-Object Name, Attributes

The first two queries commonly include pagefile.sys and swapfile.sys. They can appear in both lists because they have both attributes. The Windows-directory query can show bootstat.dat with System and Archive attributes, without Hidden. An empty selection is valid when no matching files exist in that particular location. Inspect the actual Attributes column.

The .sys filename extension does not set the System attribute. The filter checks the stored attribute, rather than the file's extension.

Compare attribute expressions

Attribute expressions use ! for NOT, + for AND, and , for OR. Keep an expression in quotes, with no spaces around ! or +. See the Get-ChildItem attribute reference.

The comma below supplies two search locations. Each query lists their direct children; FullName distinguishes files from the two directories.

$attributeLocations = $systemDriveRoot, $env:windir

Get-ChildItem -LiteralPath $attributeLocations -File -Force -Attributes 'Hidden,System' |
    Sort-Object FullName |
    Select-Object FullName, Attributes

Get-ChildItem -LiteralPath $attributeLocations -File -Force -Attributes 'Hidden+System' |
    Sort-Object FullName |
    Select-Object FullName, Attributes

'Hidden,System' selects files with Hidden or System, including files with both. 'Hidden+System' requires both attributes on the same file.

Inspect: Why can bootstat.dat appear in the OR selection but be absent from the AND selection?

Show solution

When bootstat.dat has System but not Hidden, it satisfies Hidden,System through its System attribute. It fails Hidden+System because the Hidden attribute is missing. A file such as pagefile.sys with both flags satisfies both expressions. If your machine assigns different attributes, its result follows those actual flags.

Use NOT when you want to exclude an attribute:

Get-ChildItem -LiteralPath $systemDriveRoot -Force -Attributes '!Directory+!System' |
    Sort-Object Name |
    Select-Object Name, Attributes

This excludes directories and system items. Hidden files without System can still appear because -Force includes them. Prefer -File, -Directory, -Hidden, or -System when one simple switch expresses the requirement.

Understand recursive folder copying

Copying a folder and copying its contents are different requests. An existing destination folder can become the parent of the source folder. To compare these requests, create two separate destination folders and use previews.

$folderCopyTarget = Join-Path -Path $fileLessonRoot -ChildPath 'folder-copy'
$contentsCopyTarget = Join-Path -Path $fileLessonRoot -ChildPath 'contents-copy'
$dataContents = Join-Path -Path $dataFolder -ChildPath '*'

New-Item -Path $folderCopyTarget -ItemType Directory -Force | Out-Null
New-Item -Path $contentsCopyTarget -ItemType Directory -Force | Out-Null

Copy-Item -LiteralPath $dataFolder -Destination $folderCopyTarget -Recurse -WhatIf
Copy-Item -Path $dataContents -Destination $contentsCopyTarget -Recurse -WhatIf
Parameter Behavior
-Path Interprets wildcard characters such as *, ?, and [abc].
-LiteralPath Treats the entire path exactly as written. Wildcard characters have no special meaning.

The first request copies data as a folder under folder-copy. The second copies the items inside data into contents-copy without that extra data level. $dataContents deliberately uses a wildcard to select those contents.

The previews do not copy files. Check whether the destination already exists and decide whether it should contain the source folder or just its contents. Deleting a destination first is not required to make that choice. -Force is not a general permission bypass and does not replace checking possible overwrites.

Preview batch creation and renaming

A batch operation repeats a command for multiple items. These examples use ForEach-Object. The pattern needed here is introduced below; the loops lesson develops it further.

1..3 generates the numbers from one to three. The pipeline passes each number to the script block, where $_ is the current value.

1..3 | ForEach-Object {
    $sampleName = 'sample-{0}.txt' -f $_
    New-Item -Path $dataFolder -Name $sampleName -ItemType File -WhatIf
}

These are previews: no sample files are created. The -f operator inserts the number into the {0} placeholder.

To rename an existing selection, first enumerate its exact members and then preview the new names:

Get-ChildItem -LiteralPath $dataFolder -File -Filter '*.txt' |
    ForEach-Object {
        Rename-Item -LiteralPath $_.FullName -NewName ('reviewed_' + $_.Name) -WhatIf
    }

Here, $_ represents a file object instead of a number. .FullName identifies the source, while .Name supplies its current filename.

Other advanced naming rules include:

Requirement Naming idea
Replace text in a name Use -replace for a precisely tested regex.
Add a date Combine BaseName, a Get-Date -Format 'yyyyMMdd' value, and Extension.
Add a sequence number Use a counter and keep the original extension.

Changing a filename extension does not convert the file's content. Always check for duplicate destination names before performing a batch rename.

Advanced read-only practice

Complete these tasks to apply the advanced file-selection concepts. They complement the separate hands-on scenario.

  • List the lesson's files with their names and creation dates, newest first.
Show solution 
Get-ChildItem -LiteralPath $dataFolder -File |
    Sort-Object CreationTime -Descending |
    Select-Object Name, CreationTime

The lesson files are notes.txt and support.log. Their order depends on actual creation times; a reused file can have an earlier creation date. Adding -Recurse also includes files below any subdirectories.

  • List its directories with names and modification times, sorted by name.
Show solution 
Get-ChildItem -LiteralPath $fileLessonRoot -Directory |
    Sort-Object Name |
    Select-Object Name, LastWriteTime

This lists the lesson root's immediate directories alphabetically, including archive, data, and reports. Advanced examples also create folder-copy and contents-copy. Modification times vary. Add -Recurse to include nested directories.

  • Use Measure-Object -Property Length with -Minimum, -Maximum, -Average, and -Sum to inspect file sizes. Keep byte values numeric; convert them to KB or MB when presenting a report.
Show solution 
Get-ChildItem -LiteralPath $dataFolder -File |
    Measure-Object -Property Length -Minimum -Maximum -Average -Sum

Count is the number of measured files; the other properties describe their numeric byte lengths. Exact sizes depend on content and encoding. Add -Recurse to include nested files, which can change every statistic. Divide a byte value by 1KB or 1MB only when presenting the result.

  • Search for *.docx below a folder containing only your assigned practice documents. Filter on CreationTime after [datetime]'2026-10-01', sort oldest first, and display names, dates, and sizes. An empty result is valid.
Show solution

For a safe check using the lesson's own practice directory:

Get-ChildItem -LiteralPath $dataFolder -File -Filter '*.docx' -Recurse |
    Where-Object { $_.CreationTime -gt [datetime]'2026-10-01' } |
    Sort-Object CreationTime |
    Select-Object Name, CreationTime, Length

The supplied lesson creates no Word documents, so this check is empty unless assigned practice documents were added. Use the instructor-assigned document folder when provided. -gt excludes the cutoff itself. Keep both sides as date values. Without -Recurse, nested documents are excluded.

Predict which commands and properties each task needs before running it. Explain how the answer changes when you include subdirectories.

Show solution

Use Get-ChildItem for retrieval, CreationTime or LastWriteTime for timestamps, Length for file bytes, Where-Object for property tests, Sort-Object for ordering, and Measure-Object for statistics.

-Recurse expands the selection below the starting folder. It can add files and directories, change counts and size statistics, and introduce duplicate names. Display FullName when the location must be unambiguous. If there are no matching nested items, the results stay the same.

Summary

Join-Path builds paths, Get-Location explains relative paths, and Test-Path checks what exists. Get-Item inspects an item; Get-ChildItem lists and filters a directory's contents. Use Set-Content, Add-Content, and Get-Content to work with text.

Copy-Item keeps the source, Move-Item changes its location, Rename-Item changes its name, and Remove-Item deletes the selected item. Build exact targets, preview supported changes with -WhatIf, and inspect the resulting state.

Advanced file management adds recursion, timestamp and attribute selection, folder-copy choices, and batch operations. These are required parts of the topic: choose a starting path and selection rules that fit the task, and verify what the command will act on.

Clean up the lesson demonstration

Remove-Item -LiteralPath $sourceLog, $notesPath -WhatIf

Check the preview paths. Then run the narrowly scoped cleanup:

Remove-Item -LiteralPath $sourceLog, $notesPath

Test-Path -LiteralPath $sourceLog
Test-Path -LiteralPath $notesPath

Both checks return False. The practice folders remain available. Do not remove the hands-on's separate files as part of this lesson's cleanup.
