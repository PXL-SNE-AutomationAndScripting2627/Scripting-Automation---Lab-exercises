Variables, objects, and data types

07 - Variables, objects, and data types

Originele pagina openen →

Learning objectives

By the end of this chapter, you can:

  • store and reuse values with descriptive variable names;
  • inspect types and distinguish a variable from the object it references;
  • convert text before calculations and explain type constraints;
  • manipulate strings, arrays, and hashtables;
  • pass named arguments with hashtable splatting;
  • create custom objects with reusable, typed properties; and
  • recognise automatic variables and explain the effects of scope.

Prerequisites

  • Complete the objects and pipelines lesson.
  • Use PowerShell 7 in Windows Terminal or Visual Studio Code.
  • Understand properties, methods, and basic filtering and selection.

Why variables matter

A support script may inspect a print queue once, calculate its workload, and use the same values in several reports. Variables give those values names so the script can reuse them instead of repeating a query or parsing display text.

Run the examples in order in a fresh PowerShell session. Most change only session variables. The file example uses C:\powershell\Variables-Lesson; your instructor must prepare C:\powershell with writable access first. Keep the theory examples separate from the matching lab's datasets.

Store and reuse a value

A variable is a name that refers to a value. Put $ before the name when assigning or reading it. The assignment operator = stores the value; it does not compare two values.

Assignment and reuse

flowchart LR
    A["Value: 7"] --> B["Assign to waitingJobCount"]
    B --> C["Read the value in a calculation"]
    B --> D["Read the value in a report"]

Assigning a different value later changes what the variable refers to.

$queueName = 'Print-A'
$waitingJobCount = 7

$queueName
$waitingJobCount

$waitingJobCount = 9
$waitingJobCount

The displayed values are Print-A, 7, and 9. Reassignment replaces the value associated with the name.

Use camel case, such as waitingJobCount, and names that describe purpose. Use plural names for collections, such as printJobs. Variable names are case-insensitive, but consistent spelling makes scripts easier to read. Do not reuse automatic names such as $HOME, $PWD, or $PID.

Save command output

Assignment captures the command's success-output objects:

$inspectionTime = Get-Date
$inspectionTime.Year
$inspectionTime.AddMinutes(10)

The first expression reads a property; the second calls a method and returns a new date. Neither changes $inspectionTime. The actual date varies by run.

An object combines data in properties with actions exposed as methods. A variable refers to the object; the variable name is not its data type. Saving output lets later commands reuse the same result. It does not save that result to disk or preserve it after the PowerShell session closes. Use an export command when persistence is needed.

You can also capture cmdlet output with the subexpression operator, $(...). It runs the enclosed statements and returns their output:

$currentProcess = $(Get-Process -Id $PID)
$currentProcess.ProcessName
$currentProcess.GetType().FullName

$PID is the current PowerShell process ID. This query returns one System.Diagnostics.Process object; its process name depends on the session. The variable holds the object, so you can still read its properties. For this simple assignment, $currentProcess = Get-Process -Id $PID works too; $() is optional. Inside double quotes, $() can insert a command's result into text:

"Process ID: $((Get-Process -Id $PID).Id)"

The resulting message is a string containing the current process ID.

$() does not guarantee an array. The number of output objects determines whether the result is absent, one object, or an array. The command-output examples below compare this with @(...).

Apply: Activities 1.1–1.2: assignment and naming.

Inspect and control types

A type describes what a value represents and which operations it supports. PowerShell uses .NET types. These are common examples:

PowerShell notation Short type name Use
[string] String Text
[int] Int32 Whole numbers
[double] Double Binary floating-point values
[decimal] Decimal Decimal arithmetic
[bool] Boolean $true or $false
[datetime] DateTime Dates and times
[object[]] Object[] An array of values
[hashtable] Hashtable Key-value pairs
[pscustomobject] PSCustomObject Named properties for a record

Dynamic typing and type constraints

An unconstrained variable can refer to values of different types:

$queueValue = 9
$queueValue.GetType().Name

$queueValue = 'nine'
$queueValue.GetType().Name

The type names are Int32 and String. This is dynamic typing.

A declaration can instead constrain later assignments:

[int]$copyCount = 2
$copyCount = '4'
$copyCount
$copyCount.GetType().Name

PowerShell converts the supplied text to integer 4. The variable remains constrained to Int32. Assigning text such as 'many' would fail conversion; the earlier value would remain. Test such failures separately from normal examples.

Convert before calculating

A cast converts an expression to another type:

$copiesText = '8'

$copiesText + 2
[int]$copiesText + 2
$copiesText.GetType().Name

The results are string 82, integer 10, and type name String. A cast on an expression does not permanently constrain or modify the source variable. The left operand influences conversion: 2 + '8' performs numeric addition, while '8' + 2 concatenates text.

A type constraint and a business rule serve different purposes. [int] accepts negative integers too; parameter validation can restrict the allowed range.

Null and empty text

$null represents the absence of a value. An empty string is a string with zero characters. Do not call instance methods such as .GetType() on null.

$missingQueue = $null
$emptyQueue = ''

$null -eq $missingQueue
$null -eq $emptyQueue
$emptyQueue.Length

The results are True, False, and 0. Put $null on the left of equality tests to avoid accidentally filtering a collection instead of obtaining the intended Boolean comparison.

Apply: Activities 1.3–2.3: constraints, conversion, and null.

Work with strings as objects

Use single quotes for literal text. Double quotes expand variables. Use $() to evaluate an expression inside an expandable string.

$printerName = 'Print-B'
$queuedPages = 18

'Queue $printerName has $queuedPages pages.'
"Queue $printerName has $queuedPages pages."
"After one more page: $($queuedPages + 1)."

The first line retains the variable names. The others display Print-B, 18, and calculated value 19.

A backtick followed by n inserts a newline inside double quotes; a backtick followed by t inserts a tab:

"Queue:`t$printerName"
"Queue:`n$printerName"

The first message separates label and value with a tab. The second places the value on a new line.

Properties, methods, and new strings

$queueLabel = '  Print Queue  '
$trimmedLabel = $queueLabel.Trim()

$trimmedLabel.Length
$trimmedLabel.ToUpper()
$trimmedLabel.ToLower()
$trimmedLabel.StartsWith('Print')
$trimmedLabel.EndsWith('Queue')
$trimmedLabel.Substring(0, 5)
$trimmedLabel.Replace(' ', '-')
$queueLabel

The length is 11. The transformed values include PRINT QUEUE, print queue, Print, and Print-Queue. Both tests return True.

Length is a property; members followed by parentheses are method calls. Strings are immutable: these methods return new values. The original $queueLabel still has its surrounding spaces.

Index, split, and join

$queueCode = 'PR-42'
$queueCode[0]
$queueCode[-1]

$queueParts = $queueCode.Split('-')
$queueParts.Count
$queueParts -join '/'

Indexes start at 0. Index -1 selects the last character. The results are P, 2, 2 parts, and PR/42.

Apply: Activities 3.1–3.3: string operations.

Work with arrays

An array stores values in an indexed order. @(...) collects output into an array, including when the pipeline returns zero or one object.

$printQueues = @('Print-A', 'Print-B', 'Print-C')

$printQueues.GetType().Name
$printQueues.Count
$printQueues[0]
$printQueues[-1]
$printQueues[1..2]

The type is Object[] and the count is 3. Index 0 selects Print-A; -1 selects Print-C. The slice 1..2 selects Print-B and Print-C. The comma form $printQueues = 'Print-A', 'Print-B', 'Print-C' also creates an array.

Inside @(...), commas are optional when each element is on its own line:

$printQueues = @(
    'Print-A'
    'Print-B'
    'Print-C'
)

This creates the same three-element array. Each line outputs one value, which @(...) collects. Use commas between these values when writing them together on one line, as in the earlier example.

For arrays, Count and Length both report the number of elements. They are properties: write .Count rather than .Count(). For a string, Length counts characters, while Count normally reports one scalar value.

Capture zero, one, or many results

A query may find different numbers of matches on different computers. Use @(...) when later code needs an array in every case.

Output objects Direct assignment or $(...) @(...)
Zero No result; compares equal to $null Empty array, count 0
One The single object Array with one element, count 1
Two or more Array of the output objects Array of the output objects

Compare the two operators with a filter that cannot match: process IDs are never negative.

$noProcess = $(Get-Process | Where-Object { $_.Id -lt 0 })
$noProcesses = @(Get-Process | Where-Object { $_.Id -lt 0 })

$null -eq $noProcess
$null -eq $noProcesses
$noProcesses.Count
$noProcesses.GetType().Name

The results are True, False, 0, and Object[]. The first query has no result. The second produces an actual array containing zero elements, just like @(). An empty array is therefore different from $null. Do not call .GetType() on the missing result; there is no object on which to call the method. Check an array's .Count to determine whether it has elements; a null comparison does not test whether an array is empty.

For one match, $(Get-Process -Id $PID) returns a process object, whereas @(Get-Process -Id $PID) returns an array containing that process object. Use $() to evaluate statements and @() to keep a collection even when the query returns zero or one object.

Replace elements and extend the collection

$printQueues[1] = 'Print-D'
$printQueues += 'Print-E'

$printQueues
$printQueues.Count
$printQueues.IsFixedSize

The array contains Print-A, Print-D, Print-C, and Print-E. Its count is 4 and IsFixedSize is True.

An array's size is fixed, but its elements can be replaced. It is therefore not correct to describe the entire array as immutable. += creates a larger array and assigns it back to the variable. It does not grow the existing array in place.

Filter and process values

$pageCounts = @(6, 14, 9, 22)

$largeJobs = @($pageCounts | Where-Object { $_ -ge 10 })
$largeJobs
$pageCounts | Measure-Object -Average -Minimum -Maximum

$largeJobs contains 14 and 22. The average is 12.75, minimum 6, and maximum 22. $_ is the current object entering the pipeline stage.

To remove selected entries from an array, filter and assign the new result:

$printQueues = @($printQueues | Where-Object { $_ -ne 'Print-C' })
$printQueues

The remaining names are Print-A, Print-D, and Print-E. Use @(...) when later code relies on an array even if the number of matches changes.

Apply: Activities 4.1–4.4: arrays and cmdlet results.

Work with hashtables

A hashtable associates keys with values. Use keys when named lookup is more meaningful than a numeric position.

$queueSettings = @{
    Name    = 'Print-A'
    Copies  = 2
    Duplex  = $true
}

$queueSettings['Name']
$queueSettings.Copies

$queueSettings['Location'] = 'Library'
$queueSettings['Copies'] = 3
$queueSettings.ContainsKey('Location')
$queueSettings.Remove('Location')
$queueSettings.ContainsKey('Location')

The first values are Print-A and 2. The key checks return True and then False. .Remove('Location') removes the key-value pair. Remove-Item is not a method for removing a hashtable entry.

Use @{} for an empty hashtable. Separate pairs with newlines or semicolons; quote keys that contain spaces. .Keys and .Values expose the entries' keys and values. A normal hashtable does not promise a display order. Use [ordered]@{...} when insertion order matters; that creates an ordered dictionary rather than a normal hashtable.

Splat named arguments

Splatting supplies a collection of arguments to a command. Hashtable splatting uses each key as a parameter name and each value as its argument.

In PowerShell, $PID is an automatic variable containing the Process ID (PID) of the current PowerShell process.

$inspectionParameters = @{
    Id = $PID
}
$displayParameters = @{
    Property = 'ProcessName', 'Id'
}

Get-Process @inspectionParameters | Select-Object @displayParameters

The output describes the current PowerShell process. Its name and ID depend on the session. @inspectionParameters supplies -Id $PID; the other hashtable supplies -Property 'ProcessName', 'Id'. Read a hashtable with $, but splat it with @. Command arguments and declaring your own inputs are different steps; the parameters chapter develops the latter.

Apply: Activities 5.1–5.3: keyed data and splatting.

Create custom objects for report rows

A custom object groups related values as named properties. Use [pscustomobject]@{...} to describe one record, rather than storing a report row as an already formatted string.

$printJob = [pscustomobject]@{
    Queue = 'Print-A'
    Pages = 14
    Held  = $false
}

$printJob.GetType().Name
$printJob | Get-Member
$printJob | Select-Object Queue, Pages

.GetType().Name reports PSCustomObject. Get-Member displays the full type name System.Management.Automation.PSCustomObject and lists the properties. Pages remains numeric and Held remains Boolean.

Use an array of custom objects for several rows:

$printJobs = @(
    [pscustomobject]@{ Queue = 'Print-A'; Pages = 14; Held = $false }
    [pscustomobject]@{ Queue = 'Print-B'; Pages = 8;  Held = $true }
    [pscustomobject]@{ Queue = 'Print-C'; Pages = 22; Held = $false }
)

$printJobs |
    Where-Object Held -eq $false |
    Sort-Object Pages -Descending |
    Select-Object Queue, Pages

The output contains Print-C (22 pages) then Print-A (14 pages). Keep the objects until the final formatting stage so later commands can still filter, measure, or export their properties.

Apply: Activities 6.1–6.2: custom objects and Part 7: build a typed course summary. The lab uses a different scenario so you must choose and combine the techniques yourself.

Inspect automatic and environment variables

PowerShell maintains automatic variables for session and execution state. Environment variables belong to the process environment and use $env:Name.

Variable Meaning
$PSVersionTable PowerShell version and edition information
$PWD Current working location
$HOME User's home directory
$PSHOME PowerShell installation directory
$PROFILE Profile script path information
$PID Current PowerShell process ID
$_ or $PSItem Current pipeline object; the error record inside catch
$args Arguments not bound to declared parameters in a simple script or function
$Error Recent error records; index 0 is the newest
$? Success status of the last operation
$LASTEXITCODE Exit code from the last native program, or a script that sets it
$PSCulture Culture used for conventions such as date and number formatting
$PSUICulture Culture used for user-interface resources 
$PSVersionTable.PSVersion
$PWD.Path
$env:USERNAME

The values depend on the session and computer. You can list environment entries with Get-ChildItem Env:, but inspect only the entries needed for a task; environment entries can contain sensitive application settings. Do not overwrite automatic variables or use a user profile as a lab workspace.

Advanced: input and explicit conversion

These sections extend the same concepts. Work through them after the foundational examples; advanced identifies depth.

Interactive input and files

Read-Host returns text unless another mode is requested. Run this example interactively, enter 6 at the prompt, and inspect the conversion:

$enteredCopies = Read-Host -Prompt 'How many copies?'
$enteredCopies.GetType().Name
$numericCopies = [int]$enteredCopies
$numericCopies + 1

The type is String and the calculated result is 7. Non-numeric text fails conversion. Validation and error handling are developed in later chapters.

For a secret, use Read-Host -AsSecureString or Get-Credential as required by the command consuming it. Do not print or convert the secret to plaintext.

A file provides another source of text. For this example, first create the small input in its own lesson workspace. The if guard runs the write only when Test-Path reports that the file is missing; -not reverses the test. The conditionals chapter develops these decisions further:

$variablesLessonRoot = Join-Path -Path 'C:\powershell' -ChildPath 'Variables-Lesson'
New-Item -Path $variablesLessonRoot -ItemType Directory -Force | Out-Null
$queueNamePath = Join-Path -Path $variablesLessonRoot -ChildPath 'queue-name.txt'

if (-not (Test-Path -LiteralPath $queueNamePath)) {
    Set-Content -LiteralPath $queueNamePath -Value 'Print-A'
}
$queueFromFile = Get-Content -LiteralPath $queueNamePath -Raw
$queueFromFile.Trim()

A new file produces Print-A after trimming the final line ending. An existing file is preserved; its value can differ. -Raw reads one string; without it, Get-Content returns one string per line. Keep the file for review; no deletion is required.

Alternative conversions

$convertedCopies = [Convert]::ToInt32('6')
$convertibleText = '6' -as [int]
$unconvertibleText = 'six' -as [int]

$convertedCopies
$convertibleText
$null -eq $unconvertibleText

The results are 6, 6, and True. In this example, -as returns null rather than throwing when conversion fails. Check for null rather than using a truth test: a successfully converted 0 is also false in a condition. .ToString() converts a value to text; formatting and culture can affect that representation.

Advanced: collection growth and iteration

A foreach loop runs its body once for each item. It names the current item explicitly. ForEach-Object instead receives the current item through $_ in a pipeline.

$queueNames = @('Print-X', 'Print-Y')

foreach ($queue in $queueNames) {
    "Queue: $queue"
}

$queueNames | ForEach-Object { $_.ToLower() }

The loop produces Queue: Print-X and Queue: Print-Y. The pipeline produces print-x and print-y. An array also provides a .ForEach({...}) method, which applies a script block to its elements:

$queueNames.ForEach({ $_.ToUpper() })

This returns PRINT-X and PRINT-Y. The loops lesson explains how the language loop and pipeline cmdlet differ in more detail.

Grow a list in place

Repeated array += operations copy values into new arrays. When a script adds many values, use a collection designed to grow:

$queueList = [System.Collections.Generic.List[string]]::new()
$queueList.Add('Print-X')
$queueList.Add('Print-Y')
$queueList.Remove('Print-X')
$queueList

Remove() returns True and the list contains Print-Y. The generic List[string] accepts string elements.

You may also encounter the older, mixed-type ArrayList:

$legacyQueues = [System.Collections.ArrayList]@('Print-X')
[void]$legacyQueues.Add('Print-Y')
$legacyQueues.Remove('Print-X')
$legacyQueues

It contains Print-Y. ArrayList.Add() returns the new element's index; [void] suppresses that return value. This avoids accidentally mixing indexes into the intended pipeline output.

Advanced: scope and shared objects

Scope controls where a variable name can be read or assigned. A function normally has a child scope. It can read values from its parent; assigning the same variable name locally does not replace the parent's value.

$queueStatus = 'Outside'

function Get-QueueStatusExample {
    $queueStatus = 'Inside'
    $queueStatus
}

Get-QueueStatusExample
$queueStatus

The results are Inside and Outside. A script also normally runs in its own script scope. Local means the current scope, Script identifies the script's scope, and Global identifies the session's outer scope. Private: restricts visibility to the defining scope; it is an option, not a separate scope introduced by PowerShell 7.

Dot-sourcing runs a script in the caller's scope. Prefer passing inputs and returning results instead of changing global variables. See the scope reference and practise function scope in Functions Activity 4.1.

Inspect and clear your own variables

$temporaryQueueNote = 'Check paper tray'
Get-Variable -Name temporaryQueueNote
Clear-Variable -Name temporaryQueueNote
$null -eq $temporaryQueueNote
Remove-Variable -Name temporaryQueueNote

Clear-Variable sets this variable to null; the comparison returns True. Remove-Variable removes the named variable. Use exact names; do not clear or remove every variable in a session.

Native program exit status

Capture success status immediately after the operation it describes. Later commands can change $?. In PowerShell on Windows, the following native program deliberately returns exit code 5 without changing files:

& $env:ComSpec /c 'exit 5'
$nativeSucceeded = $?
$nativeExitCode = $LASTEXITCODE
$nativeSucceeded
$nativeExitCode

The results are False and 5. $? is a Boolean status; $LASTEXITCODE is the numeric code from the native program. Use the latter's documented meaning when handling external tools.

A class defines a reusable type

A class describes a type's properties and methods. Use PSCustomObject for straightforward report rows; a class is useful when a named type needs a defined structure.

class PrintQueueRecord {
    [string]$Name
    [int]$WaitingJobs
}

$queueRecord = [PrintQueueRecord]::new()
$queueRecord.Name = 'Print-Z'
$queueRecord.WaitingJobs = 3
$queueRecord

The record has name Print-Z and 3 waiting jobs. Run a class definition once in a fresh session when experimenting with changes to the type.

For the advanced sections, explain why a failed -as conversion differs from integer zero, why growing a list differs from array +=, and why two variables can observe the same hashtable change. Revisit scope in Functions Activity 4.1.

Show solution

A failed -as [int] conversion returns $null; converting '0' succeeds and returns integer 0. Test $null -eq $result rather than truthiness when distinguishing them, because both null and zero evaluate to false.

A generic list's Add() method grows the existing list. Array += creates a new array containing the old elements and the added item, then assigns it back to the variable. Repeated array growth can require repeated copying.

Assigning a hashtable to another variable copies its object reference. Both variables can therefore observe mutations to that one hashtable. Reassigning one variable to a new hashtable changes that variable's reference; it does not reassign the other variable.

Summary

Variables name values and object references. Inspect types before choosing an operation, convert external text deliberately, and distinguish casts from variable constraints. Strings return new values when transformed; array sizes are fixed but their elements can change. Hashtables support named lookup, while custom objects expose report properties that pipeline commands can reuse.

Keep typed objects until display or export. Session variables are temporary; saving a value in a variable does not save it to a file.
