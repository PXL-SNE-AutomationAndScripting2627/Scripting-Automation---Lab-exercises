PowerShell remoting and CIM sessions

05 - Remote access

Originele pagina openen →

Remote administration lets one authorized operator run commands consistently across one or more computers. PowerShell remoting uses the PowerShell Remoting Protocol, while CIM sessions provide a reusable connection for CIM operations.

Learning objectives

By the end of this lesson, you can:

  • explain the requirements and security boundaries of PowerShell remoting;
  • distinguish one-to-one, one-to-many, temporary, and persistent remoting;
  • create, use, inspect, and remove PSSession objects;
  • create and clean up reusable CIM sessions; and
  • collect structured information from multiple authorized computers.

Prerequisites

  • Complete the PowerShell Basics course and the Windows information lesson.
  • Use instructor-provided Windows lab computers with approved credentials and network access.
  • Confirm the target names and authorization before connecting.
  • Enable or disable remoting only when the lab instructions explicitly assign that configuration task.

Understand the remoting boundary

When a command runs remotely, two computers and two PowerShell environments are involved. Local and remote execution policies, permissions, modules, paths, and variables may differ.

Remote command boundary

flowchart LR
    A["Local session: Invoke-Command"] --> B["Authorized remote session"]
    B --> C["Remote command runs on target"]
    C --> D["Serialized results returned locally"]

The returned objects may retain useful properties without all their original methods. A CIM session is a separate way to query management information.

On Windows, Enable-PSRemoting configures the computer to receive WS-Management-based PowerShell commands. It changes services, listeners, session configurations, and firewall rules, so it requires administrator rights and must not be run on unapproved systems.

Get-Service -Name WinRM
Get-PSSessionConfiguration
Test-WSMan -ComputerName 'Server01'

In a domain, Kerberos with computer names is the preferred default. Do not weaken authentication or broadly edit TrustedHosts merely to bypass a configuration problem.

Run one command on one or many computers

Invoke-Command -ComputerName creates temporary connections for the command.

Invoke-Command -ComputerName 'Server01' -ScriptBlock {
    [pscustomobject]@{
        ComputerName = $env:COMPUTERNAME
        PowerShell    = $PSVersionTable.PSVersion.ToString()
        Date          = Get-Date
    }
}

Invoke-Command -ComputerName 'Server01', 'Server02' -ScriptBlock {
    Get-Service -Name WinRM |
        Select-Object MachineName, Name, Status, StartType
}

Returned objects are serialized copies. Their properties remain useful, but most original methods are unavailable on the calling computer.

Use a persistent PSSession

A PSSession keeps a connection and remote session state available for several commands.

$session = New-PSSession -ComputerName 'Server01'

Get-PSSession

Invoke-Command -Session $session -ScriptBlock {
    $serviceSnapshot = Get-Service |
        Where-Object Status -eq 'Running'
}

Invoke-Command -Session $session -ScriptBlock {
    $serviceSnapshot.Count
}

Remove-PSSession -Session $session

Use Enter-PSSession for an interactive one-to-one troubleshooting session. Use Invoke-Command for repeatable automation and fan-out to several computers.

Understand local and remote variables

The script block executes remotely. Use the using: scope modifier to pass a local value into it.

$serviceName = 'WinRM'

Invoke-Command -ComputerName 'Server01' -ScriptBlock {
    Get-Service -Name $using:serviceName
}

Pass only the values required by the remote command. Do not send secrets as ordinary strings.

Create reusable CIM sessions

A CIM session stores connection settings and can be reused across CIM-aware cmdlets.

$cimSession = New-CimSession -ComputerName 'Server01'

Get-CimInstance -ClassName Win32_OperatingSystem -CimSession $cimSession |
    Select-Object PSComputerName, Caption, Version, LastBootUpTime

Get-CimSession
Remove-CimSession -CimSession $cimSession

CIM sessions connect when a cmdlet uses them and close the operation afterward. A PSSession maintains remote PowerShell state until removed.

Collect from a server list

$servers = Get-Content -Path '.\servers.txt' |
    Where-Object { $_.Trim() -and -not $_.StartsWith('#') }

$results = foreach ($server in $servers) {
    try {
        $os = Get-CimInstance -ClassName Win32_OperatingSystem `
            -ComputerName $server -ErrorAction Stop

        [pscustomobject]@{
            ComputerName = $server
            Reachable    = $true
            Caption      = $os.Caption
            LastBoot     = $os.LastBootUpTime
            Error        = $null
        }
    } catch {
        [pscustomobject]@{
            ComputerName = $server
            Reachable    = $false
            Caption      = $null
            LastBoot     = $null
            Error        = $_.Exception.Message
        }
    }
}

$results

A useful fleet script returns a result for every requested computer, including failures. This makes missing or unreachable systems visible instead of silently dropping them.

Practice and self-check

  1. What does Enable-PSRemoting change on a Windows computer?
Show solution

It configures the computer to receive WS-Management-based PowerShell remote commands, including changes to services, listeners, session configurations, and firewall rules. Run it only when explicitly authorized.

  1. When should you use Invoke-Command -ComputerName instead of a persistent session?
Show solution

Use -ComputerName for a one-off command when you do not need to preserve remote session state. Use a persistent PSSession when several commands must share state or reuse the same session.

  1. Why are remote result objects described as serialized copies?
Show solution

PowerShell sends a serialized representation across the connection and reconstructs it locally. Properties are generally available, but most methods of the original live object are not.

  1. What does $using: do in a remote script block?
Show solution

It makes the value of a local variable available to the remote script block, for example $using:serviceName. It does not make the local variable itself editable from the remote session.

  1. How does a CIM session differ from a PSSession?
Show solution

A CIM session holds connection settings for CIM operations. A PSSession maintains a remote PowerShell session and its state across commands. Remove either session when it is no longer needed.

  1. Why should a multi-computer report include failed connections?
Show solution

It makes missing results visible and identifies which computers need follow-up. Include a useful error for each failed target rather than silently omitting it.

Summary

PowerShell remoting supports temporary commands, persistent sessions, interactive troubleshooting, and multi-computer automation. Use approved hosts and secure authentication, understand local-versus-remote state, return structured results, and remove sessions when finished.
