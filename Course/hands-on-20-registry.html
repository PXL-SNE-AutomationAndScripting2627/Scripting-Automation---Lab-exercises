Hands-on — Registry

20 - Registry

Originele pagina openen →

Goal

Create, inspect, update, rename, and remove values only inside a dedicated current-user registry key.

Learning objectives

By the end of this lab, you can:

  • navigate Registry provider drives;
  • distinguish keys from values;
  • preview and verify registry operations;
  • enumerate non-provider properties; and
  • build reversible registry preference automation.

Prerequisites

  • Complete 19 — Networking.
  • Complete Automating the Windows registry before starting this lab.
  • Use PowerShell on Windows.
  • Use only HKCU:\Software\PowerShellCourse\RegistryLab for modifications.

How to work in this lab

Inspect the exact path before each modification, run -WhatIf first, and verify afterward. Never replace the lab path with an operating-system or policy key.

Part 1 — Inspect the provider

Activity 1.1 — Discover drives and commands

Get-PSProvider -PSProvider Registry

Part 5 — Challenge: build reversible preference automation

Filename: Set-CourseRegistryPreference.ps1

Create Set-CourseRegistryPreference.ps1. It must:

  • use [CmdletBinding(SupportsShouldProcess)];
  • accept Action with Status, Apply, or Cleanup;
  • use only the exact lab key;
  • create or update CourseMode as String and RunCount as DWord during Apply;
  • accept validated Mode values Practice or Assessment;
  • accept RunCount from 0 through 100;
  • return a structured object describing the current state;
  • support -WhatIf for Apply and Cleanup; and
  • treat a missing key as a valid clean state during cleanup.

Test:

.\Set-CourseRegistryPreference.ps1 -Action Apply -Mode Assessment -RunCount 2

Detailed solution: Use Set-CourseRegistryPreference.ps1. It hard-codes and rechecks the safe path, uses ShouldProcess for mutations, and always returns the same state shape.

.\Set-CourseRegistryPreference.ps1 -Action Status
.\Set-CourseRegistryPreference.ps1 -Action Apply -Mode Assessment -RunCount 2 -WhatIf
.\Set-CourseRegistryPreference.ps1 -Action Apply -Mode Assessment -RunCount 2
.\Set-CourseRegistryPreference.ps1 -Action Cleanup -WhatIf

Question: Which safeguards prevent broader deletion?

Detailed answer: The path is a constant under HKCU, compared with the exact approved string, contains no wildcard, is previewed, and is checked for absence after removal.

Show solution Optimized

The linked script is the step-by-step version. This alternative uses a single state query after the action. It changes only the specified lab key.

[CmdletBinding(SupportsShouldProcess)]
param(
    [Parameter(Mandatory)]
    [ValidateSet('Status', 'Apply', 'Cleanup')]
    [string]$Action,
    [ValidateSet('Practice', 'Assessment')]
    [string]$Mode = 'Practice',
    [ValidateRange(0, 100)]
    [int]$RunCount = 0
)

if (-not $IsWindows) { throw 'This script requires Windows.' }
$labKey = 'HKCU:\Software\PowerShellCourse\RegistryLab'

if ($Action -eq 'Apply' -and
    $PSCmdlet.ShouldProcess($labKey, "Apply CourseMode=$Mode and RunCount=$RunCount")) {
    if (-not (Test-Path -LiteralPath $labKey)) {
        New-Item -Path $labKey -Force -ErrorAction Stop | Out-Null
    }
    New-ItemProperty -Path $labKey -Name 'CourseMode' -PropertyType String `
        -Value $Mode -Force -ErrorAction Stop | Out-Null
    New-ItemProperty -Path $labKey -Name 'RunCount' -PropertyType DWord `
        -Value $RunCount -Force -ErrorAction Stop | Out-Null
} elseif ($Action -eq 'Cleanup' -and (Test-Path -LiteralPath $labKey) -and
    $PSCmdlet.ShouldProcess($labKey, 'Remove the dedicated registry lab key')) {
    Remove-Item -LiteralPath $labKey -Recurse -ErrorAction Stop
}

$exists = Test-Path -LiteralPath $labKey
$values = if ($exists) { Get-ItemProperty -LiteralPath $labKey -ErrorAction Stop }
[pscustomobject]@{
    Path       = $labKey
    Exists     = $exists
    CourseMode = if ($values) { $values.CourseMode } else { $null }
    RunCount   = if ($values) { $values.RunCount } else { $null }
}

Status reflects the actual current state; -WhatIf does not apply the proposed changes.
